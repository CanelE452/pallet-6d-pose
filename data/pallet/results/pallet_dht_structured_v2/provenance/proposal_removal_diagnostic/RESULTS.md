# DHT 교점 후보 제거 진단 — 완료

기존 `point_segment` seed 1의 저장된 후보 점수와 margin 0.5를 그대로 사용했다. 새 학습·모델 forward·GT 기반 선택·임계값 변경은 0회다. 기존 결과와 동결된 코드는 바꾸지 않았다.

**실사에서 관측한 단일 프레임의 개선은 DHT 교점 후보를 제거해도 유지됐다.** 제거 후에는 C4 번호배치 후보가 선택됐다. 이 결과를 DHT 교점 보정의 성능 기여로 해석할 근거는 없다.

캘리브레이션 256장·합성 검증 512장은 각각 고정된 4개 상태, 실사 DEV 319장은 원래 상태를 확인했다. 총 3,391개 프레임–상태에서 남긴 10개 후보의 실제 모델 입력 FP32 좌표가 원래 후보의 정확한 부분집합임을 검증했다. 원래 순서, semantic ID 평가, centroid, 분모를 보존했다.

단위는 원본 픽셀. 합성은 관측 가능한 감독 8코너(캘리브레이션 2,022점, 검증 4,021점), 실사는 centroid 포함 공식 감독 9점 중 관측·매칭된 2,738점이다. 합성 가림 라벨은 amodal 감독이며 실제 보이는 물리 경계의 인증이 아니다.

실사 median/P90는 baseline 6.896978/41.487329 → 전체 후보와 교점 제거 모두 6.882053/39.813888 px. 두 방법 모두 005838 한 프레임의 8코너만 개선하고, baseline 오차≤10px인 1,711점 중 새로 10px를 넘긴 점은 0개다. 합성 국소 변형에서는 교점 후보가 평균오차를 약 0.0396px 더 줄였지만, 원래 양호한 점 1개를 10px 밖으로 이동시켰다. 모든 상태의 결과는 위 표와 JSON에 보존했다.

`plastic_day_01:005838`에서는 기존 후보 45(quarter-3 C4 + corner 5 half-snap)에서 후보 3(C4-only)으로 바뀌었다. 후보 3의 저장 점수 gap 0.798528이 이미 margin 0.5보다 커서 GT를 보지 않고 선택됐다. 사후 공식 GT 기준 9점 평균오차는 원래 118.580959, C4-only 5.011946, 선 snap 포함 5.167237px다. ID 배치 변경의 이득은 113.569013px이며 추가 snap은 평균오차를 0.155291px 높였다. 코너 5 오차도 4.988218→6.385833px였다. 이는 공식 라벨에 대한 수치이며 실제 물리 경계의 소수점 픽셀 정확도를 인증하지 않는다.

이 진단은 같은 학습된 scorer의 후보 의존성을 확인한다. 후보 수 감소가 함께 일어나고, 기반 모델/P4는 기존 DHT 공동학습 특징을 그대로 유지한다. 따라서 모든 DHT 정보의 제거 실험이나 같은 조건으로 재학습한 대조군은 아니다. 이전에 확인한 DEV 319장과 학습 seed 1개에서 나온 결과로 일반적 개선을 주장하지 않는다.

초기 진단은 `[B,8,49]`의 corner 축을 교점 슬롯 축으로 잘못 인덱싱하여 exact subset 검사에서 중단됐다. 어떤 선택·지표 결과도 저장하기 전에 실패했다. `[:, :, 1:]`로 수정했고 허용 오차는 추가하지 않았다. 원래 코드·실패·소스 동결 기록은 [repairs/axis_index_001](repairs/axis_index_001/)에 보존했다. 프로토콜/알고리즘/학습 소스는 그대로다.
