## 왜 닫혔는가 — 네 게이트가 같은 벽을 가리킨다

```
Gate A   상보성은 실재한다.  그러나 파라미터 없는 융합(좌표 median · medoid)은
         p90 을 43.9 -> 70~73 으로 악화시킨다.  좋은 후보가 나쁜 후보에 묻힌다.
Gate A   교사 불일치는 "어디가 틀렸는지" 를 잘 안다 (gross20 예측 AUC 0.79,
         R0 자신의 confidence 0.658 보다 위).  그러나 "무엇이 맞는지" 는 모른다.
Gate D   그래서 불일치로 거른 usable 부분집합은 **R0 가 이미 맞히는 자리**가 된다
         (R0 median 6.97 -> 5.80, p90 60.31 -> 20.14).  거기서 융합은 R0 를 못 이긴다.
Gate B   국소 RGB 도 대안을 주지 못한다.  oracle 후보의 이득은 밀도의 산물이고,
         학습된 전문가조차 R0 의 gross 코너 498개 중 1개만 구제했다 (0.002).
Gate E   도메인 축은 오차와 연결돼 있지 않다.  지울 대상이 아니다.
```

pseudo-label 은 좌표를 요구한다. 이 트랙이 만들어낸 것은 **신뢰도**뿐이다.
신뢰도만으로는 라벨을 만들 수 없다.

```

   꼬리를 못 건드려 게이트는 못 넘었지만, fine localisation 자체는 학습으로 좋아진다.

   "이 프레임의 이 코너는 믿지 마라" 에는 쓸 수 있다.
```

## 사후 조정하지 않은 것

```
- Gate B 가 밀도 통제에서 무너졌지만 사전등록 STRONG 판정을 뒤집지 않았다.
- 합의 임계 tau 를 real 통과율이 1.5% 로 나온 뒤에도 올리지 않았다.
- Gate D 의 세 검사(median · p90 · gross20)를 하나만 통과하면 되도록 완화하지 않았다.
- Gate E 에서 domain AUROC 만 보고 adapter 를 돌리지 않았다.
- 학생 arm 을 "그래도 한 번 돌려보자" 로 실행하지 않았다.
```

## 다음이 있다면 무엇을 봐야 하는가 (제안일 뿐, 실행하지 않았다)

이 트랙이 닫은 것은 "여러 교사의 합의로 pseudo-coordinate 를 만드는" 경로다.
남은 관측 두 개가 다른 방향을 가리킨다.

```
- 교사 불일치 AUC 0.79 는 라벨 생성이 아니라 **평가/거부(rejection)** 축에 쓸 수 있다.
- 미라벨 풀의 불일치 중앙값이 DEV_EVAL 의 7배다.  self-training 의 병목이
  방법이 아니라 **adaptation pool 의 구성**일 수 있다.
```

둘 다 이 트랙의 잠긴 범위 밖이므로 여기서 실행하지 않았다.
