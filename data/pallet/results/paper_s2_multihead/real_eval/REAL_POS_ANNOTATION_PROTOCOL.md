# REAL POSITIVE ANNOTATION PROTOCOL

목표: 실제 촬영 프레임에서 **믿을 수 있는 R_gt, t_gt** 를 만든다.
합성처럼 완벽한 GT 는 없으므로, 불확실성을 숨기지 말고 **측정해서 같이 낸다.**

## 1. convention (합성과 동일해야 한다)

```
keypoint   camera_dynamic_0123_v4
           0~3 = 앞면,  {0,1,4,5} = 위,  {2,3,6,7} = 아래,  8 = centroid
camera     OpenCV pinhole
3D model   objects[0].dimensions_m 와 같은 축 정의. 팔레트 실측 치수를 쓴다
```

★ 합성에서 쓰던 관례를 그대로 옮긴다. 여기서 축을 새로 정의하면 학습된 모델과
평가가 서로 다른 것을 재게 된다.

## 2. 클릭 규칙

```
보이는 코너는 가능한 만큼 전부 클릭한다.  최소 4개.
안 보이는 코너를 "대충 여기쯤" 으로 찍지 않는다.  <- 절대 금지
```

**invisible corner 를 억지로 어노테이션하면 GT 가 아니라 사람의 추측이 된다.**
그 추측으로 만든 pose 를 모델 평가 기준으로 쓰면, 모델이 아니라 어노테이터를
평가하게 된다. 안 보이면 `visible=false` 로 남기고 PnP 에서 제외한다.

가림(occlusion)과 화면밖(truncation)을 구분해 기록한다 — 원인이 다르고,
나중에 실패 분석에서 갈라 봐야 한다.

## 3. pose 복원

```
visible 2D  <->  known 3D  대응
    |
    +-- 4점이고 거의 한 평면이면  IPPE (평면 PnP)
    +-- 그 외                      EPnP + RANSAC
    |
refinement (Levenberg-Marquardt, reprojection 최소화)
    |
R_gt, t_gt
```

평면 PnP 는 해가 두 개다. 두 해 중 **팔레트가 카메라 앞에 있고 위/아래 축이
장면의 중력 방향과 맞는 쪽**을 고른다. 자동으로 고르지 말고 overlay 로 확인한다.

## 4. 검수 — 8코너 재투영 overlay

pose 를 얻은 뒤 **8개 코너 전부**를 다시 투영해 이미지에 그린다.
클릭한 4~7개만 맞는 게 아니라, **클릭하지 않은 코너까지 물체 위에 앉는지**를
사람이 눈으로 승인한다.

```
승인    8코너가 팔레트 구조 위에 앉는다
반려    안 보이는 코너가 허공/바닥에 떠 있다  -> 재작업 또는 프레임 폐기
```

이게 이 프로토콜의 핵심 게이트다. 클릭 4점만 맞추는 pose 는 depth 가 무너져도
reprojection error 가 낮게 나온다 (합성에서 이미 관측된 실패 모드).

## 5. 이중 어노테이션 — 불확실성을 측정한다

전체의 **10~20%** 를 서로 다른 두 사람이 독립으로 어노테이션한다.
(같은 사람이 두 번 하면 기억이 남아 일치도가 부풀려진다.)

측정하고 보고할 것:

```
2D click disagreement    코너별 픽셀 거리의 median / p90
R disagreement           두 pose 사이 회전 각도 (deg)
t disagreement           두 pose 사이 거리 (m)
```

**이 수치가 GT 의 바닥 노이즈다.** 모델 오차가 여기에 근접하면 "모델이 나쁘다"
가 아니라 "이 평가셋으로는 더 못 가른다" 가 맞는 결론이다. 보고서에 항상 같이 적는다.

## 6. 프레임 폐기 기준 (사전 고정)

```
visible corner < 4                      -> 폐기 (pose 복원 불가)
overlay 검수 반려                        -> 폐기
두 어노테이터의 R 차이 > 10도            -> 3인 검토 후 결정, 못 좁히면 폐기
팔레트가 화면의 2% 미만                  -> 폐기 (클릭 정밀도 한계)
```

폐기한 프레임 수와 사유를 세어서 남긴다. 조용히 빼지 않는다.
