## 1. 재계산으로 확인한 지적 (전부 사실)

### 1.1 S_seed3 을 H2/H3 와 묶은 것은 틀렸다 [확인]

원보고서 §5 표는 `H2, H3, HA2, HA3, S3` 를 한 줄로 묶고 전부 `f7377` 5.340px 로 적었다.
실제로는 **S_seed1·S_seed3 은 후보 1**(순수 번호 재배열)을 골라 **5.024358px**,
H2/H3/HA2/HA3 는 **후보 28**(재배열 + 코너 국소 snap)을 골라 **5.339696px** 다.
서로 다른 후보이므로 묶으면 안 된다.

### 1.2 "실제 점 이동분 3~5px" 는 양을 혼동한 것이다 [확인]

원보고서는 최적 재대응 후 잔여 정답오차(5.024 / 3.186px)를 **좌표 이동량**처럼 썼다.
둘은 다른 양이다. 선택 후보를 같은 사분면의 순수 순열 후보와 좌표로 직접 비교하면
실제 이동은 다음 한 코너뿐이다.

| 프레임 | 선택 후보 | 가장 가까운 순수 순열 | 실제 이동 |
|---|---|---|---|
| `f7377` | 28 | quarter 1 | 코너 4 만 **9.104px** |
| `f5154` | 40 | quarter 3 | 코너 0 만 **1.716px** |

즉 f7377 에서 H 는 순수 재배열(5.024px)보다 **0.315px 더 나쁜** 배치를 골랐다.
이 한 장의 개선을 "선 교점 위치 보정의 성공"으로 읽을 수 없다.

### 1.3 "점수가 나은 후보를 싫어했다" 는 부정확하다 [확인]

랭킹(raw argmin)과 수락 규칙(calibration margin)을 섞어 썼다. 저장된 점수를 다시 세면
**대부분의 프레임에서 비identity 후보를 선호한다**.

| 군 | raw argmin 이 비identity 인 프레임 | 실제 채택 |
|---|---:|---:|
| P_seed1 | 498 / 512 | 0 (identity-only 정책) |
| P_seed2 | 501 / 512 | 0 |
| P_seed3 | 499 / 512 | 0 |
| H_seed1 | 494 / 512 | 3 |

변경이 1~5장뿐인 것은 **calibration 이 고른 margin 이 억제했기 때문**이지
"점수 함수가 나은 후보를 싫어해서"가 아니다. 다만 raw argmin 이 비identity 라는 사실만으로
그 대안이 실제로 더 낫다는 뜻도 아니다.

### 1.4 "C4 위상 동전던지기" 는 철회한다 — 실제로는 계통적 편향이다 [확인]

검토서 §5.2 를 저장 좌표에서 독립 재계산했고 **모든 값이 재현**됐다.
관측 509 프레임 중 순수 C4 후보가 엄격히 더 나은 프레임은 **8장**이고,
H 세 seed 는 그중 **f7377 1장에서만** 정답 사분면을 선호했다.

| 합성 프레임 | 원래 mean8 px | 최선 순열 mean8 px | 사분면 | H1/H2/H3 raw 로 정답 선호 |
|---|---:|---:|---:|---|
| `f32733` | 60.397 | 1.635 | 3 | 아니오 |
| `f3423` | 111.535 | 28.405 | 3 | 아니오 |
| `f39518` | 53.400 | 2.658 | 3 | 아니오 |
| `f39546` | 154.405 | 42.151 | 1 | 아니오 |
| `f7377` | 133.606 | 5.024 | 1 | **예** |
| `f20333` | 88.370 | 4.820 | 3 | 아니오 |
| `f22017` | 116.699 | 5.096 | 3 | 아니오 |
| `f23543` | 148.227 | 2.877 | 3 | 아니오 |

첫 4후보 raw argmin 이 GT 최선과 불일치한 프레임은 H1=8 / H2=9 / H3=8 (509 중).
4지선다 균등무작위라면 8장 중 약 2장을 맞혀야 하는데 **1장**이다. 즉 무작위가 아니라
**원래 번호 배치(identity) 쪽으로 계통적으로 치우친 실패**다.
"영상으로 위상을 식별할 수 없다"는 주장은 GT 좌표 오차만으로는 검사되지 않았으므로
**[미검증 가설]** 로 낮춘다. `f3423`·`f39546` 은 최선 순열 뒤에도 28.4/42.2px 가 남아
모든 사례가 순수 번호 오류인 것도 아니다.

또한 "항상 identity" 만 해도 509 중 501 이 맞으므로, 전체 정답률을 모델의 강점으로
제시하면 안 된다(불균형).

### 1.5 그 밖에 낮추거나 철회한 문장 [확인/판정]

- **train oracle 42.19% 를 validation headroom 처럼 쓴 것** — 42.19%·159프레임은
  train 1,792(관측 1,791)의 진단이다. validation 512 의 전체 64후보 oracle 은 계산하지 않았다.
  "병목은 랭킹" 이라는 단정을 이 수치로 뒷받침할 수 없다.
- **calibration 0.005327 → val 0.005789 이므로 표본 부족** — 서로 다른 모집단의 절대값을
  직접 빼면 안 된다. 각자의 baseline 대비 손익으로 비교해야 하며, 이 결과만으로
  calibration 표본 부족을 단정할 수 없다. → 관찰만 남기고 원인 단정은 철회.
- **"공통 affine 이라 군간 차이를 만들 수 없다"** — 공통 변환이라도 끝점 전용과 내부
  sampler 의 query 위치가 달라 상호작용할 수 있다. 단정 철회(이번 실패의 원인이라는
  주장도 하지 않는다).
- **`H − HA` 효과 없음** → "현재 설정에서 안정적 이점이 확인되지 않았다"로 표현을 낮춘다.
  부재의 증명이 아니다.
- **camera_dynamic_0123_v4 는 카메라 기준 앞/뒤·상/하 번호 규약**이며 정사각 물체의
  절대 yaw 대칭과 같은 문제가 아니다. 모든 합성 물체가 물리적으로 C4 대칭이라는 계약은
  이번 기록에서 확인되지 않았다.

## 2. 무결성 주장의 범위를 좁힌 항목 [판정]

`SOURCE_CHECKS_KO.md` 의 지적을 받아들여 다음을 명시한다. **수치가 틀렸다는 뜻이 아니라
보증 범위를 좁히는 것**이다.

| 원래 표현 | 좁힌 표현 |
|---|---|
| 정책 12개 동결 후 val 개봉 | 실제 실행은 군마다 cal→policy→val 순차. val 기반 재튜닝 증거는 없으나 지시문 §9.1 의 "12개 전부 동결 후 개봉" 순서와는 다르다 |
| P4 parity 2,560/2,560 bit-exact | P4 텐서의 재현 확인이지 predictor **전체 반환값**의 동일성 검사는 아니다 |
| G1 좌표 검사 PASS | affine 역행렬 왕복·선식의 **내부 산술 정합성** 확인이다. 실제 영상-feature 물리 정렬의 독립 인증이 아니다 |
| G2 데이터 분리 PASS | frame ID 비중복은 직접 검사. **이미지 바이트 비중복은 상류 boolean 을 읽은 것**이고 PASS 조건에도 안 들어간다 |
| scoring 중 supervision 파일 open 0 | `ExportDataset.observation` 8회 로딩 경로만 계측했다. score_cache 전체 추론을 계측한 것이 아니며, 코어의 `supervision_files_opened=0` 은 **계측값이 아니라 선언 상수**다 |
| `missing_required_artifacts=[]` | `cli/audit.py` 의 REQUIRED 목록에 `CANDIDATE_CONTRACT.json` 이 빠져 있어 **지시문 전체 준수의 증명이 아니다** |
| `unrelated_working_tree_changes=[]` | `_docs/`·`challenge/` 를 범위에서 제외하고 센 값이다. 무관 변경이 전혀 없었다는 보증이 아니다 |

## 3. 범위 이탈 1건 [확인]

원 지시문 §12 는 외부 알림을 범위 밖으로 두는데, 실행 중 Discord 알림을 2회 보냈다
(HTTP 204). 이는 **사용자가 CLI 세션에서 "디코로 알려줘"라고 명시 요청**해 그쪽을 따른
것이며, 그 승인은 ZIP 안에 없다. 실험 프로토콜(학습·평가·판정)에는 외부 호출이
들어가지 않았고 성능 숫자와도 무관하다. 알림 영수증은 검토 ZIP 에서 제외했다.

## 4. 검토서에서 그대로 받아들이지 않은 것

- 검토서도 "무결성 완전 통과"를 부정할 뿐 12개 결과 숫자가 틀렸다고 하지 않는다.
  나 역시 `INDEPENDENT_REPLAY.json` 431 검사 전부 통과와 원본 픽셀 지표 최대차 0.0 을
  확인했다.
- 가중치·특징 텐서가 검토 ZIP 에 없으므로 검토자도 **신경망 재실행으로 검증하지 않았다**.
  이는 내 기록의 결함이 아니라 제출 범위의 한계이고, 양쪽 문서에 그대로 남긴다.

## 5. 수정된 최종 결론

> 동일 고정 backbone 과 후보 bank 에서 네 증거 읽기 구조를 비교했다. 제한된 학습과
> 합성 평가는 전부 완료됐고 주요 수치는 저장 좌표에서 재현된다. 일부 번호 재배정으로
> 개선된 사례가 있었지만 한두 정상 프레임의 큰 손상이 seed 별 손익을 뒤집어 사전
> 합성 진입 기준을 만족하지 못했다. 선분·Hough 증거 또는 같은-ID reference 제거의
> 안정적 이점은 확인되지 않았다. 실패는 무작위 위상 선택이 아니라 **원래 번호 배치
> 쪽으로 치우친 계통적 랭킹 오류**이며, 순수 재배열만으로 고칠 수 있었던 8장 중
> 7장을 놓쳤다. 이 결과는 현재 선택기의 한계를 말할 뿐 영상 기반 번호 식별
> 불가능성이나 점·선 결합 일반의 실패를 증명하지 않는다. 실행 순서·무결성 검사의
> 보증 범위 제한은 §2 에 그대로 보존한다.
