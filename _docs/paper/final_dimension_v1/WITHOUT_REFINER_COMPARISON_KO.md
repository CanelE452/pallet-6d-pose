# 치수 유지 + 보정 제거 비교 (2026-09-20)

결론: 기존 DEV319에서는 성능이 낮아진다. 초록150에서는 지표별로 엇갈린다.
작은 이동이라는 이유만으로 보정 효과가 없다고 볼 수는 없다.

여기서 '치수만 입력'은 R0의 원래 2D 코너 + 등록 치수 + 기존 PnP이다.
현재 N2는 치수를 입력받아 코너를 보정하는 하나의 모듈이므로, 제거하면 신경망의
치수 조건화도 함께 사라진다. 치수는 3D 자세 계산에 계속 사용한다.
별도 치수 입력 신경망을 새로 학습한 실험은 아니다.

| 지표 | 치수 + N2 보정 | 치수만, 보정 제거 | 제거 시 변화 |
|---|---:|---:|---:|
| 2D 코너 중앙오차 ↓ | 5.698 px | 6.721 px | +1.022 px |
| PCK10 ↑ | 68.95% | 63.43% | -5.52%p |
| 3D 위치 중앙오차 ↓ | 6.896 cm | 7.897 cm | +1.000 cm |
| 위치 P90 오차 ↓ | 38.233 cm | 40.530 cm | +2.298 cm |
| 회전 중앙오차 ↓ | 2.127° | 2.539° | +0.411° |
| 3D IoU 중앙값 ↑ | 0.6353 | 0.5943 | -0.0410 |
| ADDsym AUC ↑ | 0.4109 | 0.3766 | -0.0343 |

동일한 치수, 예측 기반 W/D 선택, SQPnP/LM을 사용해 R0와 N2 seed1/2/3의
6D 결과를 CPU에서 재계산했다. 모든 모델은 319/319 자세 산출 가능했다.
N2의 위치/회전/yaw/IoU3D 중앙값과 P90은 기존 결과와 수치 일치를 확인했다.
seed2/3도 R0보다 위치/회전 중앙오차, IoU3D 중앙값, ADDsym AUC가 좋았다.
2D 수치는 기존 동일 corner8 평가 결과를 사용했다.

## 속도와 해석 범위

기존 동일 RTX3080 측정에서 PnP 포함 중앙 처리시간은 보정 포함15.130ms,
제거11.638ms로 약3.49ms(23.1%) 줄어든다. 이번에 속도를 재측정하지 않았다.

DEV319는 재사용된 개발 데이터이며 6D 정답은 기하로 재구성한 값이다.
독립 물리 계측 정확도를 입증하지 않는다. 초록은 저장 라벨과 카메라 불일치
한계 때문에 2D만 비교하며 DEV와 합산하지 않는다. 이번 6D 비교는 기술통계다.
배포 모델, 기존 결과, 학습 상태는 변경하지 않았다.
