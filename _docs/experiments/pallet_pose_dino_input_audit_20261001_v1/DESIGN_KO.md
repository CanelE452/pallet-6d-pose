# 고정 자세 후보 위치의 RGB 특징 입력 감사

목표는 T와 R의 안정적인 동시 개선이다. 직전 비대칭 Huber 실험은 source 조건 43/45로 실패했고 실사는 실행하지 않았다. 해로운 선택 감소와 함께 유익한 선택도 감소했으며, 변경된 UNION 선택은 모두 기존 anchor로 돌아갔다. 추가 loss 계수 조정 대신 후보의 이미지 근거를 확인한다.

이번 단계는 **입력 구축과 검산**이다. 새로운 선택기 학습, 후보 선택, T/R 평가를 하지 않는다. 입력 감사 통과를 성능 개선이나 전체 목표 달성으로 표시하지 않는다. 최초 첨부 계획의 0회 학습 진단 단계와 이후 사용자의 안정적 개선 목표를 구분하며, 이번 단계 자체도 학습 0회다.

## 고정하는 입력

- 기존 단일 RGB, 팔레트 치수, 카메라 K와 고정된 R0/PoseFix 자세 후보를 사용한다.
- 기존 C2 학습 대상 2,598행과 원래 후보 유효성을 유지한다. 모든 후보가 무효인 1행도 남기고 이미지 추론을 생략한다.
- 현재 R0의 선택된 예측 박스로 정한 하나의 wide crop을 모든 후보가 공유한다. 기존 crop의 scale을 유지하고 중심 이동 `[144,192]`를 적용하여 높이 768, 폭 576으로 만든다. 준비된 source RGB를 다시 padding하지 않는다.
- 이미 보유한 공식 DINOv2 ViT-S/14 코드·가중치를 해시로 검증한다. 가중치는 고정하며 새 다운로드는 없다. 기존 wide 전처리와 동일하게 784×588로 resize하고, 마지막 patch token을 FP16 `[384,56,42]`로 저장한다. 추론은 FP32, TF32는 끈다.
- 각 고정 pose의 8개 꼭짓점을 기존 cf 좌표계와 K로 투영한다. center와 관측 q9를 새 영상 특징에 추가하지 않는다.
- 준비 이미지와 crop 내부에 있으며 깊이가 양수인 꼭짓점만 영상 샘플의 지원 대상으로 삼는다. 이는 가시성·가림 판정이 아니다. 후보 유효성을 변경하지 않는다.
- half-pixel 변환 `(crop_xy+0.5)*grid_size/crop_size-0.5`와 bilinear border sampling을 사용한다. crop 밖 점을 가장자리 특징으로 대신하지 않는다.
- 지원된 꼭짓점의 384채널 평균과 지원 비율 1개를 합쳐 385차원을 만든다. 0개 지원은 모두 0이다. 채널별 합산 순서를 고정해 꼭짓점 순열 때문에 합산 오차가 달라지지 않게 한다.
- R0의 원래 유효 TRAIN 후보 5,194개로 FP32 mean/std를 구하며 std floor는 1e-6이다. 후속 선택기는 기존 271차원에 정규화 후 candidate−anchor 차분 385차원을 붙이는 단일 비교가 후보이며, 아직 학습하지 않았다.

## 재사용 판단과 검증 범위

기존 source diversity DINO 캐시의 8,505행은 source 8,256행과 real 249행을 합친 수다. 같은 ID와 기록된 이미지 해시가 맞아도 현재 R0 crop affine가 정확히 같아야 같은 특징 캐시로 사용할 수 있다. 작은 affine 차이를 허용 오차로 지워 재사용하지 않는다. 현재 감사에서 정확한 crop 일치가 없어 현재 TRAIN에 대해 새로 추출한다.

모든 FP16 patch token과 최종 descriptor를 보관하고 별도 구현으로 투영·샘플링·지원 마스크·정규화를 검산한다. descriptor 정합은 이미지 근거가 올바른 T/R를 구별한다는 증거가 아니다. 8개 평균은 C2 순열에 불변이지만 모든 꼭짓점 순서를 버리므로 방향·구조 정보도 줄인다. 기존 RGB 후보 선택기의 실패와 제한적 성공을 [선행 방법 검토](PRIOR_METHODS_KO.md)에 함께 기록한다.

VAL/실사 특징은 이 단계에서 추출하지 않는다. 원래 source 45조건과 실사 5조건은 그대로 남으며 이번 입력 감사를 이유로 완화하지 않는다. 실제 후속 학습은 입력 검산 후 별도 고정 계약으로 수행해야 한다.

## 실제 감사 후 결정

전수 수치 검산은 통과했지만, 준비된 영상의 반사 padding을 별도로 세었을 때 R0의 지원 위치 41,282개 중 3,618개가 원본 영상 영역 밖이었다. 다른 세 expert도 각각 3,390/41,512, 3,418/41,505, 3,395/41,513개였다. 이는 오차 정답이나 성능 결과를 조회한 진단이 아니다. [전체 padding 진단](PADDING_SUPPORT_AUDIT.json)에 원래 후보·지원점 분모를 보존했다.

따라서 이번의 prepared-canvas 지원 버전을 그대로 학습하지 않는다. 다음 입력 변경은 기존 전처리의 pad 값으로 원본 영상 영역 `[pad,width-pad)×[pad,height-pad)`만 직접 샘플 위치로 허용하는 하나의 명시적 수정이다. 고정 token을 다시 모아 descriptor와 TRAIN 정규화만 별도 산출물로 만들고 검산할 수 있으므로 새로운 backbone forward는 필요 없다. 원래 pose 유효성은 유지한다. 이미 저장한 이번 protocol·token·descriptor는 바꾸지 않는다.

이 수정도 padding의 영향을 모두 없애지는 않는다. DINO의 문맥 특징은 원본 영역에 샘플링해도 주변 padding의 영향을 받을 수 있다. 입력 수정이나 검산을 T/R 성능 개선으로 주장하지 않으며, 이후 별도 고정 학습·source·실사 검증은 계속 필요하다.
