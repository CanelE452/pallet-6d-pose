# Reproduction and resume

`all` / `resume` also run `audit` and scoped main-only `publish`. Their completion does not manufacture missing confirmation or author approval. PDF compilation creates a pending visual-review state: render every current PDF page, inspect it, and record its exact hashes in `PDF_VISUAL_REVIEW.json` before the execution audit may declare all available work complete. A new PDF invalidates an old visual receipt. Remote-advance or unrelated staged changes are reported rather than automatically stashed or overwritten.

After actually inspecting every rendered page (never just after compiler success), use `record_visual_review.py --manuscript-sha <the inspected PDF SHA256> --supplementary-sha <the inspected PDF SHA256>`, then `run.py audit` and `run.py publish`. This receipt distinguishes assistant layout inspection from the outstanding human author review. An unchanged, hash-matching manuscript is reused on resume; changed results or sources trigger regeneration and a new review.

GPU stages need actual host CUDA access. The sandbox's lack of device access is not a reason to replace a working driver or silently train on CPU. Do not run an additional `all` while a prior train process is active. Foreign compute is checked and never killed; display/RustDesk activity is retained.

Individual stages: `bind`, `implementation`, `train`, `evaluate`, `confirmation`, `manuscript`. Main fits are only PRIOR1/2/3, each6000 updates, nominal batch16 and the exact P order. Last checkpoint only. Each checkpoint binds code/protocol/init/order, optimizer, Python/NumPy/CPU/CUDA RNG and durable step; completion receipts also bind checkpoint bytes. Source RGB workers do not perform random augmentation. Prefetched rows are deterministic and resume from the saved cursor.

`evaluate` resumes through `evaluate_pipeline.py`. A hash-verified `DEV_COMPLETE` goes directly to runtime without repeating training, inference or bootstrap analysis. Incomplete DEV uses `evaluate_compatible.py`: the original immutable selection omitted the canonical scorer's literal `selection_population` field, so the compatibility entry point adds it in a separate metadata view with exact-equal prediction frames. See `SCORER_METADATA_CORRECTION.md`. Original selection, predictions, model code and weights are not rewritten. CPU scoring of stored predictions may proceed during another task's GPU use; the runtime guard still requires the other compute to finish. Later failures are archived under ignored `raw/stage_failures` before the latest status is updated.
