# V11: 모순 선 제외와 약한 관측의 명시적 반환 계약

사용자의 요청은 자기 가림 판정을 완벽히 맞히는 것이 아니라, 다른 유효 대응으로 자세를 구하고 승인된 새 자세가 있으면 자기 가림 코너의 초기 좌표를 재투영으로 교체하는 것이다. 원 첨부 문서의 C2 선 관측 절제는 같은 IMAGE_ROLE 관측에만 적용한다. 이 계약은 최신 sparse boundary-only C2의 관측 모순과 수치적 약함을 처리하는 한 번의 방법 수정이다. 새 학습·합성 RGB·수동 어노테이션·성능을 보고 고른 threshold/seed를 추가하지 않는다. V4/V6 hybrid 또는 native-versus-query 코너 선택을 다시 실험하지 않는다.

두 방법 이름은 `FILTERED_LOCAL`, `FILTERED_LOCAL_WEAK_SAFE`이고 기본 배포 출력은 후자다. 같은 프레임에서 **하나의 새 filtered LOCAL solver**를 실행하고 두 출력 view를 만든다. 앞 view는 V9의 기존 rank-only 승인 조건을 유지하는 관측 필터 대조이며, 뒤 view는 그 동일 선택 후보를 기존 weak-condition 규칙으로 추가 판정한다. 뒤 view에서 다른 후보를 골라 다시 최적화하지 않는다. 이 두 출력은 독립적으로 두 번 자세를 푼 결과가 아니다.

`pipeline.solve_repair_packet(local_packet, audit_row, observer=None)`은 기존 V9 `validate_local_packet()`의 네 필드 packet과 동일 ID의 완료 V10 audit 원행을 받아 `(rows2, ledger)`를 반환한다. 전체 파일 SHA·245개 ID·V7 1960 geometry/735 observations/490 fixed·V9 245 geometry·V10 245 audit·seal·독립 PASS·cleanup·보호 snapshot의 증명은 driver가 먼저 수행한다. packet 함수도 원 parent/ROLE/native semantic SHA, K/xyz/raw size/H/sparse q/실제 채택 코너/actual unused factor pool와 audit line witness를 다시 대조한다. score/GT/사람 마스크를 이 함수에 넣지 않는다. V10 원행을 수정하거나 관측 필터 결과로 덮어쓰지 않는다.

원 V10의 `CONTRADICTED_REJECT`가 된 **실제 사용되지 않은 선**만 최종 LOCAL 관측에서 제외한다. `SUPPORTED_RETAIN`과 `UNVERIFIED_RETAIN`은 유지한다. UNKNOWN은 유효 선의 증명도 no-match의 증명도 아니며 프레임 전체 실패 조건이 아니다. 판정은 기존 V6/V10 그대로 원 native N3 좌표의 prior-free 유한 4점 강건 PnP에 `H ∪ {선의 양 끝 코너}`를 제외한 다음, 해당 선의 양 끝 모델 재투영과 실제 관측 선 사이 RMS를 기존 8px로 비교한 것이다. 그 선 자체·초기 R,t·초기 치수 선택·검증 재투영을 검증 자세의 관측 또는 prior로 넣지 않는다. 이 검증 자세도 틀린 합의일 수 있으므로 실제 물리 경계 ownership을 인증했다고 말하지 않는다.

필터 전 선은 V5의 실제 geometry registry/CAL/query/support/일관된 중복/코너 소비 규칙으로 확인한다. 실제 선택 q와 그 선을 소비한 코너/queries는 바꾸지 않는다. 제외 ID의 모든 중복 raw line record를 제거하고, 코너가 소비한 support line은 그대로 보존한다. 필터 뒤 V9 kernel이 원 sparse q에서 같은 U를 만들고, 선 pool이 원 actual unused pool에서 모순 ID만 뺀 집합인지 확인한다. 선 0개가 남아도 기존 C2 point-local objective가 충분하면 실행하며 선의 효과와 구분한다. scalar 관측 수 부족·수치 실패·rank 부족·다중 동점·기본 출력 반환은 기존 V9 상태를 유지한다. 관측이 없을 때 native q로 채우지 않는다.

LOCAL 수학은 frozen V9 `LocalPointLineBank.solve()`를 변경 없이 호출한다. 초기 N3와 사용 가능한 같은 sparse point-only 자세는 시작값만 제공하고 잔차 prior를 제공하지 않는다. 각 시작에서 양 등록 치수를 모두 시도하며, 같은 초기 벡터만 정확히 cache한다. 고정 `soft_l1`, `f_scale=8`, `max_nfev=50`, 점 두 성분/선 양 끝 signed normal 잔차의 `1/sqrt(2)` 가중, 같은 whole factor pool soft cost 선택, 양의 깊이, 두 최종 J의 rank6, 기존 numerical tie/physical equivalence 처리를 유지한다. 초기 J rank는 진단이다. 8px inlier는 진단이며 새로운 점/선 수 threshold를 추가하지 않는다. LOCAL 결과는 초기화에 의존한 수치 자세 산출이며 독립 전역 PnP/PnL 또는 유일해의 증명이 아니다.

weak-safe는 **선택된 후보**의 `point_line_geometry.observed_normal_joint`와 `modeled_normal_joint`의 이미 계산된 singular spectrum을 읽는다. V1 `HypothesisBank._jacobian()`과 V5 `rank_info()`는 모두 열 L2 norm을 `max(norm,1e-300)`로 나눈 J에 SVD를 적용한다. 그대로 `s_min < s_max * 1e-4`를 두 J 각각에 적용하며 하나라도 참이고 rank-only 새 자세가 승인돼 있다면 `WEAK_OBSERVABILITY`로 새 update를 거절한다. 이 규칙은 기존 V1 진단 threshold를 이 LOCAL 경로의 명시적 운영 gate로 사용하는 수정이다. 새 cutoff·SVD·GT 선택·최적화·다른 후보 재선택을 추가하지 않는다. 정규화된 열 사이의 근접 선형 종속을 판정하며 pixel covariance에 근거한 절대 자세 불확실도나 모든 correspondence 오류를 인증하는 규칙은 아니다. 강한 condition이어도 잘못된 대응이면 실제 자세가 나쁠 수 있다.

`WEAK_OBSERVABILITY` 원행은 모든 시작/후보/최종 observed·modeled J/rank/spectrum/condition/soft cost/대안/operation count를 보존한다. rejected proposal의 R,t/fit IDs/projected/hidden replacement는 `solver.rejected_local_pose`에 따로 남긴다. 승인된 solver의 R,t/projected/fit IDs는 비우고 V2 `assemble()`이 원 N3 기본 자세와 원 native display를 반환한다. 이것을 성공한 새로운 자세나 샘플 삭제로 세지 않는다. 초기 자세도 없으면 `POSE_FAILURE`다. 두 view의 `fresh_filtered_solver_semantic_sha256`는 같은 gate 전 solver이며 ledger `full_rank_only_solver`에서 재구성할 수 있다. 새 solve와 보고 view 수는 각각 1과 2다.

승인된 NEW에서만 최종 R,t의 재투영으로 초기 H 좌표를 교체한다. 초기 H 좌표는 fit U에 없고 검증용 endpoint의 일시 제외와 H를 별도 기록한다. 재투영점이나 재투영선을 독립 관측으로 다시 fit하지 않는다. 같은 선에서 만든 점과 그 선을 중복 factor로 세지 않는다. 원 detector center, confidence, box, 선택/비선택 candidate metadata는 기존 보존 계약을 유지한다.

`repair_observations(points, native_points, K, xyz, observation, hidden, adopted_boundary_corner_ids, *, initial_pose, point_result, image_size, endpoint_audit=None, observer=None)`는 파일·모델·이미지·GT를 받지 않는 공통 kernel이다. `endpoint_audit`가 있으면 검증 완료 V10의 같은 source decision을 재사용하고 새 endpoint PnP는 0회다. 없으면 원 native 좌표의 한 PoseBank로 각 actual unused edge의 endpoint LOO를 새로 계산하고 모든 H/endpoint mask에서 같은 가설 bank를 공유한다. 후자의 호출은 source audit replay가 아닌 실제 새 point-only PnP다. 양 경로 모두 LOCAL fit은 한 번이다. observer의 request start/return/exception은 driver가 중단된 prefix 및 실제 호출 accounting을 남기는 용도이며 정책에 관여하지 않는다.

`deployment.Pipeline.predict()`는 같은 kernel을 실제 배포 경로에서 호출한다. 요청마다 한 번의 fresh fixed detector/N3/IMAGE_ROLE capture, fresh sparse point control, fresh native endpoint LOO, fresh filtered LOCAL, weak routing, H 재투영/display 보존을 수행한다. sealed parent packet·saved audit decision·원 평가 좌표를 배포 입력으로 쓰지 않는다. 한 call의 두 view는 한 solver에서 만들어지며 별도 predict 요청은 전체 경로를 새로 계산한다. `last_capture`, `last_point_result`, `last_repair_ledger`, `last_views`, `last_execution_events`와 실제 누적 model/local/native counter를 제공한다. 두 view 계산/복사와 모든 초기 자세·feature Base 자세·PnP/LOCAL·재투영은 실제 전체 경로 timing 구간에 포함해야 한다. 정확도 replay wall time을 배포 latency로 주장하지 않는다.

정확도는 모든 Clean153+Moderate92의245개를 유지한다. severe74는 사용자가 제외하도록 수정한 범위다. Base/N3/기존 point control/원 V9 LOCAL와 두 view를 같은 저장 원행 기준으로 비교하며, NEW·기본 출력·실패의 산출률과 전체 운용 및 공통 산출집합을 함께 기록한다. weak fallback이 큰 오차 사례를 NEW 집합에서 빼는 효과와 실제 전체 운용 개선을 구분한다. 직접 가시 코너와 숨은 재투영 오차는 실제 위치/회전/ADDsym과 구분한다. 의미 있는 개선이 있는지는 실제 후단 평가 후 판정하며 이 문서는 개선을 예측하거나 완료 결과를 주장하지 않는다.

driver는 own freeze/STARTED/quiet preflight, 원본과 게시된 V7/V8/V9/V10 bytes 보호, actual LOCAL/SciPy/residual/J/SVD/6개 OpenCV entry/return/exception, full candidate 원행 및 ledger를 기록하고 모든 monkeypatch·환경·thread/모델 cleanup을 완료한 다음 GT-free seal을 만든다. 독립 scalar checker는 변경 없는 V9 수학 witness와 필터/공유 solver/weak routing/H fit 제외/fallback를 확인하고 PASS 이후에만 scorer가 GT를 읽는다. 성능 결과를 보고 설정을 바꾸거나 실패 artifact를 덮어쓰지 않는다. runtime·공개 검산·정상 branch commit/push는 각각 필요한 별도 권한/계약에 따라 부모 driver가 수행하며 main 자동 변경/merge/force push는 하지 않는다.

이 문서는 실행 전 구현 계약이다. 기존 V1/V4/V5/V6/V7/V8/V9/V10의 완료 실험·실패·수정 기록은 그대로 남긴다. 새 V11 수치 실행/정확도/latency/게시 완료 여부와 실제 호출 수는 추후 receipt가 권위이며, CODE ONLY 구현과 정적 검토를 실행 완료로 세지 않는다.
