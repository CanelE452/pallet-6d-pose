# Known-object conditional evaluation

DEV's `object_type` is supplied by the frozen benchmark manifest. This experiment does **not** establish an independent live inventory/operator feed or train an object-type recognizer. DIM/META results therefore describe an explicitly **known-object conditional scenario**, not demonstrated unconditional deployment performance. If object type/size/group is unavailable at deployment, these arms reject the input; that unknown-type scenario is not scored as headline inference.

Within the conditional scenario, the manifest object type indexes one fixed registry entry. Dimensions do not depend on that frame's GT pose, clicked corners, projected extent, selected W/D hypothesis or evaluation branch. The approved symmetry code has separate contract provenance, never a square-dimension heuristic. Object dimensions are privilege/side information, not free information.

The causal claim remains limited: differences compare fixed heads under a stated metadata-availability assumption. Wrong/shuffled metadata sensitivity is not proof of causal utility or proof of real-world availability. N4 vs N0 is not a same-input comparison; N4 vs N3 isolates the explicit group-code increment with other conditions fixed.
