너는 현재 로컬 pallet-6d-pose에서 작업하는 CLI 에이전트다.
사용자는 완료된 N3 실험을 바탕으로, 리프터를 제외한 나머지 논문 빈칸을 마감하도록 요청했다.
계획만 작성하고 끝내지 말고, 아래 범위에서 재집계 코드 수정·실행·검산·논문 표 내보내기를 수행하라.

이 지시는 과거 실행 지시의 리프터 작업 및 추가 학습 허용보다 우선한다.

## 0. 최상위 목적과 판정 원칙

목적:
같은 N3 보정 절차를 YOLO·DOPE·ResNet-18에 각각 적용한 효과와 한계를,
원고의 동일한 입력·평가 규약에 맞춘 실제 숫자로 연결한다.
교수와 독자가 판단할 것은 각 기반 안의 보정 효과, 치수·대칭의 추가 가치,
정사각형·재질·가림 조건의 적용 범위다.

목적은 x 개수 최소화나 모든 결과의 개선이 아니다.
데이터·평가 계약이 성립하지 않는 칸은 x로 남기거나 별도 비교표로 분리한다.
불리한 결과, 측정된 0, 성립하지 않는 통계도 그대로 보고한다.

각 작업을 시작하기 전에 목적 / 재사용 가능한 것 / 최소 추가 행동 / 결과별 판단을 짧게 기록하라.
의사결정과 관계없는 재학습, 새 방법, 무의미한 표 채우기는 하지 않는다.

## 3. 원고 빈칸을 작업 종류로 분리

먼저 원고 표/행/열 단위의 상태표를 작성하라. 상태 이름은 이번 마감용 새 표기다.
- READY_TO_INSERT: 현재 계약의 원시 결과와 검증이 있으며 원고에 넣을 수 있음.
- NEED_RESCORE: 자료는 있으나 누락 계산/재집계가 필요함.
- NEED_INFER: 검증된 기존 가중치는 있으나 필요한 고정 추론이 빠짐.
- NEED_REVIEW: 기존 근거만으로 레이블·참조 의미를 확정하지 못함.
- BLOCKED_CONTRACT: 모집단·노출·참조 조건이 맞지 않아 해당 표로 합칠 수 없음.
- NOT_APPLICABLE: 해당 모집단에서 그 값이 정의되지 않음. 이유 필수.
- OUT_OF_SCOPE_USER: 리프터 등 이번 제외 범위.

실험 값과 상태를 분리하라.
아직 계산하지 않은 값과 막힌 값은 x, 정의 불가 값은 NA/해당 없음, 실제 관측 0은 숫자 0이다.
자료 부족을 0으로 쓰거나, 실제 악화값을 x로 감추지 않는다.
전체 논문 완료율을 셀 개수로 임의 산출하지 말고, 질문별 근거 확보 여부를 보고한다.

## 4. 우선 실행 A — N0/N1 6D 계산 누락 보완

[확인한 코드 위치]
reuse.py의 DCP_ARMS에는 N0_BASE_REPLAY와 N1_SYM_ONLY가 포함돼 있다.
그러나 CORE_ARMS는 OLD_P, N2_DIM_ONLY, N3_DIM_SYM만 포함한다.
build_core()의 need_pose = include_pose and arm in CORE_ARMS 때문에
N0/N1은 원시 좌표를 읽고도 자세 계산이 생략된다.
로컬에서 이미 수정됐는지 먼저 확인하고, 수정·완료됐다면 재사용한다.

수행:
1) N0/N1 각각 seed 1/2/3의 완료된 원시 좌표와 동일 DEV319 참조를 실제로 확인한다.
2) 새 출력 영역에서 N0/N1에도 기존의 동일 pose 평가 함수를 호출한다.
   단순히 CORE_ARMS 전역 상수를 바꿔 관련 없는 선택/집단 로직까지 바꾸지 마라.
3) 치수·카메라·3D 코너·대칭·가설 선택 알고리즘·PnP·실패 처리는 기존 N2/N3와 같게 유지한다.
   정답으로 가장 좋은 pose 후보를 선택하지 않는다.
   보정 후 선택 가설이 달라지는 것은 허용되지만 선택 알고리즘은 바꾸지 않는다.
4) seed별 이동·회전·방향각 중앙값/P90, IoU3D, ADDsym AUC, 자세 산출 수/비율을 계산한다.
   ADDsym은 기존 정의를 유지하고 BOP의 다른 지표나 ADD-S로 바꾸지 않는다.
5) N2−N0, N1−N0, N3−N2, N3−N1의 차이를 2D와 6D에서 나란히 제시한다.
   과거 OLD_P를 통제 재현 N0로 바꿔 부르지 않는다.
6) R0/OLD_P/N2/N3의 기존 2D·6D 결과는 같은 원시 자료로 회귀검산한다.
   원시 좌표 요약의 숫자 불일치를 반올림으로 숨기지 말고 원인을 찾는다.
   기존 수치에 맞추기 위해 정답·모집단·평가기 또는 허용오차를 사후 변경하지 않는다.

이 작업은 학습이 아니라 CPU 중심 재집계/PnP 계산이다.
최대 대상은 N0/N1 ×3seed ×319 frame = 1,914개 기존 frame-method 행이며
유효하지 않은 행도 실패로 남긴다. 해결되지 않는 입력 결손은 해당 행/모드를 명시한다.

## 5. 우선 실행 B — ResNet 유효 명세 정정

실제 평가된 ResNet은 10-epoch synthetic CONSTANT checkpoint를
고정 0 조건에서 이미지 전용 함수로 접은 모델이다.
CONSTANT를 '모든 이미지에서 같은 좌표를 출력하는 모델'로 오해하거나
'60-epoch RGB SimpleBaseline 학습을 마쳤다'로 바꿔 쓰지 마라.

1) 실제 사용 checkpoint, hash, 기본 학습 receipt, model 정의, decoder,
   folding 전후 동등성 시험과 N3 학습이 참조한 가중치를 대조한다.
2) 기존 PROTOCOL.json의 실제 epoch10 checkpoint/decoder와,
   nested input의 epoch60·argmax·옛 loss 설명 사이의 충돌을 항목별로 기록한다.
3) 기존 잠금 PROTOCOL.json과 training receipt를 덮어쓰지 않는다.
   새 EFFECTIVE_PROTOCOL_CORRECTIONS.json(신규 파일 이름)과 정정 설명을 작성하고,
   각 항목에 원래 값 / 실제 증거 / 유효한 값 / 원본 해시를 연결한다.
4) 기존 folding parity 기록이 충분하면 재사용한다.
   부족하면 같은 고정 입력에서 가중치 변경 없는 동등성 시험만 추가한다.
5) 데이터 노출과 checkpoint 선택 이력을 확인한다.
   실사 성능을 보고 선택한 경우 숨기지 말고 개발 선택 이력으로 기록한다.
   확인하지 못하면 '선택 이력 미확인'이지 '비노출 확인'이 아니다.
6) 원고 표의 모델 이름·학습량·디코더·입력 설명을 실제 실행과 일치시킨다.

명세 정정 때문에 N3를 다시 학습하지 마라.
실제 모델/예측이 기록과 다르거나 folding 불일치가 확인되면 그 결과만 보류하고 보고한다.

## 6. 우선 실행 C — 6D 짝지은 분석·불확실성·실패 보존

목적은 중앙값 개선이 같은 평가 대상에서 유지되는지와 큰 오류의 변화를 확인하는 것이다.
이미 2D에 사용한 session-paired bootstrap을 6D에 확장하되,
결과가 나온 뒤 추가한 기술적 분석이라는 이력을 남긴다.
독립 TEST나 사전등록 확증 분석이라고 부르지 않는다.

1) 모든 방법에서 frame ID, session ID, 참조 출처와 유효 pose ID를 대조한다.
   같은 개수의 성공 프레임이라고 같은 프레임이라고 간주하지 않는다.
2) base/N3 모두 성공 / base만 성공 / N3만 성공 / 둘 다 실패의 전이 수를 저장한다.
   결측 처리와 전체 분모 ADDsym AUC·자세 산출률을 유지한다.
3) 기존 headline은 각 방법의 원래 성공 집단에서 계산한 정의 그대로 보존한다.
   성공 집단이 다르면 공통 성공 집단의 짝지은 결과를 별도 보조표로 추가한다.
   이 보조표로 원래 전체 실패를 지우지 않는다.
4) 변화의 부호는 '보정 후−보정 전'으로 통일한다.
   median(after)−median(before)와 median(after−before)는 다른 통계다.
   논문 주표의 변화는 전자이며, 프레임 변화의 후자를 제시하면 별도 이름을 붙인다.
5) 기존 잠금: bootstrap 단위 session, 10,000회, 난수 seed 20260917.
   기존 2D 코드의 구간 방식·집계 가중치를 읽고 계승한다.
   두 방법과 세 seed에 동일한 session 재표집을 적용하고,

## 11. 기존 학습·입력·수치의 무결성 재검산

완료 결과를 원고에 넣기 전에 다음을 확인하라.
- 학습 완료/추론 완료/평가 완료/원고 반영 완료를 별도 상태로 관리한다.
- 같은 N3 이름에 다른 weights/temperature/cap/기본 모델이 섞이지 않는다.
- 기존 N3는 이미지 특징+치수, 학습 대칭 감독을 포함한다. P/D로 대체하지 않는다.
- 보정 전후 box/score/선택 객체/중심점/valid mask가 일치한다.
- 변위 역변환은 축별 크기 비율을 사용하며 원본 기준1% cap을 검사한다.
- 예측 파일의 정답 필드는 추론에 쓰지 않는다. 평가용 참조 읽기와 분리한다.
- 학습을 새로 하지 않는 이번 실행에서 optimizer update 횟수는0이다.
- 표의 코너0–7와 기존9점 결과, 영상/코너 단위, fraction/%를 혼합하지 않는다.
- PCK 변화는 퍼센트포인트와 상대율을 구분한다. cm/m, degree/radian을 확인한다.
- seed 평균은 seed별 통계 평균이다. 예측 앙상블이나 프레임 수3배가 아니다.
- 정답 없는 값은 x이고, 실제 0과 정의 불가 NA는 다르다.

모든 기존 숫자를 무조건 정답으로 취급하지도 말고, 새로운 숫자로 조용히 덮어쓰지도 마라.
자료/평가기 수정이 필요하면 옛 값·새 값·이유·영향받는 표·해시를 함께 기록한다.
새 결과가 나쁘다는 것은 기술 실패가 아니므로 원인 미확정 상태로 그대로 보고한다.

## 12. 결과 파일과 원고에 반영할 범위

다음은 새 산출물의 제안 이름이며 기존 저장소 키/파일이 존재한다고 가정하지 마라.

- TASK_STATUS.md: 비리프터 작업별 완료/보류/판단/최소 남은 입력.
- SOURCE_BINDINGS.json: 사용한 코드·checkpoint·raw·주석·원고 해시와 실제 위치.
- EFFECTIVE_PROTOCOL_CORRECTIONS.json: 원본을 보존한 ResNet 등 유효 명세 정정.
- POSE_ABLATION_RESULTS.json / CSV: N0/N1 포함 seed별6D와 비교값.
- PAIRED_POSE_RESULTS.json / CSV: paired 성공집단, 전이, CI, seed spread.
- ANNOTATION_RECONCILIATION.md 및 검수 목록: 가림 분류 변화와 미확정 항목.
- PAPER_CELL_MAP.json: 논문 table/row/metric/mode/seed/단위/분모/원시 산출물 연결.
- REMAINING_X_NON_LIFTER.md: 실제 남은 x/NA와 사유. 리프터는 별도 제외 항목.
- VERIFY_NON_LIFTER.json: 실행한 검증과 통과/실패/실행안함 구분.
- FINAL_REPORT_NON_LIFTER_KO.md: 변화·불확실성·남는 주장·막힌 항목.
- tables/ 및 figures/: 원고에 넣을 LaTeX/CSV와 실제 데이터 그래프.
- README_RUN.md: 실제로 구현·실행·검증한 비리프터 명령, 재시작 조건, 사용 환경.

원고 소스가 있으면:
1) 원본 복사본에서 작업하고 사용자 수정 이력을 보존한다.
2) 기존 표의 x 중 같은 모집단·모드·평가 정의로 검증된 값만 교체한다.
3) ResNet 명칭, 표본 분모, seed 집계, 감독 활성, 자기학습128장 비교의 설명을 함께 바꾼다.
4) 정사각형6D·미검수 가시성·리프터 표는 임의로 채우지 않는다.
5) PDF는 생성하지 않는다. Overleaf에서 교체할 소스 파일과 패치 목록을 제공한다.
6) 원고 파일이 없으면 표 조각·셀 대응·문장 수정 목록까지만 만들고 반영 완료라고 하지 않는다.

결과 그림은 원자료 기반으로만 생성하고 문구는 영어로 한다.
실제 전후 코너와 PnP로 재투영한 코너를 구분한다.
큰 오차 범위를 잘라 숨기지 않고 개선·무차이·악화 사례를 함께 제시한다.
가림/가시성 미검수 이미지는 검수 자료일 뿐 확정된 결과 그림으로 쓰지 않는다.

## 13. 중단 조건과 최종 보고

무결성 문제: 잘못된 hash/모델/좌표계/정답 누출/모집단 불일치/파괴적 덮어쓰기는
그 경로의 실행과 표 반영을 중단한다. 독립적인 다른 작업은 계속한다.
주석/참조/새 권한이 필요한 문제는 해당 항목만 NEED_REVIEW 또는 BLOCKED로 남긴다.
이미지 접근이 없는데 봤다고 하지 말고, 도구가 지원하지 않는 작업을 완료로 기록하지 않는다.

최종 보고 순서:
1) 이번에 실제 계산·검산·원고 반영까지 끝난 항목.
2) 전후 수치와 기존 주장에 미치는 영향. 대칭 무차이와 큰 오류 악화도 포함.
3) 원고에 넣을 수 있지만 아직 삽입하지 않은 항목.
4) 재계산이 남은 항목, 사람 검수가 필요한 항목, 계약상 채울 수 없는 항목.
5) 신규 학습0회, 고정 추론/계측 횟수, 실제 CPU/GPU 시간, 오류·중단·재시작 기록.
6) 실제 생성된 파일·검증된 실행 명령·diff 목록.

완료 표기는 '비리프터 범위의 실행 완료/부분 완료'와 '논문 주장 충족 여부'를 나눠라.
리프터 제외를 실패로 세지 않고, 가시성/6D 참조가 남았는데 모든 논문 x가 해결됐다고 하지 않는다.

## 14. 참고 근거와 사용 범위

주 근거는 실제 로컬 원시 산출물과 위 저장소 고정본이다. 보고서 문장만 복사하지 않는다.
기존 원고의 기준을 바꾸지 않고 재계산·확장하는 작업이다.

기술 확인용 공식 문서:
- SciPy bootstrap: https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html
  짝지은 재표집은 같은 인덱스를 사용한다. 세션 구조의 설계는 기존 프로젝트 규약을 계승하며,
  scipy의 기본 프레임 재표집을 그대로 사용해 세션 부트스트랩이라고 부르지 않는다.
- BOP 평가 정의: https://bop.felk.cvut.cz/tasks/
  사전에 정의한 객체 전체 대칭을 사용한다는 원칙을 확인하는 용도다.
  본 프로젝트의 E_sym/ADDsym을 BOP 표준 지표로 재명명하거나 평가식을 교체하지 않는다.

마지막 실행 지시:
현재 상태·재사용 가능한 것·막힌 항목만 먼저 짧게 보고한 후 위 A~G를 실행하라.
처음부터 N3를 다시 학습하지 말고, 리프터 단계는 단 하나도 실행하지 마라.
