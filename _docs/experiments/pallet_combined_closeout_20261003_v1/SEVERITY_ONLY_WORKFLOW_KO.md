# 리프터 원본 가림 분류

사용자 요청에 따라 기존 `scripts/annotate/annotate.py`의 이미지 표시·프레임 이동 루프에 가림 분류 전용 화면을 연결했다. 고정 120장 원본을 보여주며 모델 예측·오차·코너 번호는 표시하지 않는다. 기존 정적 319장의 완료 주석은 재사용하고 다시 요구하지 않는다.

```bash
/home/minjae/anaconda3/envs/pallet-yolo26/bin/python scripts/research/pallet_lifter_case_review_20261003_v1/open_severity_annotation.py
```

| 입력 | 분류 | 동작 |
|---|---|---|
| 1 또는 첫 버튼 | 가림 없음 (`clean`, `none`) | 저장 후 다음 이미지 |
| 2 또는 둘째 버튼 | 중간 (`moderate`, `partial`) | 저장 후 다음 이미지 |
| 3 또는 셋째 버튼 | 어려움·심한 가림 (`severe`, `heavy`) | 저장 후 다음 이미지 |
| P | 이전 이미지 | 분류 수정 가능 |
| N | 판단 보류 | 레이블 없이 다음 이미지 |
| R | 현재 분류 취소 | 기록을 남기고 미분류로 복원 |
| S | 이미 분류한 이미지에서 다음 | 미분류 상태에서는 저장하지 않음 |
| +/−, H/J/K/L | 확대·이동 | 분류 변경 없음 |
| Q | 종료 | 저장된 선택 유지 |

식별자는 입력하지 않는다. 자동 생성한 로컬 별칭을 기억하되 사람의 신원·예측 노출 이력은 확인 완료라고 선언하지 않는다. 원본 영상·이미지·GT·고정 manifest·plan·코너 검수 파일은 보존한다. 뒤쪽 면의 자체 가림만으로 외부 가림 등급을 자동 결정하지 않는다. 과거 상세 축별 주석 규약과 동일하다고 주장하지 않는다.

실제 선택은 `data/pallet/results/pallet_lifter_case_review_20261003_v1/review/SEVERITY_REVIEW_IN_PROGRESS.json`에 저장된다. 프레임 ID, 원본 이미지 SHA-256, 입력 계약 해시, 키/버튼 입력, 선택 시각, 수정 이력을 연결한다. `SEVERITY_GROUPS.json`에는 세 등급과 미분류의 이미지 경로 목록을 별도로 저장한다. 다시 열면 첫 미분류 이미지부터 이어진다.

이 결과는 사람의 가림 등급 입력만 기록한다. 코너 좌표·대상 대응·독립 6D 정답·검수자 신원 확인까지 완료했다고 승격하지 않는다. CLI가 레이블을 추정하거나 실제 사용자 입력 없이 사람 검수 완료를 만들지 않는다.

검증: 입력 120장 해시·치수 검증 통과. 임시 디렉터리에서 원본 이미지 화면 렌더, 미입력 시 저장 방지, 버튼→키 처리→저장/다음, 키 선택, 수정, 재시작, R 취소, 그룹 목록, 코너·자세 상태 보존을 확인했다. 데스크톱 창 `Annotate - Lifter occlusion 1 2 3`의 `IsViewable` 상태를 확인했고 실제 사용자 입력의 저장 로그도 확인했다. 합성 검증은 실제 주석 저장소에 쓰지 않았다.
