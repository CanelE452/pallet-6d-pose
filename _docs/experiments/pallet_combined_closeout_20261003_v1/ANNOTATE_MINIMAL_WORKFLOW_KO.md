## 저장과 재개

- 기존 편집기는 변경하지 않고 이번 실행 안에서만 저장·입력 어댑터를 연결한다.
- `review/annotations_in_progress.json`: 기존 평가기와 동일한 검수·타임스탬프·frame ID·마스크 규약으로 저장.
- `review/native_annotations/primary/`, `repeat/`: 네이티브 편집기의 분리된 기록.
- `review/LIFTER_REFERENCE_REVIEWED.json`: 저장 시 제출된 범위를 자동 내보냄. 수동 export를 반복할 필요 없음.
- `Shift+S` 중간 저장은 완료 참조로 내보내지 않는다. 상태를 입력하지 않은 코너가 있으면 완료 저장을 막는다.
- 다시 실행하면 완료 프레임은 작업 목록에서 제외한다. 평가 분모와 고정 manifest는 그대로 유지한다.
- 반복 24장에서는 첫 검수 좌표를 불러오지 않는다. 동일 검수자의 반복은 독립 두 사람 검수로 기록하지 않는다.
- 원래 브라우저 코너 서버와 동시에 쓰지 않는다. 이번 전환 시 브라우저 검수 서버는 종료했다.

## 번호와 대칭에 대한 정정

처음 추가한 도식은 시점 때문에 ID0이 뒤쪽처럼 보였다. 도식을 기존 annotate.py의 near-face 규약에 맞춰 앞면 0–3, 뒷면 4–7로 고쳤다. 원본 이미지나 저장된 좌표/번호를 재배열한 것은 아니다.

가까운 면: `0 왼쪽 위 → 1 오른쪽 위 → 2 오른쪽 아래 → 3 왼쪽 아래`. 뒷면은 대응하는 4/5/6/7이다. 클릭하는 시간 순서는 바꿔도 되지만 먼저 해당 번호 키를 선택해야 한다. 번호 자체를 임의 순서로 섞으면 안 된다.

현재 리프터 `metrics/evaluate.py`의 기본 `evaluate_visible_corners` 호출은 `mode=canonical`이다. 네 방향 회전 대칭을 자동 적용하지 않는다. `frozen_whole_permutation`은 별도 사전 고정 계약과 호출이 필요한 선택 분석이다. 이 변경에서는 평가 규약을 바꾸지 않았고, C4 전체 회전과 코너별 임의 순열을 혼동하지 않는다. 대칭적으로 같은 물체라도 현재 고정-ID 결과와 대칭 허용 결과를 섞을 수 없다.
