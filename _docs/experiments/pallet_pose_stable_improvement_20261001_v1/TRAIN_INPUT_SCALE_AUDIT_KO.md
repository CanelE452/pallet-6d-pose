# 학습 입력의 해상도·크기 정규화 확인

**DIVERSE251은 같은 refiner crop 단위와 bbox 크기로 정규화해도 고정 의사 타깃과의 입력 좌표 차이가 더 크다.** 원영상20px 기준122개 대50개만으로 학습 난도를 단정해서는 안 되지만, 이 차이가 원영상 해상도만으로 생긴 것은 아니다.

두 군의251장씩 모두 실제 이미지 header가 **640×480**이었다. Refiner 입력도 모두288×384, 출력 heatmap은72×96이다. 두 군을 합친452개 고유 RGB와 pair 파일의 hash를 검증했고 모델 추론·새 학습·평가 GT 접근은 하지 않았다.

| 고정 pseudo target과 입력의 차이 | SINGLE251 | DIVERSE251 |
|---|---:|---:|
| 유효 코너 수 | 2008 | 1913 |
| 원영상 오차>20px | 50/2008 (2.49%) | 122/1913 (6.38%) |
| 원영상 중앙값 / P90, px | 1.972 / 7.814 | 3.481 / 14.659 |
| **공통 crop 중앙값 / P90, px** | **2.046 / 8.095** | **3.231 / 11.552** |
| **bbox 대각선 대비 중앙값 / P90** | **0.848% / 3.368%** | **1.389% / 4.927%** |
| 출력 heatmap 중앙값 / P90, px | 0.511 / 2.024 | 0.808 / 2.888 |

마스크는 기존 `OCC.target_valid AND OCC.valid`를 그대로 사용했다. 중심 index8은 제외했고, 감독 대상인데 입력 invalid인 코너는 두 군 모두0개였다. 표는 유효 코너를 모은 분포이며 동일한 코너 집합의 paired 차이가 아니다. 각 영상에 같은 가중치를 주기 위해 영상별 중앙값의 분포도 별도로 계산했다. 영상별 crop 중앙값들의 중앙값은 SINGLE2.051px, DIVERSE3.445px로 같은 방향이다.

원영상에서 crop으로 가는 isotropic affine 배율이 다르므로 원영상20px는 두 군에서 같은 입력 변위를 뜻하지 않는다. SINGLE의20px는 crop에서16.63–23.33px, DIVERSE는7.22–51.32px에 해당했다. P90의 DIVERSE/SINGLE 비도 원영상1.876배에서 crop1.427배로 줄었다. 따라서 원영상 기준만 사용하면 두 분포의 차이를 실제 refiner 입력 공간보다 크게 보일 수 있다.

계산식은 다음과 같다. 모든 crop matrix의2×2 부분이 양의 isotropic scale임을 확인했다.

- crop 오차: `norm(points_crop − target_crop)`
- 원영상 오차: `crop 오차 / crop scale`
- 상대 오차: `원영상 오차 / norm(predicted bbox의 대각선)`
- 출력 heatmap 오차: `crop 오차 / 4`

이 결과는 **고정 Replay+self-occlusion PnP 의사 타깃을 따라가려면 보정해야 할 입력 변위가 상대적으로 크다**는 관찰이다. 의사 타깃 자체의 물리 정확도, 실제 가림 정도, 모델 학습의 어려움 또는 자연99의 개선을 입증하지 않는다. 보고서에서는 단순히 “더 어렵다”보다 “크기 정규화 후에도 입력과 고정 의사 타깃의 차이가 더 크다”라고 쓰는 것이 정확하다. 기존 선택·loss·threshold·입력 lock은 변경하지 않았다.

모든 프레임의 배율·bbox 크기·마스크 지원 수·단위별 통계와 recording별 집계는 [TRAIN_INPUT_SCALE_AUDIT.json](TRAIN_INPUT_SCALE_AUDIT.json)에 있다.
