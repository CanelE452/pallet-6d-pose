팔레트 6D pose 원인 진단 — CLI /goal + /plan
작성일: 2026-09-30 (KST)
사용: CLI 채팅창에 /goal 블록, 이어 /plan 블록을 전달한다. 셸 명령이 아니다.

/goal

[최상위 목표]
단안 RGB 팔레트 6D pose 연구에서 clean→가림 전이의 개선이 어느 단계에서 끊기는지 검증하고,
자연 가림에서 T와 R을 함께 개선하기 위한 다음 개입 하나를 근거에 따라 선택한다.
T는 팔레트 중심 위치의 오차, R은 현재 평가의 대칭을 반영한 회전 오차다.

[결과를 사용할 사람과 판단]
민재와 지도교수가 다음을 판단할 수 있게 한다.
1. 타깃 정확도 → 학습 → 새 장면 전이 → PnP·후보 선택 → 평가 중 어떤 연결이 약한가?
2. 지금 개입할 대상은 보정기, 학생 자기학습(ST, self-training), 후보 선택, 검출,
   데이터 구성, 평가 참조 중 무엇인가?
3. 무엇이 확인됐고 무엇이 추정으로 남았으며, 다음 최소 비교가 무엇인가?
방법 논문의 목표는 유지한다. 분석형 논문으로의 전환을 임의로 결정하지 않는다.

[현재 출발점과 검증 수준]
[확인: 사전 감리 기준 커밋 d10a8c7fd456a339b735d7504ac403d5eb15bb5c]
평가 full128 = clean29 + Moderate21 + Severe78이고, natural99 = Moderate21 + Severe78이다.
clean29는 학습용 clean78과 다르며, natural99마다 대응하는 clean 이미지가 있는 것은 아니다.
기존 natural93과 현재 natural99는 공통92장이고 단순히 6장 추가된 관계가 아니다.
근거: 이 문서 끝의 S1, S2. 실행 시 실제 ID 목록과 평가 정의를 다시 대조한다.

[추정·미검증]
FULL125의 현재 natural99·동일 GEO 평가 공백, 큰/동시 코너 오류의 분포 차이,
clean RGB와 가림 RGB에서의 보정 능력 차이, 타깃 추종과 정확도의 불일치,
검출·W/D 선택·참조 불확실성을 경쟁 설명으로 검증한다.
공개 기록에서 못 찾은 결과가 로컬에 있으면 계약 일치를 확인해 재사용한다.

[이번 실행 목표의 범위]
기존 결과·캐시 재사용, 필요한 최소 평가 어댑터, CPU pose 재계산·분석,
지정된 고정 체크포인트의 추론까지 수행한다. 새로운 학습은 0회다.
E0→E1·E2→E3를 우선하고, E4–E6은 남은 질문과 입력 가용성에 따라 수행한다.
E7의 기존 데이터 분석은 모든 비교에 붙인다.
신규 촬영·재클릭·GT 수정·데이터셋 확대·새 학습은 근거와 후속 계획까지 작성한다.

[완료 조건]
- FULL125 보정 전후를 현재 natural99의 동일 T/R 계약으로 비교하거나,
  비교를 막는 정확한 파일·계약 공백을 기록했다.
- 2D/의사 타깃 개선과 실제 T/R 개선을 구분했다.
- 후보 선택 여지, 검출 실패, 가림 RGB, 좌표 오류, 전이 조건을 가능한 범위에서 분리했다.
- 전체 분모·실패 수·recording별 변화·모델 계보를 추적할 수 있다.
- 각 질문을 ANSWERED / UNRESOLVED / BLOCKED / SKIPPED로 판정했다.
- 다음 학습 또는 데이터 개입은 근거가 있는 한 가지 비교로 좁혔다.
개선 수치가 나오지 않아도 원인 후보 배제·조건 발견·자료 공백 확인이면 진단의 성과다.
개선되는 조합을 찾을 때까지 실험을 늘리는 것을 완료 조건으로 삼지 않는다.

/plan

이 문서는 앞서 합의한 E0–E7 진단 설계를 CLI에 넘기는 실행 계획이다.
현재 CLI가 계획 전용 모드라면 이 범위와 실행 순서를 먼저 고정한다.
실행 단계에 들어가면 이미 범위에 포함된 캐시 분석·최소 구현·고정 모델 추론을 계속 진행하고,
새 학습이나 신규 수집이 필요한 지점에서는 근거와 구체적인 후속안을 남긴다.
이 답변에 없는 기존 변수명·스키마·체크포인트 경로를 추측해서 사용하지 않는다.

[표기와 용어]
- [확인]: 실제 읽은 파일·실행 로그·관찰 결과를 출처와 함께 기록.
- [추정]: 관찰로부터의 원인 해석·일반화.
- [추정·미검증]: 아래 대조실험·임시 예산과 후속 설계.
- 참조 pose: 저장된 2D 주석, K(카메라 내부파라미터), 치수로 만든 평가용 (R_ref,t_ref).
  독립 장비의 실측 정답이라고 가정하지 않는다.
- PnP(Perspective-n-Point): 3D 점과 영상 2D 점의 대응으로 카메라 기준 pose를 구하는 절차.
- W/D: 폭/깊이 축 배정. GEO는 저장소의 기존 후보 선택기.
- Oracle: 평가 참조를 이용하는 진단 개입. 실제 추론 성능과 분리한다.
- R0: 기준 pose 추정기. PRIOR1/FULL125: 보정기. OLD_REF217: 별도 ST 학생.
  정확한 계보·체크포인트·설정은 실제 파일에서 확인한다.

0. 작업 시작과 Phase 0
- 최상위 목적을 위 /goal에서 가져와 실행 manifest 첫 부분에 적는다.
- 실제 저장소 루트, 현재 HEAD, 작업 트리 변경, 프로젝트 지침, 사용 환경을 확인한다.
- 사전 감리 커밋은 d10a8c7fd456a339b735d7504ac403d5eb15bb5c다.
  HEAD가 달라도 강제로 되돌리지 않는다. 관련 변경과 기존 결과를 확인하고 실행 기준을 기록한다.
- 기존 데이터·원본 GT·체크포인트·보고서·사용자 변경을 덮어쓰지 않는다.
- Ubuntu/GPU 실행 환경과 필요한 로컬 이미지·체크포인트 가용성을 확인한다.
  캐시로 가능한 CPU 분석은 GPU나 이미지가 없어도 먼저 끝낸다.
- 각 E 항목에 목적 / 기존 답 / 새로 구별할 설명 / 필요 입력 / 예상 결과별 결정 / 중단 조건을 적는다.
  이미 답이 있고 조건도 같은 항목은 재사용한다. 결정이 바뀌지 않는 추가 실험은 SKIPPED와 이유를 적는다.
- 데이터·평가 계약이 미확정이면 해당 의존 실험보다 계약 확인을 먼저 한다.
  한 분기가 막혀도 다른 독립 분석은 계속한다.

1. E0 — 입력·평가 계약 고정
- S1–S8 중 관련 파일과 실제 호출 코드를 rg로 찾고 읽는다. 문서 제목만으로 구현을 추정하지 않는다.
- natural99, clean29, full128, old natural93, 공통92의 실제 이미지 ID 목록을 연결한다.
- 각 모델의 학습/선택/평가 이미지 및 recording 계보를 확인한다.
  clean29를 특정 모델의 미관측 데이터로 부르려면 그 모델에 대해 중복을 확인한다.
- 이미지 SHA, checkpoint hash, 입력/출력 캐시, 좌표계, resize/padding/crop,
  K·왜곡 처리·치수·원점, 키포인트 순서, 허용 대칭, PnP·GEO 버전을 기록한다.
- 실제 보정기 출력의 invalid-point 복원, 인덱스8 처리, confidence 및 후처리를 그대로 재현한다.
  좌표의 유효성(validity)을 가시성(visibility)으로 해석하지 않는다.
- T는 현재 중심 위치 오차(cm), R은 현재 회전 오차(°)를 유지한다.
  현재 주 지표는 natural99의 T 중앙값과 R 중앙값이다.
  보조 지표는 P90, 유효/실패/미검출 수, 같은 프레임의 동시 개선·악화다.
- 기존 6D 평가에 2D 평가의 IoU gate나 새 제외 규칙을 추가하지 않는다.
- 전체128/99의 기존 실패 정책을 유지하고,
  전체 파이프라인 / 동일 객체 매칭 성공 / 공통 유효 pose 진단의 분모를 따로 표시한다.
- 입력 계약 검증이 실패하면 해당 수치는 BLOCKED 처리한다.
  누락 행·미검출·PnP 실패를 개선 없음 또는 성공 프레임으로 대체하지 않는다.

2. E1 — FULL125의 현재99 T/R 연결: 최우선
2A. 기본 비교
- FULL125에 실제 들어간 full128 입력과 저장된 출력 좌표부터 찾는다.
- 같은 입력에 대해 identity(보정 없이 통과), PRIOR1, FULL125를 비교한다.
- 같은 PnP 후보 생성과 같은 기존 GEO로 현재 natural99와 clean29를 평가한다.
- OLD_REF217+GEO는 별도의 현재 성능 기준으로 제시한다.
  OLD_REF217와 FULL125의 차이를 순수한 보정기 효과라고 부르지 않는다.
- 같은 입력·변환·모델을 복원할 수 있고 캐시만 없으면 고정 모델 추론으로 채운다.
  checkpoint 또는 필수 입력을 못 찾으면 다른 모델로 대체하거나 재학습하지 않는다.

2B. 후보 선택과 좌표 보정의 효과
- 실제 운영 경로: 같은 GEO 알고리즘으로 후보를 재선택한다.
- 진단 경로: 보정 전 W/D 가설을 고정한 채 각 출력 좌표로 연속 R/t를 다시 계산한다.
- 기존 branch 진단 구현을 재사용하고 현재 FULL125 입력에 대한 계약만 확인한다.
- 같은 W/D 가설은 같은 R값이나 같은 PnP 내부 해를 보장하지 않는다고 명시한다.
- 보정 전후 2D, T/R, 후보 변경, 유효성 변화를 같은 프레임에 연결한다.

2C. 서로 다른 정확도 기준을 구분
- clean 입력의 R0 예측에 가까워짐: clean 예측 복원.
- 저장된 실제 학습 의사 타깃에 가까워짐: 학습 타깃 추종.
- 평가 2D 주석/참조 pose에 가까워짐: 평가 정확도.
- TRAIN의 실제 타깃과 DEV에 같은 생성 절차로 만든 진단용 타깃을 구분한다.
  natural99에 대응하는 clean 이미지나 clean 정답 타깃이 있다고 가정하지 않는다.
- 기존 endpoint 결과로 질문이 해결되면 추가 좌표 보간은 생략한다.
- 타깃 방향과 pose 결과의 관계가 남을 때만 lambda={0,0.5,1}을 사전 고정해 분석한다.
  q(lambda)=q_model+lambda*M*(q_target-q_model), M은 실제 변경/감독 가능한 점이다.
  배포 코드의 인덱스8·유효성 처리를 유지하고 참조 중심을 별도로 주입하지 않는다.
  최적 lambda를 natural99에서 골라 새 방법의 성능으로 보고하지 않는다.

2D. Source256의 알려진 기하로 연결 확인
- S7의 기존 renderer GT 연결을 재사용한다.
  이미지 ID/SHA/경로 일치와 K/pose/인덱스/현재 대칭 계약의 일치는 별도 확인한다.
- 기존 raw 좌표 캐시가 있으면 같은 operational output으로 2D와 T/R을 함께 계산한다.
- 예전 source R 집계값을 현재 R로 복사하지 않는다.
- source stress가 좌표 손상 실험이면 실제 RGB 가림 실험이라고 부르지 않는다.
- source 결과는 변환과 합성 조건의 진단이며 자연 참조의 정확도 증명이 아니다.
- 입력 캐시가 없으면 기본 E1/E3을 우선한다.
  source 신규 추론은 실제 남은 변환/기하 질문이 있을 때만 아래 예산 안에서 수행한다.

3. E2 — 후보 선택 여지와 검출 꼬리
- 기존 후보별 pose·오차를 재사용해 현재 GEO 선택과 정확한 ID로 연결한다.
- T-best는 argmin_k ||t_k-t_ref||인 후보 하나의 전체 (R_k,t_k)를 선택한다.
  R-best도 후보 하나를 선택한 후 그 후보의 T와 R을 함께 보고한다.
- 서로 다른 후보의 최소 T와 최소 R을 합친 가상 pose/동시 성능을 만들지 않는다.
- 현재 선택 대비 T만 / R만 / 둘 다 / 둘 다 아님을 프레임별로 집계한다.
  동률 처리 규칙은 집계 전에 고정하고 기록한다.
  과거 D9 기준 장수를 현재 GEO 기준 장수로 재사용하지 않는다.
- 박스 매칭/IoU, 모든 저장된 박스 후보, 후보 T/R, recording, T 오류 순위를 연결한다.
  큰 T 오류 중 검출 미매칭, 맞는 후보의 오선택, 모든 박스 후보 누락,
  같은 객체에서의 코너/PnP/W-D 문제를 구분한다.
- 필요할 때 기존 박스 후보 중 참조와 가장 잘 맞는 박스를 선택하는 진단을 수행한다.
- 참조 crop 재추론은 위 분석으로 검출의 영향이 남고 기존 ROI 경로를 재사용할 수 있을 때만 한다.
  crop 크기·문맥도 바뀌는 개입임을 보고하고 순수 검출 인과효과라고 부르지 않는다.
- 현재 후보 pool의 oracle은 그 pool의 여지다. 누락된 좋은 후보까지 포함한 절대 상한이 아니다.

4. E3 — clean29의 동일 이미지 RGB×좌표 2×2
- PRIOR1, FULL125와 각 입력 좌표의 identity를 기본 비교로 고정한다.
- 기존 검증된 마스크 생성 규칙 하나를 재사용하고 성능을 보기 전에 매개변수를 기록한다.
- 신규 마스크의 seed는42로 고정한다. 이는 임시 재현성 설정이며 성능 근거가 아니다.
  과거 실험 재현은 당시 seed를 유지한다.
- clean29마다 키포인트 위치를 덮는 마스크 1개,
  같은 색·면적·형태로 키포인트 위치를 피하는 마스크 1개를 만든다.
- 위치 선택은 고정된 기하 규칙으로 정하고 모델 결과를 보고 다시 뽑지 않는다.
  actual mask/좌표 중첩량을 저장한다. 적절한 배치가 불가능하면 해당 조건과 이유를 기록한다.
- qC=clean RGB의 R0 좌표, qO=가림 RGB의 같은 R0 좌표.
- CC=(clean RGB,qC), CO=(clean RGB,qO), OC=(가림 RGB,qC), OO=(가림 RGB,qO).
- 네 조건은 같은 clean 기준 bbox/crop/확대율/affine와 입력 메타데이터를 사용한다.
  좌표 외 조건을 고정한다. qO가 누락되거나 객체가 바뀌면 qC로 조용히 대체하지 않는다.
- 실제 배포 경로의 native OO를 별도 평가하고, 필요하면 native clean도 기록한다.
  controlled OO와 native OO의 차이는 crop·검출·입력 처리의 합성 차이일 수 있다.
- 전체 파이프라인 실패와 동일 객체 쌍에서의 보정 능력을 분리한다.
- 가시성 미검수 점은 '키포인트 위치 가림'이라고 표기한다.
  가림 mask가 실제 pose를 바꾼 것으로 처리하지 않는다.
- 절대 clean/가림 T/R, identity 대비 이득, clean 악화를 함께 보고한다.
  clean 성능이 나빠져 gap이 줄어든 것을 전이 성공이라고 부르지 않는다.
- 29장×2mask는 58개 독립 촬영 표본이 아니다.
- 가림이 실제 오류를 만들지 않았다면 stress 부족으로 기록한다.
  성공/실패가 나오도록 mask를 추가 탐색하지 않는다.

5. E4 — 가시성이 확인된 점의 부분 개입
- S8의 기존 사람 가시성 검수를 current99 ID와 연결한다.
  기존169개 등의 장수를 current99의 장수로 그대로 복사하지 않는다.
- visible / occluded / unknown을 유지한다.
  클릭 출처를 가시성으로 바꾸지 않으며 외부 가림/자기 가림이 미분리라면 명시한다.
- 같은 객체·canonical ID가 확인된 범위에서:
  baseline / 확인된 가림 점만 참조 교체 / 확인된 visible 점만 교체 / 두 집합 교체.
- unknown 좌표는 유지하고 교체 가능한 N과 전체 N을 함께 보고한다.
- 동일 W/D 재계산과 같은 GEO 재선택을 함께 평가한다.
- 참조 교체 효과는 이 입력 상태에 대한 개입 효과다.
  효과들을 더해 오류 원인 비율로 만들거나 보정기 전체의 상한이라고 부르지 않는다.
- 가림 점 제외 PnP는 현재 solver/입력 계약이 지원하고 추가 질문을 해결할 때만 한다.
  인터페이스 미지원과 알고리즘의 음성 결과를 구분한다.

6. E5 — 전이 단계와 오류 구조: 조건부
- A=기존 TRAIN+기존 가림, B=같은 TRAIN+새 고정 가림,
  C=clean29+같은 새 가림, D=current natural99로 결과를 연결한다.
- A는 기존 결과를 재사용한다. C는 E3, D는 E1을 재사용한다.
- B는 E3 결과만으로 남는 전이 공백이 있을 때만 수행한다.
  TRAIN 29장을 ID·고정 규칙으로 선택하고 성능으로 선택하지 않는다.
  우선 native OO만 실행한다. 전체 2×2 재실행은 기본 범위에 넣지 않는다.
- A/B/C의 마스크 규칙·crop·타깃·오류량이 다르면 차이를 표시한다.
  A와 B 차이를 즉시 암기로, C와 D 차이를 즉시 자연 가림 인과효과로 해석하지 않는다.
- 큰/동시 오류가 남을 때만 고정 타깃 중심의 통제된 좌표 손상 비교를 한다.
  같은 점·개수·오류 크기·RGB·crop에서 독립 방향과 상관된 방향을 비교한다.
  주변 오류 분포를 맞추고 상관성만 바뀌었는지 점검한다.
- 좌표 변경 후 PnP만 재계산하는 분석과, 변경 좌표를 보정기에 넣는 복구 실험을 구분한다.
  복구 실험은 CPU/GPU와 무관하게 모델 forward로 집계한다.
  clean29에 대해 오류 크기1개·코너수1개·방향조건2개·보정기2개로 최대116회를 사용한다.
  크기와 코너수는 기존 오류 기록·검증된 손상 구현에서 정하고 추론 전에 manifest에 고정한다.
  크기/점 개수 sweep을 추가하지 않으며 입력 계약을 못 맞추면 후속 계획으로 남긴다.
- 기존 단일점20/30/40px 복구·일반 gradient·crop 확대를 이유 없이 반복하지 않는다.
- 같은 오류를 frozen 모델이 못 고친다는 관찰만으로 노출량 부족을 확정하지 않는다.

7. E6 — 기존 실사 지도 비교 기준
- S6에서 REALFT_A 계보와 실제 체크포인트를 확인한다.
- current128 예측 캐시를 우선하고 없으면 고정 체크포인트로 128장 추론한다.
- 실제 학습/선택 recording 중복, 검출 변화, 같은 GEO/지표 계약을 확인한다.
- 다른 teacher나 이름이 비슷한 모델로 대체하지 않는다.
- 성공은 그 모델·정보·학습 구성에서 개선 가능하다는 증거다.
  데이터/학습 범위 차이 때문에 의사 타깃 정보 부족만을 유일한 원인으로 확정하지 않는다.
- 무차이는 이 모델/구성의 결과다. 모든 ST·보정기의 불가능성으로 결론 내리지 않는다.

8. E7 — 모든 결과의 해석과 평가 신뢰성
- natural99와 clean29를 분리하고 각 recording의 N과 결과를 보고한다.
- 전체 중앙값 차이와 프레임별 차이의 중앙값을 구분한다.
- 기존 paired recording bootstrap와 leave-one-recording-out 절차를 재사용한다.
  natural99의6개, clean29의3개 recording과 반복 사용 DEV라는 한계를 적는다.
- 같은 참조를 쓰는 모델들을 같은 표본으로 재표집한다.
  실패/무한대 때문에 정의되지 않는 통계량이나 bootstrap draw를 조용히 버리지 않는다.
- CI가0을 포함하면 불확실성이 남았다고 쓰고, 효과 없음·측정 불가능으로 바꾸지 않는다.
- MDE(최소 탐지 효과)를 CI 폭이나 가정한2px 잡음으로 대체하지 않는다.
- 기존 metadata로 가림·앙각·거리·bbox크기·W/D·매칭 상태별 경향을 분석한다.
  표본 수와 recording 구성을 표시하고 작은 다중 교차 집단/회귀를 기본으로 추가하지 않는다.
- 원클릭/투영점 출처와 사람의 축 판단 확실성을 실제 기록에서 구분한다.
  geometry-resolved나 파일명 manual만으로 독립 사람 클릭·축 정답을 보장하지 않는다.
- 이미 실제 재클릭 정보가 있으면 입력 잡음과 상관성을 반영한 참조 민감도를 계산한다.
  모델 예측을 고정하고 모든 모델에 같은 참조 변동을 적용한다.
  투영점들을 독립 클릭처럼 흔들지 않는다.
- 원클릭·잡음 정보가 없으면 경험적 noise floor 계산은 BLOCKED로 기록한다.
  가정한 잡음을 쓰는 분석은 가정값에 대한 민감도일 뿐이라고 표시한다.
- 신규 재클릭/촬영은 실행하지 않는다.
  필요한 경우 12장×2인×2회 재주석, 또는 고정12pose의 clean→가림→clean 36장 촬영을
  임시 진단 예산으로만 제안한다. 검정력 근거가 있는 표본 수라고 주장하지 않는다.
- 중심 T와 다른 물리 앵커 T를 추가할 때는 동일 물리 점·대칭 대응을 확인한다.
  분명하지 않으면 생략하고 지표를 바꿔 주 결과를 좋게 만들지 않는다.

9. 선행연구 가정과 조건부 후속 계획
- L1/L2: clean/약한 입력 교사의 타깃과 증강된 학생 입력을 연결하는 원리.
  분류에서의 성공을 pose의 보장으로 쓰지 않는다. E1/E3을 먼저 해석한다.
- L3: 실제 오류 분포에 맞춘 pose refinement 원리. E5와 연결한다.
  팔레트 W/D/검출 오류를 인간 pose의 특정 오류 유형과 동일하다고 단정하지 않는다.
- L4: 렌더링·마스크·RGB 정합 원리. 실제 CAD/K/mask가 있을 때,
  현재 후보의 정합 점수가 참조에 가까운 후보를 구별하는지 확인하는 후속안을 적는다.
  RGB-only 경로를 외부 depth가 필수인 방법으로 설명하지 않는다.
- L5: 정지 객체와 카메라 상대 운동/연속 관측 제약.
  해당 정보가 있을 때 후보의 다중 프레임 일관성과 실제 T/R의 관계를 확인하는 후속안을 적는다.
  같은90° 오답도 시간적으로 일관될 수 있음을 고려한다.
- 렌더러·SLAM을 새로 구축하거나 논문 전체를 재학습하지 않는다.
  전제 검증과 전체 방법 재현을 구분한다.

- 2D와 T/R이 함께 좋아짐: 해당 조건의 효과를 인정하고 recording 일관성·실패율을 확인한다.

   조건·seed·명령·환경·자원·재사용 출처·원래 필드와 새 필드의 매핑.
2) FRAME_RESULTS.csv 또는 저장소 표준의 동등 파일
   실제 분석에 필요한 프레임/recording/모델/조건, valid·매칭 상태,
   입력/출력2D, T/R, 후보·선택·branch 변화. 없는 값은 출처와 NA 이유를 기록.
3) SUMMARY.json
   각 집합/recording/조건의 분모·실패 수·T/R·paired변화·공동개선·후보 여지.
4) REPORT_KO.md
   무엇이 문제였나 → 어떤 비교로 구별했나 → 확인된 관찰 → 경쟁 설명 →
   허용되는 결론 → 남은 공백 → 다음 최소 개입.
   각 E항목 상태, 재사용/실행/생략/차단 이유와 근거 파일을 연결한다.
   신규 학습·수집의 구체안은 이 보고서의 후속 계획에만 적는다.

필요한 그림만 저장소의 기존 방식으로 만든다:
- E1 보정 전후 T/R 변화와 후보 전환.
- E3 네 입력 조건의 절대 정확도와 identity 대비 변화.
- recording별 차이 및 E5 오류 크기/동시 발생별 복구.
표로 같은 판단이 가능하면 장식용 그림은 추가하지 않는다.

최종 답변에는 '무엇을 실행/재사용했는지, 무엇이 해결/미해결인지,
가장 강한 원인 가설과 반론, 다음 하나의 비교, 실제 비용'을 먼저 적는다.
이 진단 결과만으로 'ST/보정기는 원리적으로 불가능' 또는
'현재99에서 개선했으므로 새 recording에도 일반화한다'고 결론 내리지 않는다.
