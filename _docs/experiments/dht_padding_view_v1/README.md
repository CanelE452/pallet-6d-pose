# DHT 패딩 × 구도 실험 구성

이번 작업은 실행할 실험을 고정하고 데이터·코드·소규모 동작 검증을 준비하는 단계다. `main` 본학습 결과와 `smoke` 실행 결과를 구분한다. 본학습을 수행하기 전에는 어느 조건이 더 좋은지 판정하지 않는다.

## 질문과 1차 비교

반사 패딩으로 학습한 모델의 추론 패딩만 바꾼 이전 진단과 달리, **각 패딩으로 처음부터 새 DHT head를 학습하고 같은 패딩으로 평가**한다. 동시에 기존 학습 분포와 낮은 구도를 보강한 데이터 구성을 비교한다.

| 학습 데이터 구성 | 반사 100px | 검정 공백 100px | 평균색 공백 100px |
|---|---|---|---|
| base: 기존 합성 2,048장 | seed 1·2·3 | seed 1·2·3 | seed 1·2·3 |
| low_balanced: 기존 1,024장 + 낮은 구도 1,024장 | seed 1·2·3 | seed 1·2·3 | seed 1·2·3 |

총 **18회**, 각 실행 **6,000 step·batch 12·AdamW(lr 0.001, weight decay 0.0001)**이다. 학습 장수와 업데이트 수가 같다. 각 데이터 구성·seed 안에서는 세 패딩이 같은 이미지 순서와 초기 가중치를 사용한다. 초기 가중치 SHA와 배치 인덱스 순서 SHA를 저장해 일치를 검증한다. 기존에 학습된 DHT head를 불러와 fine-tuning하지 않는다.

백본은 기존 합성 사전학습 DOPE VGG로 고정하고, 같은 `128×50×50` 특징에서 DHT 앞뒤 head만 새로 학습한다. 이번 구현은 원 논문 전체 모델 재현이 아니라 이전 실험의 과제용 DHT다. 좌우 측면의 구조적 지지 직선 **8개**, 패딩 폭 **100px**, 입력 **400×400**, Hough 격자와 손실은 모두 고정한다.

모든 조건은 float32 이미지에 패딩·리사이즈를 적용한다. 평균색은 BGR `(103.53,116.28,123.675)`이며 ImageNet 정규화 후 0에 해당한다. 반사/검정 조건도 같은 정밀도의 리사이즈를 사용해 uint8 반올림 효과가 섞이지 않게 한다. 조건별 특징을 float16으로 저장하고 학습 때 float32로 읽는다.

## 데이터와 구도 분리

기존 2,740개 기록을 보존하고, 검증된 `camera_dynamic_0123_v4` 낮은 고도 합성 풀에서 학습 1,024장·검증 128장·평가 256장을 추가한다. 추가 풀은 renderer 실행 묶음 단위로 나누고 이미지 SHA 중복을 제거한다. 선택은 모델 오차와 무관한 고정 seed와 구도·크기 분포 기준이다. 구체적인 포함/제외 건수와 출처는 실행 폴더의 `DATA_AUDIT.json`에 기록한다.

| 평가군 | 역할 |
|---|---|
| 기존 synth_val 256 | 고정 최종 checkpoint의 합성 진단 |
| 기존 synth_test 256 | 기존 생성 계열의 head 미사용 이미지 |
| cross_v4 128 | 다른 기존 합성 계열 |
| low_val 128 | 추가 낮은 구도 풀의 검증 |
| low_test 256 | 추가 풀의 렌더링 묶음 분리 평가 |
| real_dev 52 | 기존 정본 수동 실사 개발셋; 학습에 사용하지 않음 |

합성 영상에서는 world camera와 cuboid 중심으로 확인한 카메라 고도를 **5° 미만 / 5–15° / 15–30° / 30° 이상**으로 집계한다. 실사에는 동일한 실제 각도 자료가 없으므로 카메라 각도를 임의로 붙이지 않는다.

합성의 실제 정면 방향에서 벗어난 좌우 회전각도 `<5° / 5–15° / 15–30° / ≥30°`로 별도 집계한다. 기존 학습에는 좌우 회전각5°미만이367장 있으므로 ‘정면 데이터가 전혀 없음’과 ‘낮은 카메라가 없음’을 구분한다. 추가 low_test에서5°미만은14장으로 소수 표본이다. 이 평가만으로 완전 정면 성능을 확정하지 않는다. 실사에는 이 world각도를 추정해서 붙이지 않는다.

모든 영상에서 투영된 측면/앞면 면적비와 윗면/앞면 면적비, 원영상 폭 대비 앞면 폭을 따로 기록한다. 측면 면적비 `≤0.1 / 0.1–0.3 / >0.3`, 윗면 면적비 `≤1 / 1–4 / >4`, 크기 비율 `<0.25 / 0.25–0.5 / 0.5–1 / ≥1`로 집계한다. 이 값은 영상상의 기하 비율이며 정확한 yaw, 실제 재료 경계의 가시성과 같지 않다.

각 구도·크기별 프레임 수와 `고도×측면` 조합의 빈 칸을 함께 표시한다. 실사는 `윗면×측면`의 투영 비율과 촬영 그룹으로 분리한다. **0장은 NO_DATA, 20장 미만은 소수 표본**으로 표시하고 그 칸에서 안정적인 일반화를 주장하지 않는다.

## 무엇으로 ‘되는지’ 판단하는가

각 선의 성공 기준은 **원본 위치 오차 ≤8px 및 무방향 각도 오차 ≤5°를 동시에 만족**하는 경우로 고정한다. 위치 오차는 정답 선분의 두 끝점에서 예측 무한직선까지의 수직거리 평균이다.

모든 구도에서 성공률, 위치·각도 중앙값, 90백분위, 이미지 수·평가 선 수를 보고한다. 각 seed의 수치와 그 요약을 구분하고, 특정 seed나 잘 나온 사진만으로 판정하지 않는다. 운영에 사용할 합격 성공률은 정하지 않았다. 실험상의 선 성공 기준을 제품 전체의 합격 기준으로 해석하지 않는다.

먼저 같은 데이터 구성에서 패딩 효과를 비교하고, 같은 패딩에서 데이터 구성 효과를 비교한다. 전체 평균과 별도로 낮은 고도·작은 팔레트·야외 그룹의 큰 실패가 늘었는지 확인한다. 모든 결과는 고정 최종 step에서 수집하며 실사 결과로 checkpoint나 학습 설정을 선택하지 않는다.

## 해석 제한과 다음 분리 실험

`base`와 `low_balanced`는 이미지 수는 같지만 서로 다른 생성 풀을 섞는다. 따라서 배경·재질·렌더링 조건이 함께 달라질 수 있는 **데이터 구성 비교**다. 구도만의 인과적 효과를 분리하려면 같은 자산·배경·조명·seed에서 카메라 위치만 바꾼 대응 렌더링이 별도로 필요하다.

현재 실사에서는 윗면 노출이 작은 22장이 실외 22장과 일치한다. 정면 실내, 높은 구도 실외 등의 빈 평가 조건은 이번 개발셋만으로 채울 수 없다. 새 물리적 촬영 세션으로 분리 평가해야 하며 정본 최종 평가셋을 개발 목적으로 가져오지 않는다. 백본의 상속 사전학습 이미지 목록은 없어 현재 합성 평가와의 전체 중복은 미검증이다.

1차 비교가 끝난 후의 독립 실험 후보는 다음과 같다. 이들을 현재 18개 조건에 섞어 원인 해석을 흐리지 않는다.

- 패딩 폭: 0 / 32 / 100px 및 좌표·특징 범위 변화.
- 패딩 영역을 제외한 DHT 집계와 올바른 유효 질량 정규화.
- 앞·뒤 가로 경계까지 포함한 12개 선.
- 검출한 ROI 확대 또는 높은 특징 해상도.
- 동일 장면에서 카메라만 바꾼 대응 합성 및 새 실사 촬영.

## 실행과 산출물

코드: `scripts/research/dht_padding_view_v1/`. 결과: `data/pallet/results/dht_padding_view_v1/`.

`prepare.py`가 메타데이터·조건별 특징 캐시를 준비한다. `train_eval.py`는 단일 데이터 구성·패딩·seed의 학습과 평가를 수행한다. `driver.py`는 기본적으로 계획 화면만 생성하며 **`--execute`를 명시하면** 준비→18개 실행→평가→집계→HTML을 순차 수행한다. 중단한 실행은 일치하는 출처·설정에서만 재개한다. HTML은 완료 후 기본적으로 브라우저에서 한 번 열리고, `--no-open`으로 끌 수 있다.

```bash
cd /home/minjae/Documents/github/pallet-pose/data/pallet/results/dht_padding_view_v1
/home/minjae/anaconda3/envs/pallet-pose/bin/python /home/minjae/Documents/github/pallet-pose/scripts/research/dht_padding_view_v1/driver.py --run-dir /home/minjae/Documents/github/pallet-pose/data/pallet/results/dht_padding_view_v1

# 준비된 본학습을 실행할 때
/home/minjae/anaconda3/envs/pallet-pose/bin/python /home/minjae/Documents/github/pallet-pose/scripts/research/dht_padding_view_v1/driver.py --run-dir /home/minjae/Documents/github/pallet-pose/data/pallet/results/dht_padding_view_v1 --execute
```

`smoke/`는 24개 합성 기록, 데이터 구성별 학습 8장, 20 step의 별도 설정이다. 실제 이미지를 사용하지 않고 여섯 조건의 실행·평가·출처·동일 초기값/배치 순서 확인에만 사용한다. 이 수치를 본학습 성능 표에 넣지 않는다.

## 이번 구성 작업의 확인 결과

- 데이터 감사 PASS: 4,148개 기록, 두 학습 구성 각각2,048장, 실사 학습 포함 없음.
- 세 패딩의 전체 특징 캐시 생성 완료.
- 별도 smoke6개 모두 최종20step 학습·평가 완료. 실행당60개 유효 선, 합계360개 평가 행을 확인했다.
- 동일 데이터 구성·seed에서 세 패딩의 초기 가중치와 전체20step 배치 순서가 일치한다. 재개 경로의 중단·재개 실험은 수행하지 않았다.
- 대표6개 합성 이미지의 world투영·구조 정답을 개별 시각 확인했다. 전체 풀의 물리적 엣지 가시성 검증을 뜻하지 않는다.
- 본학습18개는 **NOT_RUN**이다. 준비 완료를 패딩 성능 검증 완료로 해석하지 않는다.

진입 화면은 `data/pallet/results/dht_padding_view_v1/experiment_dashboard.html`이다. 증거는 같은 폴더의 `SETUP_COMPLETION.json`, `SMOKE_CHECKS.json`, `DATA_AUDIT.json`, `DATA_VISUAL_QA.json`에 있다.

자동 열기 수정: 이 환경의 로컬 `text/html` 연결 프로그램이 Slack이어서 `xdg-open` 성공만으로 브라우저가 열리지 않았다. 공용 `open_gallery`는 설치된 브라우저의 새 창을 먼저 실행하도록 수정했다. 현재 페이지는 Chrome으로 직접 열고 X11에서 해당 제목의 창이 현재 데스크톱에 표시됨을 확인했다. 시스템 파일 연결 설정은 변경하지 않았다.
