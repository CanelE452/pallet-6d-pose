# 학습형 보정 이득 선택기 — GPU 실험 결과

2026-09-20 KST. 사용자가 요청한 작은 선택 모델의 학습·실사 평가를 완료했다.

## 결론

**학습은 정상 수행됐지만 초록 팔레트의 잘못된 보정을 구별하는 데 실패했다. 기존 최종 N2를 교체하지 않는다.**

- 비초록 기존 참조점: PCK@10 59.459% → 60.000%, 정확점 330 → 333. 작은 개선이며 참조점 출처가 확인되지 않은 개발 평가다.
- 초록 수동 GT: PCK@10 81.351% → 78.267%, 정확점 554 → 533. 21점 순손실이며, 이전 수작업 코너쌍 필터의 79.736%보다도 낮다.
- 사용자가 지적한 P0의 **4.34 → 168.30px 오보정을 이번 선택기는 받아들였다.** 반대로 실제로 좋은 **40.99 → 6.85px 보정도 유지했다.** 큰 이동의 좋고 나쁨을 충분히 구별하지 못한 결과다.
- 초록 Replay 신규 훼손 34점 중 9점만 차단하고 25점은 남겼다. Replay 개선 7점 중 4점 유지, 3점 손실.
- 결과를 보고 기준·학습량을 바꾸는 추가 실험은 하지 않았다. 기존 R0/N2/Replay, 평가 라벨, 최종 배포 모델은 보존했다.

## 실제로 무엇을 학습했나

기존 N2와 Replay는 고정하고, **53,233개 파라미터의 작은 CNN/MLP 선택 모델**만 새로 학습했다. GAN이나 새 좌표 생성 모델은 아니다.

입력은 다음과 같다.

- N2 점과 Replay 후보 주변 RGB 패치: 각 24×24, 한 변은 예측 박스 대각선의 12%.
- 예측 박스를 1.25배 확장한 전체 물체 RGB crop: 96×72. 원본 영상 전체를 보는 것은 아니다.
- R0/N2/Replay의 점 배치·이동량, Replay heatmap 분포 요약, native 코너 번호 및 연결된 코너의 특징.

GT를 받는 함수와 영상·예측만 받는 모델 입력 함수를 분리했다. 학습 목표는 `100 × (N2 오차 − Replay 오차) / 예측 박스 대각선`이다. 양수면 Replay가 해당 점을 개선한다. 양 끝점의 예측 이득이 모두 양수인 수직 모서리쌍만 Replay로 바꾸고, 나머지는 정확한 N2 좌표를 유지한다. 두 점을 평균내거나 GT 쪽으로 새 좌표를 만들지 않는다.

학습 설정은 seed 1, AdamW(lr 0.001, weight decay 0.0001), batch 32, masked SmoothL1(beta 1), gradient clip 5, **고정 1,500 step / 마지막 체크포인트**다. 임계값은 처음부터 0이며 검증/실사 점수로 조정하지 않았다. 이전 기하·반전 필터를 추가로 섞지 않았다.

학습 완료 체크포인트: `data/pallet/results/pallet_posefix_utility_selector_v1/last1500.pt`.

## 학습 데이터와 누수 방지

| 분할 | 원본 이미지 | 독립 scenario 그룹 | 정상+오차 입력 |
|---|---:|---:|---:|
| 선택기 TRAIN | 1,286 | 1,003 | 2,572 |
| 선택기 VALIDATION | 330 | 251 | 660 |

합성 1,616장 중 같은 장면의 P0/TEX 버전은 같은 그룹에 묶었다. 분할 사이에 scenario·이미지 SHA 중복이 없다. 기존 Replay의 합성 probe 256장뿐 아니라 해당 249개 scenario 전체를 제외했다. 이 풀은 N2·원본 PoseFix·Replay의 가중치 학습과 분리돼 있다.

정상 R0 입력과, 정답을 보지 않고 두 수직 모서리쌍에 박스 대각선 5–15%의 이동을 주입한 입력을 각각 만들었다. 같은 입력에 실제 고정 N2와 Replay를 실행했다. 출력 후보와 RGB 특징을 만든 다음에만 합성 GT로 개선량을 계산했다. 두 후보에는 **N2가 선택한 동일한 전체 물체 대칭 분기**를 적용했고, 점마다 가장 가까운 GT를 따로 붙이지 않았다.

중요한 제한:

- 이 합성 풀은 과거 R0 validation/checkpoint 선택과 여러 개발 평가에 노출돼 있었다. 후보 생성기 전체에 완전히 미노출인 신규 데이터가 아니다. 기존 원본 partition 파일이나 과거 보고서는 변경하지 않고 이번 선택기 분할을 별도 저장했다.
- 합성 풀은 C1 448장, C2 1,168장, **C4 0장**이다. 정사각형 초록 팔레트 학습 분포를 확보한 실험이 아니다.
- 실사 TRAIN 9장, 비초록 DEV72, 초록 GREEN150은 선택기 학습/검증 분할에 넣지 않았다. 실사 GT로 선택 임계값을 맞추지도 않았다.
- 합성 검증 수치는 검출이 매칭되고 GT가 지원되는 선택된 행에 대한 진단이다. 전체 합성 검출 실패까지 포함한 신규 벤치마크 수치가 아니다.

## 합성 검증 결과

보정 이득의 부호 정확도는 60.880%, 다수 클래스만 예측하는 기준은 54.844%, ROC-AUC는 0.6803이었다. 완전히 무작위인 판단보다 구별 정보는 있지만, 신뢰할 수 있는 안전 선택기로 볼 수준은 아니다. 예측 utility는 확률이나 보정된 confidence가 아니다.

| 합성 검증 입력 | N2 PCK@10 | Replay PCK@10 | 학습 선택기 PCK@10 |
|---|---:|---:|---:|
| 정상 입력 330장 | 95.233% | 91.811% | 93.618% |
| 큰 오차 입력 330장 | 54.018% | 76.317% | 75.932% |

정상 입력에서는 N2 대비 9점 복구 / 51점 훼손, 큰 오차 입력에서는 602점 복구 / 32점 훼손이었다. 즉 합성 검증에서부터 정상적인 점을 충분히 보호하지 못했다. 초록 실패를 단순히 색상이나 C4 부재 하나의 원인으로 확정할 수 없다.

위 합성 비교는 학습 target과 같은 고정 N2 대칭 대응 기준이다. 각 모델마다 최적 대칭 분기를 다시 고르는 실사 전체 지표와 해석 범위를 구별해야 한다.

모든 실사 출력 222장의 선택을 저장·해시 고정한 다음에 GT를 읽어 채점했다. 박스·검출 score·점 confidence·중심점·후보 순서는 유지했고, 사진을 평가에서 제외하지 않았다. 기존 3개 비교군의 1,116개 프레임/모드 결과가 이전 결과와 일치했다.

## GPU 실행과 수치 재현 정정

GPU는 RTX 3080을 사용했다. 최종 합성 후보 생성 루프는 약 135초, 작은 선택기 학습 루프는 6.66초였다. 이 시간은 코드 준비·수치 재현 진단·그림·검산을 포함한 전체 작업 시간이 아니다. 학습 CUDA peak allocated는 44.50MiB이며 총 GPU 점유량과 구별해야 한다.

학습 전 N2 저장본 재현 검사에서 계산 경로 차이를 발견했다.

1. FP32 batch1과 과거 cuDNN TF32 batch16 사이 차이로 0.001px 검사가 중단됐다. 좌표 변환/GT 오류가 아니라 계산 모드와 배치 구성 차이였다.
2. 원래 배치와 backend를 재현한 후, 추가한 bit-exact 검사에서 GPU box norm과 과거 CPU box norm 차이 0.0000401px도 발견했다. 이는 원래 0.001px보다 작았지만, CPU geometry와 raw 좌표 연산 순서까지 저장본과 일치시켰다.
3. 최종적으로 **정상 합성 1,616장의 N2 logits와 좌표를 전부 bit-exact, 최대 차이 0px로 재현**했다. 두 중단은 선택기 학습과 실사 평가 전에 발생했다. 원래 허용오차·학습 설정·손실·분할·모델은 변경하지 않았다.

기존 PROTOCOL/코드/실패 기록/부분 캐시는 보존했고, 실제 실행 wrapper와 정정 문서 SHA를 새 자료에 묶었다. 최종 자료는 `source_cpu_geometry_v2/`에 따로 저장해 이전 부분 캐시와 혼합하지 않았다. 정정 문서: `N2_RUNTIME_CORRECTION.json`, `N2_RUNTIME_CORRECTION_V2.json`, 완료 근거: `N2_RUNTIME_COMPATIBILITY_V2_COMPLETE.json`.

드라이버·전원·재부팅 변경이나 타 작업 강제 종료는 없었다. 완료 후 본 실험 GPU 프로세스가 종료되고 RustDesk가 유지되는 것을 확인했다.

## 판정과 재현

이번 결과는 **합성으로 학습한 작은 선택기의 제한된 개발 실험**이다. 보정 이득을 학습하는 발상 자체가 불가능하다는 증거는 아니지만, 현재 자료·모델·학습 설정으로 초록 실패를 해결했다는 증거도 없다. 추가 학습이 필요하다면 평가 150장을 몰래 TRAIN으로 바꾸지 말고 별도 데이터와 프로토콜을 마련해야 한다. 이번 작업에서는 추가 탐색이나 최종 모델 승격을 하지 않았다.

재현 순서:

```bash
python -m scripts.research.pallet_posefix_utility_selector_v1.run_generate_historical_n2_v2
python -m scripts.research.pallet_posefix_utility_selector_v1.train
python -m scripts.research.pallet_posefix_utility_selector_v1.evaluate apply
python -m scripts.research.pallet_posefix_utility_selector_v1.evaluate score
python -m scripts.research.pallet_posefix_utility_selector_v1.visualize
```

환경은 `/home/minjae/anaconda3/envs/pallet-yolo26/bin/python`이다. 원본 generator 직접 실행이 아니라 위 수치 호환 wrapper를 사용한다. 완료 파일은 덮어쓰지 않으며, 기존 모델·입력 바인딩 검사를 먼저 수행한다.

핵심 결과: `FIT.json`, `SOURCE_RESULTS.json`, `RESULTS.json`, `OUTPUTS_LOCK.json`. 소스: `scripts/research/pallet_posefix_utility_selector_v1/`. 기존 최종 모델은 그대로다.
