# 실행 기록과 저장 복구

이번 작업은 TRAIN 입력 진단입니다. 새 학습·새 후보 선택·VAL 성능 평가·실사 평가는 각각 0회입니다. 기존 판단 기준과 프로토콜은 바꾸지 않았습니다.

| 작업 | 실행 세션 | 종료 코드 | 결과 |
|---|---:|---:|---|
| 방향 특징 복원 | 24228 | 0 | 4개 expert의 유효 후보 20,776개, 186,984개 점 검증 통과 |
| 표현 진단 첫 실행 | 27248 | 1 | CPU 라이브러리 초기화 시 `/dev/null` 접근이 자체 guard에 걸림. 모델별 계산과 출력 생성 전 중단 |
| 초기화를 앞당긴 표현 진단 | 75391 | 1 | 4개 모델 계산 및 NPZ 저장 완료 후, 출력 NPZ 자체 해시를 읽는 단계에서 자체 guard에 걸림 |
| 별도 finalizer로 결과 확정 | 70906 | 0 | 동일 봉인 함수를 재사용해 계산하고 보존한 NPZ의 25개 배열을 dtype·shape·bytes까지 전수 대조한 뒤 JSON/MD 생성 |

첫 실행의 CPU 초기화 순서는 [운영 기록](RUNTIME_INITIALIZATION.json)에 보존했습니다. 두 번째 실행은 [출력 읽기 오류 기록](OUTPUT_BINDING_INCIDENT.json)에 당시 파일 SHA와 상태를 남겼습니다. 두 오류는 파일 접근 guard 구현의 결함이며 수렴 실패나 T/R 성능 실패가 아닙니다.

최종 복구는 [사전 복구 계획](RECOVERY_PLAN.json)에 따라 실행했습니다. 원래 봉인한 분석 코드는 수정하지 않았습니다. 별도의 finalizer guard가 기존 NPZ 읽기만 추가 허용하며, NPZ 쓰기는 금지합니다. 원래 분석 코드의 입력 검증·정규화·충돌·SVD 함수를 재사용하고, 최종 JSON은 원래 코드와 실제 실행기를 모두 기록합니다. 원래 생산기의 `run()`이 성공한 것으로 표시하지 않았습니다.

보존 NPZ의 SHA-256은 `2fe5a4a3a1d48fea2b6800d310ae3e0db0b7a1503893b577bc2b3a136cc6ab65`이며 크기는 2,874,500 bytes입니다. 복구는 이 파일을 덮어쓰거나 삭제하지 않았습니다. 계산 재시도 3회와 새 학습 0회를 구분합니다.
