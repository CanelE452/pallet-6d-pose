## 코드에서 확인한 실행 계약

- [확인] `recovery_pose_trainer.py::pose_parameter`는 `model.23.cv4*`, `one2one_cv4*`, `flow_model`에만 학습을 허용한다. 모든 BN running buffer는 eval/frozen이며 saved EMA에도 보호 tensor를 원값으로 복사한다. 따라서 현재 backbone/검출부/BN drift를 일반적인 full-model ST와 혼동하면 안 된다.
- [확인] `pallet_visible_transfer_closure_v1/fit.py::ExtendedTrainer`는 원래5epoch LR/criterion 계약을 유지하고 총10epoch 실행했다. step320 EMA와 loss/LR CSV exact parity를 검사한 뒤640으로 진행한다. fit2회의 실제 optimizer 합계1280이지 “추가320 두 번만 실행”이 아니다.
- [확인] `recovery_real_only.py::real_slots`는 같은512 real 목록을 두 번 이어1024로 만든다. 독립적인 source-loss coefficient 변경과는 다르다.
- [확인] `gate_a_headroom.py`는 per-keypoint teacher 최소오차와 실제 좌표 median/medoid를 별도 계산한다. `gate_b_corner_evidence.py`의 실제 선택은 RGB response/거리/line/cuboid direction 등 rank 점수이고 oracle error는 별도 GT 사후 계산이다.
- [확인] 설치된 `pallet-yolo26`의 `ultralytics/nn/modules/head.py::Pose26.forward_head`에서도 `kpts_sigma` 생성이 `self.training` 안에 있고 `fuse`가 sigma head/flow를 지운다. 옛 sigma 감사가 현재 이 설치 코드에서도 일치한다. raw sigma를 confidence나 모델간 비교 가능한 pixel 표준편차로 자동 승격하지 않는다.
- [확인] `pallet_model_conditioned_selector_v1/train_scorers.py`는 실제 TRAIN만으로 normalize하고 shared `Linear(94,1)` 두 fit을 한다. 기존 pooled S0+S1 학습보다 출력 수가 절반이라는 차이도 있어 “model conditioning만의 순수 인과효과”는 아니다.
- [확인] `pallet_single_model_preserve_v1/train.py`는 clean과 occluded preservation loss를 더해 adapter만320 update한다. zero-init parity 성공은 초기 동등성과 gradient 연결의 증거이고 이후 일반화/성능 보존 보장은 아니다.
- [확인] `pallet_hough_gain_selector_v1/core.py::assigned_target`와 `choose`는 GT utility와 inference 선택을 분리한다. Point가 정한 공통 whole-object assignment를 쓰므로 옛 arm별 symmetry-min 값과 숫자를 직접 섞으면 안 된다.

## 구현 오류·역할 오류의 보존

[확인] N2 utility selector의 첫 FP32/batch1 재현, 다음 GPU/CPU box normalization 문제는 학습 전 실패 기록이다. historical TF32/batch16/CPU decode 복원 후1616장 logits·좌표 bit-exact 검사가 통과했고 최종1500-step fit은 완료됐다. 따라서 최종 음성 결과를 `구현오류로판정불가`로 덮지 않는다. 반대로 수정 전 부분 cache는 최종 cache와 섞지 않는다.

[확인] DIM 실험의 camera-facing dimension 입력을 canonical metadata로 잘못 생각한 문제는 DIM 본학습 전에 renderer XYZ로 정정됐다. 옛 semantic-line symmetry median의 PASS는 polarity/indexed reprojection 감사에서 뒤집혔다. 정정 전 gate 결론을 새 연구의 성공/실패 증거로 사용하지 않는다.

[확인] old Wood source-pool block은 Wood116 전체를 평가로 예약한 당시의 조건이다. 현재Wood45로 recording 역할을 고정하면 REC001/002 train 후보를 사용할 수 있었으므로 그 과거 block은 전체적으로 현재에 적용되지 않는다. 반면 세로Wood225의 K 부재는 그대로다.

[확인] Hough/point-line의 synthetic gate 실패로 real 추론 또는 다음 단계 fit을 하지 않은 항목을 실사 성능0 또는 실사 학습실패로 쓰지 않는다. 국소보정 실패, single seed 손상, 작은 manual pilot 실패를 각각 전역형상·전체방법군·추가감독의 무용으로 확장하지 않는다.

## 다음 실험의 가장 좁은 근거

[추정] 우선순위는 (1) 현재217/361에서 target-following 및 실제증강·source/real gradient 0-step 감사, (2) 그 결과가 지지하면 **동일 support/노출/LR/학습부를 둔 기하증강 제거 RAW/REF pair**, (3) 현재고정후보 oracle가 큰 경우 기존GEO의 zero-fit 호환성을 먼저 보는 순서다. 원래 degrees/shear/perspective/flip/mosaic는0이므로 변경은 translate/scale로 정확히 쓰고, HSV 유지 여부와 source augmentation까지 바뀌는지 명시한다. “기하OFF”와 “모든증강OFF”는 다른 개입이다.

[추정] 이 후보의 가장 강한 반론은 기하변환이 정상적인 정규화여서 타깃모방 향상과DEV 악화를 맞바꿀 수 있다는 점이다. 다른 반론은 모방 잔차가 teacher label noise 또는 동결 표현에서 비롯됐을 수 있다는 점이다. 따라서 native/augmented TRAIN residual과 source/target 유효점·loss weight를 함께 기록하고, 결과가 좋아져도 augmentation 원인 하나로 확정하지 않는다. 현재 감사는 해당 fit을 승인예산에 소모하거나 실행했다고 기록하지 않는다.
