# GREEN150 보정 실패: 저장 예측과 고정 모델 확률분포 진단

2026-09-19. 이번 작업은 진단만 수행했다. 추가 학습, 수도레이블 생성, GT 수정, 최종 모델 교체, 평가 기반 하이퍼파라미터 선택은 하지 않았다.

## 결론

초록 팔레트 전체를 검출하지 못하는 문제가 아니다. 이번 PoseFix 추가학습 모델의 악화는 **다각도 사진에서 일부 코너를 다른 위치로 잘못 옮기는 현상**에 집중된다. 고정 모델의 실제 출력 분포를 확인하니 다음 두 기전이 모두 있었다.

1. **다른 물리적 코너를 정답 후보로 강하게 선택**한다. 최악 사례에서는 GT G1 대신 G0 근처에 최고 확률을 주었다.
2. **정답 근처가 최고점이어도, 멀리 있는 두 번째 후보까지 평균내면서 출력이 빗나간다.** 비잘림 사례에서는 최고점 오차가 1.22px인데 최종 평균 좌표 오차는 29.48px였다.

따라서 “보정을 크게 못 해서”만이 아니라 **크게 움직여도 되는 코너와 유지해야 하는 코너를 구별하지 못하고, 코너 대응이 불확실할 때 평균 좌표를 내는 문제**다. 반대로 실제 큰 오차를 줄인 사례도 있으므로 큰 보정 자체가 불가능하다는 결론은 아니다.

## 전체 변화

수동 클릭 GT만 사용했다. 150장, 수동 코너 681개가 고정 분모다. 모든 모델에서 검출은 150장, GT와 매칭된 것은 134장/610코너다. 매칭되지 않은 16장/71코너는 동일 실패 처리를 유지했다. PCK10은 원본 640×480 이미지에서 오차가 10px 이내인 비율이며, 아래 평균은 매칭된 610코너에만 해당한다.

| 모델 | 10px 이내 / 681 | PCK10 | 매칭 코너 평균 오차 |
|---|---:|---:|---:|
| R0, 보정 전 | 560 | 82.23% | 5.35px |
| 현재 최종 DIM-only, N2 | 554 | 81.35% | 5.03px |
| 기존 합성 학습 PoseFix | 546 | 80.18% | 5.00px |
| 실사 9장만 추가학습한 PoseFix | 464 | 68.14% | 17.83px |
| 실사 + 합성 replay PoseFix | 527 | 77.39% | 6.24px |
| Replay + 기존 8px 이동 제한, 진단용 | 535 | 78.56% | 5.22px |

Replay는 실사-only의 전체 악화를 상당 부분 줄였지만, 현재 최종 모델보다 안전하지 않았다. 8px 이동 제한도 PCK10을 복구하지 못했다. 이는 기존에 정한 제한의 진단 결과이지, 이번 평가에서 제한값을 탐색한 결과가 아니다.

- 현재 N2 → Replay: 기존에 맞던 코너 **34개가 10px 밖으로 악화**, 틀렸던 코너 **7개가 10px 이내로 개선**. 순감소 27개, −3.96%p.
- 이 34/7개 변화는 모두 `handheld_multiview` 119장에 있다. 리프터 계열 31장은 두 모델 모두 122/124개 정답이며 임계값 통과 여부가 바뀐 코너는 없다. 좌표 자체가 완전히 같다는 뜻은 아니다.
- 잘림 태그가 없는 103장에서도 20개 악화/1개 개선이다. 잘림만으로 설명되지 않는다.
- 중앙값은 4.12→3.97px로 개선되지만 P90은 9.75→11.07px로 악화한다. 일부 큰 실패가 남는 형태다.
- N2와 Replay의 전체 물체 C4 대칭 분기는 **150장 모두 동일**하다. 검출 누락 증가나 평가 대칭 분기 변경 때문에 생긴 수치가 아니다.
- 악화 34개 중 23개는 모델 native index 0/3 수직 코너 쌍이다. 훈련에서 가장 희소한 6/7번만의 문제로 설명할 수 없다.

## 왜 움직였는가: 실제 출력 분포 검사

기존 합성 학습 PoseFix / 실사-only / Replay의 가중치를 고정하여 네 사례에서 각각 한 번씩 순전파했다. 학습 때부터 사용한 R0 bbox 기반 crop과 좌표 복원을 그대로 유지했다. 재계산된 8개 출력 좌표와 저장된 예측의 최대 차이는 **0.000064px 미만**이었다. 따라서 다른 crop이나 새로운 추론 옵션으로 생긴 현상이 아니다.

### A. 다른 코너를 선택한 경우: 009323의 G1

- 수동 정답: (525, 316).
- 기존 합성 PoseFix 최고점: (520.16, 317.13), 오차 4.97px. 최종 평균 좌표 오차 10.17px.
- Replay 최고점: (316.96, 254.60), G1 오차 216.91px. 이 위치는 다른 수동 코너 G0=(320, 254) 근처다.
- Replay의 잘못된 최고점 주변 7×7 heatmap 셀에 확률질량 약 62.1%가 있다. 정답 쪽 후보도 남지만 평균 출력은 (363.46, 268.77), 오차 168.30px가 된다.

이 사례는 평균 대신 최고점 하나를 택해도 해결되지 않는다. 최고점은 오히려 더 틀렸다.

### B. 정답 최고점이 있는데 평균 때문에 어긋난 경우: 006349의 G0

- 수동 정답: (164.74, 225.78).
- 기존 합성 PoseFix와 Replay의 최고점은 모두 (165.95, 225.61), 오차 1.22px다.
- 그러나 Replay에는 약 98px 떨어진 (66.81, 219.00) 후보가 강해졌다. 그 주변 7×7 셀 확률질량은 기존 약 2.9% → Replay 약 28.5%다.
- 정답 최고점 주변 질량은 약 93.9% → 63.7%로 감소했다. 전체 분포의 평균을 내는 출력이 (135.39, 223.04)로 당겨져 오차 29.48px가 된다.

두 7×7 창은 이 사례에서 서로 떨어져 있지만, 일반적으로 peak별 창은 겹칠 수 있으므로 이 수치를 전체 분포의 배타적인 모드 비율로 합산하지 않는다. Heatmap 최고 확률도 검증된 정확도/confidence가 아니다.

### C. 개선 사례도 실제로 후보 분포가 바뀜: 007309의 G4

기존 합성 PoseFix의 최고점 오차 42.90px → Replay 8.46px, 최종 평균 오차 44.59px → 6.85px다. 잘못된 안쪽 후보 대신 바깥 정답 근처에 분포가 집중된 경우다. N2 대비 40.99→6.85px 개선과 일관된다.

## 원인으로 의심되지만 아직 분리 검증하지 않은 것

- **실사 학습 범위가 좁다.** 추가학습에 쓴 9장은 목재 6장, 110×130×11cm 플라스틱 3장이고, 평가의 초록 정사각 110×110×15cm는 0장이다. 실사 9장에 잘 맞춘 것이 이 물체/촬영 분포로 일반화되지 않았을 가능성이 크다. 다만 색, 치수, 형상, 시점 중 무엇이 주원인인지 이 비교만으로 분리할 수 없다. 시점별 학습 커버리지도 별도 검증하지 않았다.
- **일부 crop은 전체 문맥을 잃는다.** 최악 사례 crop은 원본 x≈289.6…571.0만 포함한다. 팔레트는 화면 오른쪽 밖까지 이어지며 R0 코너 두 개도 crop 밖이다. 하지만 실패한 수동 G1/G2 자체는 crop 안에 있으므로 “정답이 crop 밖이라 불가능”한 경우는 아니다. R0 코너가 모두 crop 안인 142장에서도 27개 악화/7개 개선이 있어 crop만으로 설명되지 않는다.
- 현재 N2는 치수를 사용하고 PoseFix는 RGB+초기 점을 사용한다. N2↔PoseFix 차이를 치수 입력 하나의 인과 효과로 해석하면 안 된다. 동일 PoseFix 구조의 기존 합성 모델↔Replay 비교에서도 분포 변화와 악화가 관찰된다.

반복 격자·모서리 유사성이 후보 혼동을 유발했을 가능성은 있지만, 시각적 인상만으로 확정하지 않는다. 단순히 “초록색 때문”, “정사각 대칭 평가 오류 때문”, “카메라 K 오류 때문”이라고 결론낼 근거는 없다.

## 이번 진단이 의미하는 다음 판단

현재 final N2를 유지하고 이 Replay를 수도레이블 생성에 바로 적용하지 않는다. 큰 보정 성공 사례는 있으나, 원래 맞던 코너도 파괴하여 앞서 정한 안전성 조건을 통과하지 못했다.

후속 검증을 한다면 먼저 **멀리 떨어진 후보의 혼재·서로 다른 코너의 중복 선택을 감지하여 기존 점을 유지하는 조건부 보정**이 맞는 질문이다. 단순 argmax 전환이나 이동량 확대만으로는 위 두 실패 유형을 함께 해결하지 못한다. 이 진단에서 임계값을 새로 맞추거나 개선을 주장하지 않았다. 초록 실사 학습을 추가하려면 별도 촬영/그룹 분리 TRAIN 자료가 필요하며, 여기서 본 GREEN150을 몰래 학습으로 돌리면 안 된다.

## 재현·제한

- 수치 재계산: `python -m scripts.research.pallet_posefix_green_audit_v1.inspect audit`
- 고정 GPU 순전파: `python -m scripts.research.pallet_posefix_green_audit_v1.inspect heatmaps` (완료 파일 덮어쓰기 금지; 재실행 시 새 출력 root가 필요).
- 저장 예측 그림: `python -m scripts.research.pallet_posefix_green_audit_v1.render`
- `inspect.py`는 표준 라이브러리 이름과 겹치므로 폴더 안에서 직접 파일 실행하지 말고 저장소 루트에서 위 `-m` 방식을 사용한다.
- 원본 이미지/GT/예측 해시, 고정 최종 릴리스와 기존 실험 바인딩을 검사했다. 그림 표시 오차는 저장 값과 1e-6px 이내로 일치했다.
- GREEN150은 반복 열람한 개발·진단 자료다. 독립적인 최종 확인이나 통계적 일반화 근거로 새롭게 포장하지 않는다.
- 이 코너 그림 네 장은 기전 설명을 위한 선택 사례다. 전체 성능은 150장 집계로 보고하며, 사례 선택을 모델 선택에 사용하지 않았다.
