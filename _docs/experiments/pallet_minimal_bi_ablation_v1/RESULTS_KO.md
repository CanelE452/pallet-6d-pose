모든 측정의 최종 pose·선택 가설·수락/fallback은 정확도 실행과 일치했다. 실제 R1 단독 CLI도 N3 자산/모듈·SubPix를 차단한 채 같은 결과를 냈다. 메인에서는 초기화마다 상태 head/ResNet/Tiny/SAM/B/I/pose 각각238회이며 N3/SubPix/O/T domain/U 표시 계산은 보정 블록에서0회다. 초기 N3 출력은 기존 캐시다. [실제 계수](MAIN_ACTUAL_CALL_COUNTS.json), [전체 측정](TIMING.json), [비용·실패 이력·보존 범위](COST_AND_VALIDATION_KO.md)를 함께 남겼다.

입력 계약→20개 실제 관측/pose 동등성→선택10장0/7/10/10 회귀→전체952행 봉인·점수→독립1,800개 통계 검사→384개 조건부 진단·독립12,860개 검사→실제 비용·단독 CLI→32개 과정 그림 검산까지 완료했다. 새 fit/optimizer update·학습 seed·데이터·GT 수정은0이다. 코드/모델/입력 SHA와 실제 명령은 [재현 문서](REPRODUCE.md), [프로토콜](PROTOCOL.json), [모델·소스 manifest](MODEL_AND_SOURCE_MANIFEST.json)에 있다.

[실제 과정 갤러리](gallery/GALLERY_KO.md)는 R1 회복·R1 손상·N1만 회복·양쪽 실패 부류에서 고정 ID 첫 사례를 썼다. 원예측·실제 관측·최종 투영을 다른 기호로 표시했으며 정답 선이나 만들어낸 중간 pose를 넣지 않았다. 원본 이미지4개는 기존 공개 inventory에서 같은 바이트의 공개 근거를 확인했다. 전체 관측 배열·마스크·solver 후보·모든 실행 시도는 별도 로컬 ARTIFACT_ROOT에 보존했다.

키포인트 불확실성을 자세 추정에 반영한다는 문헌적 동기는 [PVNet 원 논문](https://openaccess.thecvf.com/content_CVPR_2019/html/Peng_PVNet_Pixel-Wise_Voting_Network_for_6DoF_Pose_Estimation_CVPR_2019_paper.html)과 관련되지만 이번 코드는 PVNet 재현이 아니다. 반복 선택에 노출된 자료의 낙관 편향 제한은 [Cawley와 Talbot](https://www.jmlr.org/papers/v11/cawley10a.html)의 논의에 따라 유지한다. 새 예측 봉인이나 bootstrap만으로 과거 방법 선택 편향을 없앴다고 주장하지 않는다.

## 여섯 질문에 대한 최종 답

1. **RAW에 새 보정은 도움이 됐다.** 현재192장에서21회복·5손상, 공동 성공66→82, +8.33%p다. RAW 직접 연결 모듈은 독립 실행 가능한 연구 후보로 남긴다.
2. **N3/SubPix 묶음은 유지할 후보로 권고한다.** 같은 B/I 후단에서N1은108장/R1은82장이다. R1−N1의95% 군집 CI는−33.76~+1.50%p로 큰 손실 가능성을 포함한다. 제거의 안전성·동등성·비열등성을 입증하지 못했고 두 성분의 개별 필요성도 분리하지 않았다.
3. **사용하지 않는 후단 계산을 제거했다.** U 표시 모델/영역, O/T domain 생성·저장, V33 C/과거 bank/보고서 의존을 핵심에서 분리했다. 기존 상태 ResNet·Tiny·MobileSAM·B/I 공분산/선 지지와 동일 solver·fallback은 남는다. 기존 파일은 삭제하지 않았다.
4. **악화는 실제 수락된 재계산에서 발생했다.** R1 손상5/N1 손상14 모두 제약 수락이었다. S가 같은46개 전환에서도 초기 좌표/F·프롬프트/SAM·측정/자세 분기가 달랐다. 가림 판정 한 단계의 탓으로 단정하지 않는다.
5. **좌표 측정의 조건부 이득을 확인했다.** xy만 복귀하면 RAW82→68/N3 108→105였다. 전체 이득을 상태 제외·공분산·solver·좌표의 순수 인과 기여로 분해하는 것은 미확정이다. 좌표 보정이 언제나 이롭다는 결론도 내리지 않는다.
6. **운영 채택·논문 수정 전에 필요한 최소 확인은 독립 촬영 군집에서 고정 경로의 손상 재현 여부다.** 현재의 반복 개발192장과 CAL46만으로 대체를 확정하지 않는다. 특히 accepted=True 손상이 재현되는지 확인해야 한다. 이번에는 새 학습/게이트/데이터 탐색을 시작하지 않았고 운영 e·main·논문은 변경하지 않았다.
