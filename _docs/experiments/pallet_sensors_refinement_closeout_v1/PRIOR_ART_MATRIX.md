# Related methods and comparison scope

Search date: 2026-09-14. This is a targeted primary-source review, not an exhaustive systematic review. No external method has been measured on DEV319 in this experiment. Numbers from different datasets are not subtracted from our results.

| Method | Input / output | Learning / initialization | Extra information | Implementation and comparison status |
|---|---|---|---|---|
| Fixed P | R0 P3/P4, predicted box and9 points → refined8 corners | Synthetic residual targets, frozen R0; 18,962 added parameters | Known dimensions only in downstream PnP | Existing3 seeds frozen; development comparison |
| D | Same221 locations×32 samples×2 scales and same point context → direct2D residual | Fresh shared modules and regression head, same synthetic batches; 19,450 parameters | Same downstream assumptions as P | Structural ablation; not a named prior reproduction |
| PoseFix, CVPR2019 | RGB crop+input human pose → heatmaps and coordinates | Human error synthesis; ImageNet backbone; human pose datasets | Own RGB backbone rather than detector internal features | Closest image-conditioned post-estimation comparator; pallet9 adapter tested, official network/runtime integration blocked |
| CRT-6D, WACV2023 | RGB crop, projected object-surface features and evolving pose →6D | Object pose benchmark training | Surface3D keypoints/object geometry and identity | Relevant feature-sampling refinement; official repo has no executable model |
| Integral Regression, ECCV2018 | Heatmap distributions → expected coordinates | Human pose coordinate supervision | Dataset-dependent2D/3D pose | Establishes prior art for expectation readout; not a full pallet refiner baseline |
| PoseRefiner, CVPRW2018 | Image and initial human pose → corrected pose | Human hard-pose augmentation | Separate image-conditioned network | Close earlier refinement concept; formal paper reviewed, implementation availability not established |
| Knitt et al.,2022 | RGB → Euro-pallet pose using DOPE | Synthetic pallet imagery | Public pallet model/dataset; geometry-based pose estimation | Direct application prior; synthetic RGB pallet pose is not new |
| Miura et al.,VISAPP2026 | RGB and predicted metric depth/floor information → pallet6D | Additional depth model and fusion network | Depth-Anything-V2 predictions, floor constraints, detector | Recent application comparator; different evidence/backbone budget; not implemented here |

[PoseFix paper](https://arxiv.org/abs/1812.03595), [official code](https://github.com/mks0601/PoseFix_RELEASE): image-conditioned pose refinement and the heatmap-to-coordinate pipeline precede this work. Actual source commit `5556364bb0f43b0743a5fcd820de48f34b3d4360` is MIT licensed. `main/config.py` defaults to ResNet152,384×288, Adam,140 epochs; the code imports `tensorflow.contrib`. Our8-source-image affine/heatmap tests do not run that network. The planned pallet adaptation replaces human noise assumptions with frozen source-train R0 predictions and keeps center8 fixed. Pretrained human PoseFix weights are linked in the README but not downloaded or used. See `PREDECLARED_PRIOR_BASELINE_PROTOCOL.json` for additional-supervision and resource limitations.

[CRT-6D paper](https://arxiv.org/abs/2210.11718), [official repository](https://github.com/PedroCastro/CRT-6D): sparse object-surface features and cascaded pose refinement are relevant to P's feature reuse. At inspected commit `a38699b499e9dbc5c1ae8845a9ad7fb54561d08f`, the repository contains only README and GPL-3.0 LICENSE. Its README says the implementation is to be released. Bounding-box dimensions alone do not supply its surface model contract. No substitute transformer is called CRT-6D here.

[Integral Human Pose Regression](https://arxiv.org/abs/1711.08229), [official PyTorch repository](https://github.com/JimmySuen/integral-human-pose): differentiable expectation links heatmaps and coordinate regression. The official repository is MIT licensed and distinguishes its PyTorch implementation from the original internal MXNet implementation. Our expected displacement is an application of this established principle. Neither expectation itself nor the contrast with direct regression is claimed as an invention.

[Learning to Refine Human Pose Estimation](https://openaccess.thecvf.com/content_cvpr_2018_workshops/w6/html/Fieraru_Learning_to_Refine_CVPR_2018_paper.html) motivates image-plus-pose postprocessing and hard-pose augmentation. Its role is conceptual prior, not an experimentally reproduced row. Source commit, numerical optimizer schedule, weights and runtime are NOT_VERIFIED; no fabricated entries fill those fields.

[Knitt et al.](https://proc.logistics-journal.de/article/view/1038) already trained DOPE with synthetic pallet data and evaluated RGB Euro-pallet pose. This precludes a first-ever synthetic RGB pallet claim. P's possible contribution must instead rest on measured local correction, resource use, preservation contracts and independent validation.

[Miura et al.,2026](https://www.scitepress.org/publishedPapers/2026/146268/pdf/index.html) uses monocular metric depth, ground-plane information and RGB/depth feature fusion. This is a relevant recent pallet system and adds model-derived evidence beyond P's frozen detector features. No numerical head-to-head claim follows from comparing its published table with DEV319. Its cited Kai et al.2025 front-face-shot system was identified, but the primary full text could not be retrieved in this run, so detailed claims about that method remain unchecked.

The [IEEE Sensors Journal scope](https://ieee-sensors.org/ieee-sensors-journal/) and [reviewer guide](https://ieee-sensors.org/wp-content/uploads/2025/03/Guide-for-SJ-Reviewers.docx.pdf) require relevance and research contribution. They do not provide an automatic acceptance criterion for this study. A known technique's measured system contribution needs evidence; a new module name does not establish novelty. The manuscript must explicitly explain its sensing/measurement problem and remaining comparison gaps.

Official sources were inspected without installing dependencies into the active YOLO environment. Raw checkouts are ignored external research inputs; newly authored adapters do not redistribute those networks. Repository source/licensing receipts are in `PRIOR_SOURCE_RECEIPTS.json`.
