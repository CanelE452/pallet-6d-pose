# 합성 선택기 선행 검사 — 학습 전 중단

## 실행 결과

고정된 합성 512장 학습 후보 + 촬영 시나리오가 분리된 128장 검증 후보에
원본/고정 RGB 열화 변형을 적용했다. 총 1,280개 사례의 R0 6가지 입력
변환 및 native/번호 재배정 후보 생성은 정상 완료했다.
GPU 추론 본체 약 176초, 온도 52–54°C. RustDesk 유지, 재부팅/드라이버
변경/기존 모델 변경 없이 실행했다.

번호를 재배정한 후보가 최선이고 평균 오차를 예측 상자 대각선의
1%보다 많이 줄이는 원본 이미지 수:

| 분할 | 관측 | 사전 최소 조건 | 판정 |
|---|---:|---:|---|
| 학습 | 16 | 10 | 통과 |
| 검증 | 2 | 3 | 미달 |

따라서 고정 protocol의 identity coverage gate는 실패했다.
실행 후 최소 조건을 2개로 낮추지 않는다. RandomForest를 학습하지 않고
`FIT_STOP.json`으로 중단을 기록했다. 실사194장의 선택·채점도 하지 않았다.

이 결과는 **선택기 성능이 나쁘다는 실험 결과가 아니다.** 선택기 자체를
학습하지 않았으므로 성능은 모른다. 현재 고정 합성 검증 표본에 필요한
번호 혼동 사례가 부족해 이 설정의 검증을 진행하지 않은 것이다.
합성 접근 일반이나 다른 아키텍처의 불가능성을 입증하지도 않는다.

## 근거

- `PROTOCOL.json`: 사전 고정 기준, 데이터 및 코드 해시
- `SOURCE_COMPLETE.json`: 1,280개 사례와 split별 coverage
- `FIT_STOP.json`: 학습 미실행 및 중단 사유
- 데이터: `data/pallet/results/pallet_type_selftrain_v1/large_corner_recovery_v1/source_selector/cases/`
- 기존 코드 회귀 검사 7개 및 선택/기권 규칙 검사 4개 통과.
  이는 실제 복구 성능을 입증한 검사가 아니다.

## 현재 실사 경로

`real_support_review_v2/EXISTING_PROVENANCE_AUDIT.json`에 따르면,
제안 학습/검증 7개 세션에서 발견한 legacy 파일은 45개다.
첫8점 기준 저장된 nonnull 좌표 351개, null 9개지만 코너별 source 기록은
없다. 정수 좌표 여부나 낮은 재투영 오차로 직접 클릭한 정답이라고
추정하지 않았다. 이 감사는 저장소 전체의 어노테이션 품질 판정이 아니다.

실사 학습 제안20장·검증 제안10장은 계속 **미확인 후보** 상태다.
사용자가 보이는 코너를 직접 확인·수정할 수 있는지 응답과 검증된
정답이 필요하다. 평가 세션을 학습으로 옮기거나 미확인 좌표를 정답으로
승격하지 않는다. 큰 코너 복구 목표는 아직 미완료다.
