# DINO 중간층 + 마지막층: 큰 코너 복구 검증

결론: 고정 5,000스텝 실험과 재현 검증은 완료했지만 최상위 목표는 미완료다. 최종 모델에 적용하지 않는다. 새 수동 어노테이션·태그·깊이·CAD·필터는 추가하지 않았다.

| 일반 PLASTIC 전체194장 | R0 | 마지막층 SYN5k | 중간층+마지막층 SYN5k |
|---|---:|---:|---:|
| PCK20 (%) | 77.86 | 71.32 | 73.76 |
| 관측 코너 오차 중앙값 (px) | 7.51 | 7.19 | 6.66 |
| 관측 코너 오차 P90 (px) | 43.64 | 83.65 | 85.87 |

중앙값과 일부 정상 코너 보존은 이전 image-only 실험보다 좋아졌지만 R0 대비 tail과 PCK20은 악화됐다. 정상 코너 손상은 8.81%로 채택 기준을 넘는다. 평균/중앙값 개선만을 큰 오류 해결로 보고하지 않는다. PCK는 full-penalty 1,513코너 분모이며 복구/손상은 매칭된 1,459코너에서 집계한다.

실제 큰 위치 복구 3개:

- `eval_pallet07:1778652125245035520` G7: 53.14 → 7.86px.
- `eval_pallet07:1778652126319943168` G7: 75.82 → 2.33px.
- 원래 의자/콘 사진 `eval_pallet07:1778652166837872128` G2: 동일 정답 역할 기준 286.44 → 2.62px. 단, 기존 어떤 점에서의 최근접 거리는 40.87px이므로 이를 286px의 새로운 공간 이동 복구로 표현하면 안 된다.

원래 요청 사진의 프레임 평균 오차는 264.90 → 178.26px이다. G2는 맞췄지만 다른 채널은 콘 등 잘못된 곳을 가리키며 전체 모양은 여전히 잘못됐다. 첫 복구 사례의 평균 오차는 27.21 → 9.62px로 개선됐으나, 이런 사례만 선택해 전체 모델 성공으로 확대 해석하지 않는다.

역할을 무시하고 새 출력의 어떤 점이라도 정답 10px 안에 존재하는 경우도 큰 위치 오류 64개 중 4개뿐이다. 이는 GT를 이용한 사후 후보 존재 진단이지 적용 가능한 선택기의 성능이 아니다.

## 조건과 검증

기존 frozen DINOv2의 마지막12번째 층은 그대로 쓰고 6번째 층(normalized block index5)을 추가했다. 384→64 projection 경로를 거쳐 기존 projected feature에 더한다. 추가 경로의 초기 출력은 정확히0, 원래 파라미터 초기값도 같다. 좌표 힌트는 사용하지 않는다. 정보와 파라미터 수가 함께 늘어 순수 layer 효과만의 실험은 아니다.

같은 합성 train8,192장, held64, 표본 순서, GT/지원mask, crop, loss, decoder, seed와 AdamW 설정으로 처음부터5,000스텝 학습했다. 실사/수도레이블 loss는 없다. 중간 checkpoint 선택 없이 마지막만 평가했다. 학습 약240초, 중간 feature 준비 약554초. GPU/드라이버/최종 모델 변경 없음.

- 회귀검사34개 통과.
- 최적화한6번째 층 추출은 공식 `get_intermediate_layers`의 FP32 token과 정확히 일치했다. 기존 마지막층 FP16 cache도 재현했다.
- source16장의 중간/마지막 feature와 공식 API를 재대조했다. 전체8,256장 cache·target·mask와 source 분리를 확인했다.
- 전체194장 GPU 출력을 최대 차이0px로 재현했다. GT 없는 추론 경로, 좌표 힌트 비의존성, box/confidence/center 보존을 검사했다.
- source held64 PCK10은78.04%, P90은57.25px였다. 원래 R0 보존 기준90.20%/9.50px를 못 넘었다.
- 학습 후 중간 경로를 끄면 source PCK10이51.96%로 떨어졌다. 새 경로는 실제 사용되지만 충분한 일반화/큰 오류 복구를 달성하지는 못했다. 이 co-trained 경로 제거를 독립 학습 ablation으로 주장하지 않는다.

근거: `PROTOCOL.json`, `EXTRACTOR_PREFLIGHT.json`, `FIT_SYN.json`, `RESULTS.json`, `SOURCE_MID_ABLATION.json`, `COMPLETION_AUDIT.json`.

전체194장 비교: `outputs/pallet_type_selftrain_v1/selftrain_recovery_v1/dino_mid_feature/index.html`. `000.jpg`와 `001.jpg`를 직접 확인했다. GT는 점수·사후 진단·표시에만 사용했고 학습/선택에 넣지 않았다. 반복 DEV이며 독립 확증이 아니다.

## 중요한 별도 발견

현재 source train8,192장에는 실제 큰 위치 오류가 있는 이미지가31장(77코너)이고, held64에는0장이었다. 기존 전체 source에는 train196장(460코너), held13장(36코너)이 있다. 두 독립 좌표 계산과4개 회귀검사로 확인했다. 자세한 수치·제약은 `SOURCE_DIFFICULTY_KO.md`를 참고한다.

이것이 실패의 유일한 원인이라는 뜻은 아니다. 그러나 feature 변형을 반복하기 전에, 이미 있는 정답의 큰 오류 사례 노출과 검증 커버리지를 통제해 볼 근거다. 새 어노테이션/태그를 요구하는 결론이 아니다. 아직 그 재균형 학습은 수행하지 않았으며, 현재 실험의 풀·정답·필터는 바꾸지 않았다.
