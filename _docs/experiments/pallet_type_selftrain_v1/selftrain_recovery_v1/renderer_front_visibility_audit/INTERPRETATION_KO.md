# 기존 합성 레이블의 앞면 선택 규칙 확인

2026-09-20. 추가 수동 어노테이션·태그·실사 깊이·새 CAD 작업 없이 수행한
읽기 전용 감사다. 모델 학습·예측 보정·필터 적용 결과가 아니다.
큰 코너 오류 복구 목표는 아직 미완료다.

## 확인한 사실

이전 `camera_facing_contract_audit`는 과거 `compute_perm_v4`의 면적 규칙이
G38 완전 감독 샘플의 약46%에만 일치하지만 P0/TEX에서는 약99.9%에
일치한다는 사실을 확인했다. 그 숫자만으로 생성 레이블이 잘못됐거나
학습 소스 간 정답이 모순된다고 결론내릴 수 없었다.

이번에는 기존 합성60,000장의 원본 renderer annotation을 모두 읽었다.
세계 좌표 cuboid와 카메라 위치로 각 측면의 바깥 법선을 계산했다.
원본 projected_cuboid에 기존 reflect padding100px를 적용한 좌표와
학습 manifest의 감독 좌표 사이 최대 차이는0.000687px 미만이다.
이는 좌표 전달의 일치이며, 눈에 보이는 팔레트와 물리적 정답의 정확성을
독립적으로 입증하는 검사는 아니다.

| 소스 | 전체 | 물체 중심 기준 앞면 최대 일치 | 카메라 고도 중앙값 | 기존 면적 규칙 일치 / 완전 감독 |
|---|---:|---:|---:|---:|
| G38 |40,000|40,000|36.72°|17,947 / 38,984|
| P0 |10,000|10,000|6.06°|9,188 / 9,201|
| TEX |10,000|10,000|5.94°|9,152 / 9,163|

여기서 카메라 고도는 cuboid 중심→카메라 벡터와 물체의 윗방향으로 계산한
각도다. 카메라 optical-axis pitch와 동일한 값이라고 주장하지 않는다.

각 면의 바깥 단위 법선을 n_f, 물체 중심을 o, 카메라 위치를 c라 할 때,
`n_f · (c-o)/||c-o||`가 최대인 측면이 저장된0–3 앞면과 일치하는지를
검사했다. **60,000 / 60,000에서 일치했다.** 이것은 앞면 선택에 대한
증거이며, 전체8개 점의 좌우 순서·실사 라벨 규칙·모든 메타데이터의
정확성을 검증했다는 뜻은 아니다. 생성기 구현 자체를 확보한 것도 아니다.

처음에는 `c-o` 대신 각 면 중심→카메라 벡터를 사용했다. 이때799장의
최대 면이 달랐다. 이 불일치를 확인한 뒤 물체 중심 가설을 추가 검사했고,
799장 모두를 포함한 전체60,000장에서 일치했다. 이 추가 가설은 사전
등록된 실험으로 위장하지 않고 `CENTER_FOLLOWUP_PROTOCOL.json`에 기록했다.
두 계산은 서로 다른 양이므로799장을 라벨 오류로 분류하지 않는다.

G38에서 과거 면적 규칙 일치율은 고도0–15°에서91.81%,15–30°에서90.97%,
30–45°에서41.83%,45–60°에서5.20%,60–90°에서0%였다.
P0/TEX는 대부분 낮은 고도다. 따라서 소스별 전체 일치율 차이는
시점 분포와 강하게 연관된다. 이것만으로 분포가 유일한 원인이라고
단정하거나, 실제 모델 오류의 인과적 원인이라고 주장하지 않는다.

## 다음 행동에 반영할 결정

- 과거 면적 규칙으로 합성/실사 정답이나 예측을 자동 재번호 지정하지 않는다.
- 소스 간 앞면 레이블 충돌을 원인으로 단정하거나 새 수동 정답을 요구하지 않는다.
- 앞면/코너 역할을 추가로 학습할 경우 이미 있는 합성 카메라·cuboid 정보가
  감독 신호로 사용 가능한지 먼저 합성 분리셋에서 검증할 수 있다.
  새 실사 어노테이션이나 태그가 있어야만 시작할 수 있는 작업은 아니다.
- 다만 이번 원본 메타데이터는 실사 추론에서 제공되는 정보가 아니다.
  합성에서의100% 일치를 실사 보정기 성능으로 보고하거나 실사 GT pose를
  추론 입력에 섞지 않는다. 아직 해당 새 학습기를 실행하지 않았다.
- 역할 번호가 틀린 오류와 어떤 기존 점도 정답 근처에 없는 위치 오류는
  계속 구분한다. 앞면 선택 검증만으로 후자의 복구를 주장하지 않는다.

## 보존 및 검증

원본 레이블·모델·수도레이블·split·평가 집합을 수정하지 않았다.
실사 GT를 이번 renderer 감사에서 읽지 않았다. 새로운 geometry/X/shape
필터도 적용하지 않았다. CPU 검사로 GPU 학습은 실행하지 않았다.

관련8개 단위 검사를 통과했다. 두 번째 계산에서 원본60,000개 파일/zip
member SHA256을 다시 확인하고, 면 대각선으로 법선을 독립 재계산했다.
첫 면 법선 계산과 cosine 최대 차이는0.00000394 미만이었다.
기존 프로토콜의 코드/입력 hash도 확인했다.

첫 실행은 원본별 `ROWS.json`을 모두 저장한 뒤 NumPy int64의 요약 JSON
직렬화에서 실패했다. 원본 검사 결과는 손실되지 않았다. 새 finalizer는
저장된 행을 다시 읽어 Python scalar로 요약하고 전체 직렬화를 미리
검사한 뒤 `RESULTS.json`을 생성했다. 실패한 부분 파일은
`RESULTS_SERIALIZATION_FAILED.partial`로 보존했다. 완료 전 실패를 숨기지 않는다.

결과: `RESULTS.json`, `COMPLETION_AUDIT.json`.
원본별 감사: RAW의 `ROWS.json`, `CENTER_ROWS.json`.
재현: `renderer_front_visibility_audit` 후 `finalize_renderer_front_audit`.
첫 모듈의 보존된 버전은 요약 직렬화 실패를 포함하므로 두 번째 모듈까지
실행해야 한다. 완료 결과가 있는 디렉터리에 첫 모듈을 다시 실행하지 않는다.
