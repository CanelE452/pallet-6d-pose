# 기존 물체 치수를 추가한 코너 대응 학습 — 미채택

2026-09-20. 추가 어노테이션·AprilTag·깊이·새 CAD 없이 GPU 실험을 완료했다.
기존 모델, 원본 레이블, 데이터 split과 수도레이블 membership은 보존했다.

## 질문과 통제

이전 선형 후보 판단기는 합성마다 다른 치수를 받지 않았다. 학습594장의
W/D 비율은 약0.639~1.065였다. 치수 누락이 실사 대응 판단의 병목인지
확인하기 위해 기존 고정 물체 치수만 입력에 추가했다.
합성은 기존 정정 DIMENSION_SIDECAR, 실사 PLASTIC은 기존 registry의
W,D,H=1.10,1.30,0.11m다. 카메라 시점에 따라 치수를 뒤집거나 GT pose를 쓰지 않았다.

입력은 기존 특징 차이 d와 d×log(W/D), d×log(H/√WD)다.
C2 불변성과 후보 교환 시 부호 반전을 유지하며, 두 후보에 같은 치수를 쓴다.
합성 학습594장, 보류1,468장, 기존 실사 수도레이블217장, 후보 점, 타깃,
optimizer, 규제 후보 및 합성 calibration 기준은 이전 선형 실험과 같다.
규제값은 source TRAIN 3-fold만으로 선택했다. 학습 후 실사 GT 채점 전에
두 모델·임계값·전체194장 예측을 고정했다. 실사 threshold sweep은 하지 않았다.

## 결과

| 실사194 | PCK20 | 중앙 px | P90 px | >20→≤10 복구 | >100→≤10 복구 | <5→>10 손상 |
|---|---:|---:|---:|---:|---:|---:|
| R0 |77.86%|7.509|43.637|0/281|0/58|0/511|
| 치수+SYN |75.35%|7.735|60.313|8/281|8/58|15/511|
| 치수+MIX |74.82%|7.801|66.748|2/281|2/58|15/511|

SYN은 합성만, MIX는 합성+기존 실사 수도레이블이다. 두 모델 모두 선택된
규제값1.0이며, source 임계값은 각각0.99/0.95다. 바뀐 이미지는9/8장이다.
양쪽 모두 실사 정상 코너 손상률 약2.94%로 사전1% 기준을 초과했다.
기존 저양각 제외159장에서도 양쪽 PCK20은78.02%로 R0의80.45%보다 낮다.
의자·콘 예시도264.90px 그대로다. 두 모델 모두 채택하지 않았다.

치수가 없는 직전 SYN은 >100px 코너21개를 복구했으나 정상15개를 손상했다.
치수를 넣은 이번 SYN은 해당 복구가8개로 줄었고 손상은15개 그대로다.
이 통제 실험은 '이 특징에 치수 비율을 곱하면 문제가 해결된다'는 가설을
지지하지 않는다. 치수 조건화 일반이나 모든 무레이블 방법의 불가능성을
보여주는 결과는 아니다. 이 결과를 보고 실사에 맞게 임계값을 낮추지 않았다.

## 해석상 중요한 구분

- 같은8개 물리적 점의 역할 번호만 바꾼다. 좌표를 새로운 꼭짓점 위치로
  옮기는 능력을 입증한 실험이 아니다. 공식 C2 평가 정의는 그대로다.
- SYN의 합성 자연 오류 복구는0/264, 인위적90도 번호 교란까지 포함하면
  5,415/11,423이었다. 합성 calibration 통과를 실사 자연 오류 복구의 증거로
  쓰지 않는다. MIX의 자연 복구는8/264다.
- 반복 DEV 평가이고 역사적 Replay 수동 학습3장이194장과 겹친다.
  독립 확인을 주장하지 않는다.
- 새 정답을 만들지 않고 실험할 수는 있지만, 잘못된 수도레이블이
  정답 방향을 제공하지 않는다는 병목은 이 실험으로 해소되지 않았다.

이번 실험은 끝났지만 '크게 틀린 코너를 안전하게 복구'하는 목표는 미완료다.
기존 최종 모델에 적용하거나 새 수도레이블을 생성하지 않았다.

재현: `python -m scripts.research.pallet_type_selftrain_v1.identity_rank_dimensions`
의 `prepare`, `fit SYN`, `fit MIX`, `infer`, `report` 순서.
회귀/보존 검사: `python -m scripts.research.pallet_type_selftrain_v1.audit_identity_rank_dimensions`.
정확한 수치와 출력 hash는 `RESULTS.json`, `OUTPUTS_LOCK.json`,
`COMPLETION_AUDIT.json`에 보존했다.
