# 큰 코너 위치 복구: 전체 평균 대신 확률 봉우리 읽기

2026-09-20. 사용자 목표는 큰 오류를 실제로 안전하게 복구하는 것이다.
이 실험은 완료했지만 그 목표는 아직 달성하지 못했다. 새 어노테이션·태그·
깊이·CAD·학습은0이며, 기존 모델과 수도레이블을 보존했다.

## 무엇을 확인했나

기존 PoseFix는 국소 이동 한도에 묶인 모델이 아니라384×288 crop 전체에서
96×72 확률 지도를 내는 모델이다. 기존 출력은 이 분포 전체의 기댓값이다.
분포가 여러 위치에 나뉘면 봉우리 사이로 좌표가 나올 수 있으므로,
가장 큰 logit 주변 고정5×5셀에서만 조건부 평균을 구하는 MODE를 비교했다.
창 크기·온도·신뢰도 기준을 실사 GT로 고르거나 조절하지 않았다.

기존 Replay(BASE)와 기존 수도레이블 denoise 학습 모델(DENOISE), 두 가중치를
동결했다. 같은 입력과 같은 logits에서 MEAN/MODE를 각각 읽었다.
먼저 자연 합성 보류256장의 결과를 고정하고, 실사194장 모든 예측을 고정한
뒤에만 기존 평가 GT로 채점했다. 새로운 거절 필터나 학습기는 없다.

100px 이상58코너는 모든 모델에서10px 이내로 복구한 사례0이다.
MODE 두 모델은 정상 손상1% 기준에 실패했고, source screen도 실패했다.
기존 의자·콘 사례는 R0 평균264.90px에서 BASE_MODE269.65px,
DENOISE_MODE269.06px로 여전히 나빴다. 따라서 둘 다 적용하지 않았다.
합성 보류 자연 오류64개에서 MEAN은3개, MODE는2개만 복구했다.
합성 정상 코너 손상도 BASE39→45개, DENOISE42→52개로 증가했다.

## 복구를 과장하지 않기 위한 위치 집합 분해

BASE_MODE에서 실제 좌표가 움직여 평가 오차가 줄어든 사례는 다음과 같다.

- `plastic_day_01:020954`, G0:59.42→1.85px, G3:60.24→2.58px.
- `plastic_day_01:021348`, G3:56.76→2.33px.

이3개는 코너 번호나 C2 평가 분기를 바꾸지는 않았지만, **R0의 다른 native
점이 이미 평가 참조점10px 안에 있었던 경우**다. 따라서 '이전에는 못 찾던
물리적 꼭짓점 위치3개를 새로 발견했다'고 주장하지 않는다. 같은 사진의
다른 코너도 여전히 크게 틀려 사진 전체가 복구된 것이 아니다.

더 엄격하게 R0의 어떤 점도 참조점10px 안에 없었던 경우만 분리하면,
>40px 오류95개 중 BASE_MODE는0개, DENOISE_MODE는1개를 복구했다.
그1개는 `eval_pallet09:1778653659065885952`, G1의48.53→5.98px다.
이 사진도 전체 평균은77.05→73.81px로 여전히 나쁘다. 다른 점과의 거리가
가깝다는 분류 자체가 대응 오류의 확정 진단은 아니다. 투영상 서로 다른
코너가 가까울 수 있으므로 공간 지지의 유무를 구분하는 진단으로만 쓴다.

## 남은 확률 후보의 진단: 달성한 복구 수가 아님

고정 logits에서 GT 없이 상위5개 봉우리를 생성했다. 봉우리 억제 반경5셀,
국소 평균 반경2셀을 사전에 코드로 고정하고 후보를 모두 저장한 뒤에만
GT와의 거리를 봤다. 정답에 가장 가까운 후보를 고른 수는 **oracle 상한 진단**이며
실제 모델 선택, 성능, 새 수도레이블 또는 추가 학습으로 사용하지 않았다.

>100px의58코너 중10px 안 후보가 있는 수는 BASE28개/DENOISE37개다.
하지만 이 중 R0의 다른 점이 이미 참조점 근처에 있던 경우가23개/27개다.
R0가 어떤 점으로도 위치를 못 찾던23코너에서는5개/10개만 후보가 있다.
나머지는 이5개 후보 안에도 참조점 근처 후보가 없었다.

또한 DENOISE의 >100px oracle 정답 근처 후보의 국소 확률 질량 중앙값은
약0.000181(0.0181%)로 아주 낮다. 후보가 존재한다는 것과 모델이 그것을
신뢰성 있게 선택한다는 것은 다르다. 낮은 확률 봉우리를 억지로 채택하면
해결된다는 결론은 내릴 수 없다.

## 이번 결과가 바꾸는 다음 판단

전체 평균 읽기가 일부 오류를 키우는 경우는 확인했다. 그러나 가장 큰
오류의 주원인을 이 readout만으로 설명하거나 해결할 수는 없다.
다음 작업에서는 (1) 이미 맞는 위치를 다른 번호로 부르는 대응 문제와
(2) 기존 점 집합·주요 확률 후보에도 맞는 위치가 없는 공간 탐색 문제를
별도로 측정해야 한다. 같은194장에서 임계값만 반복 조정하는 것은 하지 않는다.
추가 어노테이션이나 태그를 필수조건으로 바꾸지 않는다.

- `CANDIDATE_HEADROOM.json`: 별도 oracle 진단. 실제 결과와 혼용 금지.
- `SPATIAL_DECOMPOSITION.json`: 기존 위치 집합과 새 공간 지지 구분.
