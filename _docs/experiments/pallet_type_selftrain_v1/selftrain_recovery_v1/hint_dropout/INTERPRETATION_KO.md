# 입력 점 힌트를 가린 학습: 큰 위치 오류 복구 통제 실험

2026-09-20. 새 수동 레이블·AprilTag·깊이·CAD0. 기존 수도레이블과 합성 정답만
사용했다. 학습/평가/감사는 완료했지만 큰 코너 오류를 안전하게 복구하는
사용자 목표는 미완료다. 기존 최종 모델과 수도레이블에는 적용하지 않았다.

## 실험

기존 DENOISE 모델의300step 학습과 같은 초기 Replay 가중치, 실사217장,
실사8+합성8/micro2, 샘플 순서, 입력 점 교란, loss, TFAdam1e-4, seed1,
BN 통계 동결을 유지했다. 새 MASKED 모델에서는 각 학습 이미지의50% 확률로
감독 가능한 코너 하나의 **입력 Gaussian 힌트만** 끈다. 점 좌표·RGB·정답 좌표·
정답 감독 마스크는 바꾸지 않는다. 그 점을 loss에서 제외하는 방식이 아니다.

실사2,400회/합성2,400회 노출 중 실제 숨긴 힌트는 각각1,213회/1,204회다.
모델 구조나 파라미터 수를 바꾸지 않고 기존300step에 맞춰 학습했다.
GPU 학습시간은 약195초, 관측된 학습 온도는 최대71°C였다.

두 모델에 각각 두 추론법을 사전에 고정했다.

- NATIVE: 기존처럼 모든 점 힌트를 주고 전체 heatmap 기댓값을 읽는다.
- BLIND: 출력할 점 자신의 힌트만 뺀 상태로 한 번씩 추론하고,8개의 점을
  모은다. 중심점·box·score·비선택 검출은 보존한다. **PnP LOO 필터가 아니다.**
  프레임이나 코너를 거절하지 않는다. GT 선택·mode decoder도 사용하지 않는다.

먼저 합성 보류64장을 비교했고, 실사194장의 네 후보 예측을 모두 고정한 뒤
GT를 읽어 채점했다. 실사 GT로 모델·임계값·학습량을 선택하지 않았다.

## 공간 복구와 대응 변화 구분

MASKED_BLIND의 >40px 복구4개 중3개는 R0의 어떤 점도 해당 참조점10px 안에
없었던 사례다. 모두 기존 C2 평가 분기0을 유지했다.

- `eval_pallet07:1778652127361815808`, G7:50.92→3.65px.
- `eval_pallet09:1778653659065885952`, G1:48.53→6.06px, G2:50.63→4.78px.

나머지1개는 R0가 다른 번호로 이미 근처에 점을 찍었던 경우다.
그러나 이3개를 복구하면서 다른 정상 코너59개가 손상됐다. 성공 사례만
선택해서 보여 주거나, 복구된 점만 GT로 골라 실제 출력에 적용하지 않는다.
원래 사용자의 의자·콘 사진 평균은264.90px에서 MASKED_BLIND244.49px로
조금 줄었지만 여전히 크게 틀렸다. 그 사진을 해결했다고 주장하지 않는다.

## 비용과 결론

BLIND는8회 forward가 필요하다. 이번 네트워크/전송/decode 관측시간은
NATIVE 약15~16ms, BLIND 약98~99ms/장이다. disk/crop/R0 detector는 제외한
진단용 관측이며 전체 시스템 지연이나 정식 벤치마크 수치가 아니다.
느려진 만큼 큰 오류를 안전하게 복구하지 못했으므로 적용할 근거가 없다.

이 결과는 '잘못된 입력 점의 영향만 없애면 RGB가 자동으로 정확한 위치를
찾는다'는 단순 해법을 지지하지 않는다. 마스킹 학습은 맹목 추론의 손상을
87→59개로 줄였지만 충분하지 않았다. 수도레이블 자체의 정답 방향 문제,
실사 시각적 구분, 전체 코너 대응 문제를 동시에 해결한 것은 아니다.
추가 어노테이션이나 태그가 필수라는 결론으로 바꾸지 않는다.

## 검증

- 관련 검사16개 통과. 입력 힌트만 가리고 정답/감독을 유지하는 동작,
  각 BLIND 출력이 자기 힌트가 없는 pass에서 오는지 검사했다.
- 이전 대조 실험과 초기화·실사/합성 샘플·순서·정답·source signature가 동일하다.
- 새217장 학습과 전체 평가 이미지 exact-hash 중복0. 다만 역사적 Replay
  teacher의 수동 학습3장이194장에 겹친 기존 한계는 그대로다.
