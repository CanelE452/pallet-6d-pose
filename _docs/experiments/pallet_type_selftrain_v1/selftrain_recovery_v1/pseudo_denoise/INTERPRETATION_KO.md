# 추가 실사 정답 없는 큰 코너 보정: 완료한 범위와 남은 문제

## 실제 실행

2026-09-20, 기존 일반 플라스틱 217장의 Replay 보정 수도레이블을 사용했다.
새 수동 어노테이션 및 AprilTag 레이블은 0개다. 기존 Replay의 복사본 두 개를
각각 300 step 학습했다. R0 검출기와 기존 최종 배포 모델은 변경하지 않았다.

- CLEAN: 원본 R0 입력 → 기존 보정 수도레이블.
- DENOISE: 같은 이미지·목표·노출 횟수에서 입력만 50% 확률로 교란.
  25%는 하나의 신뢰 코너, 25%는 모든 신뢰 코너를 목표에서 벗어나게 한다.
- 양쪽 모두 기존 합성 GT replay를 동일하게 사용한다.
- 각 실험의 실사/합성 노출은 각각 2,400회다. 실사 입력 교란 중
  20px를 넘는 코너 노출은 3,416회다. 이는 **인위적 학습 오차**이며,
  실제 틀린 코너를 3,416개 찾았거나 고쳤다는 뜻이 아니다.
- 이전 AGREE 동의 마스크는 적용하지 않았다. 원래의 보정 좌표와 신뢰 마스크를
  그대로 사용하고, centroid는 새 감독 대상에서 제외했다.

새 코드·기존 replay 회귀검사 총 16개가 통과했다. 양 학습의 BN 버퍼는
변하지 않았다. 초기 합성 probe의 이산 카운트는 동일했고, 연속값은
최대 약 0.000015px의 GPU 수치 차이가 있어 bit-exact 추론 재현이라고 하지 않는다.

## 실제 자연 오류 평가

전체 194장에 모든 출력을 저장한 뒤 정답을 열어 채점했다. 35장 제외 버전인
159장도 기존 동결 명단 그대로 평가했다. 정답으로 후보나 임계값을 고르지 않았다.

| 평가 | 모델 | >20px → ≤10px 복구 | <5px → >10px 손상 | PCK20 | P90 |
|---|---|---:|---:|---:|---:|
| 전체194 | 기존 Replay | 7/281 | 5/511 | 79.91% | 46.25px |
| 전체194 | CLEAN | 5/281 | 7/511 | 81.30% | 43.30px |
| 전체194 | DENOISE | 14/281 | 13/511 | 80.24% | 50.52px |
| 제외후159 | 기존 Replay | 7/187 | 5/447 | 82.08% | 37.21px |
| 제외후159 | CLEAN | 5/187 | 5/447 | 83.21% | 33.56px |
| 제외후159 | DENOISE | 11/187 | 7/447 | 82.24% | 39.77px |

원본 R0는 전체194에서 PCK20 77.86%, P90 43.64px이고,
159장에서는 PCK20 80.45%, P90 33.18px다. 복구·손상 분모는 모두
동일한 R0의 매칭된 canonical GT 코너로 고정했다.

두 새 실험 모두 손상률 1% 이하 조건에 실패했다. 좋은 평균/중앙값만 보고
채택하지 않는다. 원본 모델 교체, 새 수도레이블 생성 또는 다음 학생 학습으로
자동 연결하지 않았다.

## 큰 오류 전체를 해결했다고 할 수 없는 구체적 이유

1. DENOISE가 복구한 14개는 원래 약 20.6–30.8px였던 코너다.
   가장 큰 복구는 30.78 → 8.43px였다. 40px를 넘던 코너의 ≤10px 복구는 없다.
2. 사용자가 보여준 의자·콘 사진 `eval_pallet07:1778652166837872128`은
   평균 264.90 → 270.29px로 개선되지 않았다. 코너 의미/방향 대응의 큰 오류가 남는다.
3. 올바르던 코너 13개를 손상했고 P90도 원본보다 나빠졌다.
4. 32장 인위적 교란 probe에서의 146/165 복구는 **수도레이블로 돌아가는 능력**이다.
   자연 오류에 대한 정답 정확도나 독립 검증으로 사용할 수 없다.
5. 기존 Replay는 과거 9장 수동 감독을 받았고 전체194 중 3장과 겹친다.
   이번의 '추가 레이블 0개'를 전체 파이프라인의 무감독 주장으로 바꾸지 않는다.
   전체194/159는 반복 사용한 DEV이지 새로운 독립 평가가 아니다.

따라서 결론은 '새 레이블 없이는 학습할 수 없다'가 아니다.
**기존 수도레이블로 큰 이동을 배우고 일부 자연 오류를 복구할 수는 있었지만,
잘못된 방향의 큰 이동과 정상 코너 손상을 함께 해결하지는 못했다.**

다음 검토는 이 두 문제를 분리해야 한다. 이동량을 늘리거나 같은 동의 필터를
반복하는 것만으로 해결됐다고 하지 않는다. 특히 잘못된 코너 대응을 정상 위치로
복구하는 근거와, 그대로 두어야 하는 코너를 보존하는 근거를 별도로 검증해야 한다.
추가 어노테이션/태그 요청으로 되돌리지 않는다.

## 재현·검토 파일

- `PROTOCOL.json`: 학습 전 동결한 설정, 데이터/코드/초기 모델 SHA.
- `FIT_CLEAN.json`, `FIT_DENOISE.json`: 학습 결과와 합성/수도레이블 probe.
- `CORRUPTION_EXPOSURE_AUDIT.json`: 실제 고정 입력 교란 분포.
- `OUTPUTS_LOCK.json`: 평가 정답 채점 전 저장한 전체 예측.
- `RESULTS.json`: 전체194/159 복구·손상·성능 및 사전 조건별 판정.
- `outputs/pallet_type_selftrain_v1/selftrain_recovery_v1/pseudo_denoise/index.html`:
  194장 전체의 R0/기존 Replay/CLEAN/DENOISE 비교. 성공·손상 모두 포함.
