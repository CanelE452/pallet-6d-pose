## 0. 목표와 범위

**목표는 외곽선 비용이 참조상 실패 자세를 선호하는 장면에서, 저장 경계가 실제 팔레트 외곽을 측정하는지 확인하고 마스크·형상 모델·등록/참조 중 다음에 수정할 대상을 결정하는 것이다.** 외곽선 항을 없애거나 약하게 만드는 실험이 아니다.

S/B/I/O/T/U 상태별로 점·부분 선·영역·모델 투영을 구분한다는 연구 방향, N3·SubPix·기존 전체 방법 e를 유지한다. 기존 실패를 숨기거나 모든 상태의 효용이 증명됐다고 주장하지 않는다.

[확인·원결과] 같은 가설 내부의 선택 실패22장에서 외곽선 비용은 실제 선택된 실패 후보를22/22 지지했지만, 성공114장에서도 비교한 실패 후보에 맞서 성공을114/114 지지했다. G13 내부 점수에서 외곽선 항을 제외한 고정후보 진단은9회복·11손상으로114→112/192였다. 따라서 단순 전체 삭제는 해결책으로 확인되지 않았다. 근거는 원 `RESULTS_KO.md`, `SCORE_INFLUENCE_DIAGNOSTIC.csv`다.

[진단 설계·미검증] 아래 검토가 물리 원인이나 개선 효과를 보장하지는 않는다. 작은 잔차·작은 공분산·좋은 정답 점수만으로 경계의 정체를 판정하지 않는다. 물리 대응을 확인할 수 없으면 위치와 이유를 특정해 미확정으로 남긴다.

### 바로 실행할 일

- 기존 코드·관측·원영상·마스크·후보·표본별 비용을 읽고 연결한다.
- 같은 저장 좌표를 사용하는 비교 그림과 확대 화면을 만들고 실제 이미지 내용을 검토한다.
- 저장 마스크→원 볼록 외곽→저장 표본의 생성 계보를 점검한다.
- 저장 비용의 표본 합과 구간별 기여를 재집계한다.
- 성공 반례까지 같은 기준으로 검토하고 다음 수정 한 가지 또는 구체적인 미해결 질문을 보고한다.
- 새 분석 코드·보고서·허용된 그림을 검산한 뒤 main에 commit·push한다.

### 이번에 실행하지 않을 일

새 학습·CAL 재fit·새 seed·모델 forward·분할기 재실행·새 선 검출·PnP·수치 자세 최적화·새 후보 생성은 **모두0회**다. 손실/가중치/임계값 탐색, 관측 삭제 후 재선택, 기존952개 replay 및11,603개 전량 비용 재평가를 반복하지 않는다. 참조 자세·코너·물리 축·카메라 파라미터를 수정하지 않는다. 새 주석을 정답이나 선택기 학습 레이블로 사용하지 않는다. 논문·운영 기본값·기존 결과·모델 가중치는 바꾸지 않는다.

## 3. 영상·마스크·기하·비용을 같은 좌표계로 대조

각 사례에서 아래5층을 분리해서 보여준다.

1. **원 RGB:** 표시선 없는 전체 장면과 확대. 미리보기나 이미 마커가 그려진 JPEG를 원영상으로 사용하지 않는다.
2. **실제 사용한 마스크:** 가능하면 원 soft/binary mask와 저장된 후처리 결과를 구분한다. 없는 단계는 생성하지 않는다.
3. **비용에 들어간 경계:** 저장된 볼록 다각형, 사용한 유한 선분, 제외된 화면 경계, 실제 observed 표본.
4. **두 고정 후보:** 같은 관측 위에 실제 선택과 기존 대조 후보의 모델 투영을 각각 그린다. 두 가설의 native/physical Q·등록 크기를 섞지 않는다.
5. **기존 참조 투영:** 필요하면 별도 패널로만 표시한다. 기하 재구성 참조이며 독립 물리 정답이 아님을 명시한다.

원 해상도와 crop/resize/letterbox 변환을 기록하고 원영상 좌표로 일치시킨다. 원 픽셀과 crop의 대응은 코드로 검사한다. 그림을 맞추려고 K·치수·좌표에 추가 offset을 넣지 않는다. 이미지가 너무 어둡다면 원본을 항상 함께 두고 표시용 명암 조정 사본만 별도 표기한다. 조정 사본으로 새 수치를 계산하지 않는다. 생성형 복원·inpainting·새 RGB 생성은 금지한다.

[확인·기존 코드] `observe_global_outline`은 마스크 전경의 볼록 외곽을 만들며, 이것은 실제 완전한 표면이나 물리 모서리 인증이 아니다. 단순히 볼록 외곽의 선분이라는 이유만으로 오류라고 판정하지도 않는다. 직육면체의 가상 외곽을 근사하는 데 유효한 선분일 수도 있다. 실제 영상 지지와 모델의 요구를 따로 본다.

원 생성 함수와 같은 설정으로 저장 마스크에서 외곽을 재구성해 **기존 polygon/선분/표본과의 동일성을 확인하는 것**은 허용한다. 이는 기존 데이터 변환의 검산이며 새 관측·대체 마스크가 아니다. 원 contour 추출의 표시용 파생물도 같은 mask의 구조 설명에만 사용한다. 다른 threshold·형태학 연산·새 선 검출을 적용해 결과가 좋아지는 경계를 만들지 않는다.

## 4. 실제로 선택을 바꾼 구간을 빠짐없이 확인

기존 `witness_XX_samples.csv.gz`의 확인된 열은 다음과 같다.

```text
sample_index, x_px, y_px,
selected_contribution, comparison_contribution, Delta
```

`Delta = comparison_contribution - selected_contribution`이다. 양수는 실제 선택 후보를 선호한다. 대조 후보가 성공인 실패 사례와, 대조 후보가 실패인 성공 반례에서 **같은 부호가 다른 정확도 의미**를 가지므로 구분해서 적는다.

- observed→model 방향은 두 후보가 정확히 같은 observed 표본을 사용했는지 확인한다. 원 인덱스·수·좌표·순서를 유지하고 `math.fsum(Delta)`가 기존 방향 비용차와 원 허용치1e-9 안에서 일치하는지 검사한다.
- 기존 receipt의 가장 큰 양/음 표본 목록을 재사용하고, 해당 표본이 놓인 **전체 부모 선분과 이웃 문맥**을 검토한다. 같은 선분의 표본을 수십 개 독립 증거처럼 세지 않는다. 반대 부호 구간도 숨기지 않는다.
- model→observed 표본은 후보별 투영 선분과 호 길이가 달라진다. 같은 표본 인덱스끼리 빼지 않는다. 각 후보의 자체 표본·정규화·비용을 따로 보여주고 방향 총합만 비교한다.
- 원 1/2 양방향 평균·outline weight가 어느 열에 이미 포함됐는지 `witness.py`와 장부로 확인한다. 두 번 곱하거나 가중 비용을 px 오차로 부르지 않는다.
- 나머지 점·부분 선 비용은 기존 값을 문맥으로 표시하되 재fit·삭제·새 순위 계산은 하지 않는다.

검산 사례는 `wood_night_01:030698`이다. 기존 observed→model854표본 비용차는 약+6.128810, 반대 방향 약+3.528464, 전체 outline 약+9.657273이었다. 대조 후보의 점 비용과 부분 선 비용은 각각 약−0.969840, −0.052049로 개선됐는데 outline이 이를 상쇄했다. 실제 원정밀도 값으로 검산하고 이 반올림 숫자에 억지로 맞추지 않는다.

## 5. 비용과 분리해 물리 경계의 근거를 기록

[새 진단용 기록; 정답·학습 레이블 아님] 검토 구간별로 아래 세 범주 중 하나와 관찰 근거를 기록한다. 숫자 거리 합격선을 새로 만들지 않는다.

- **PALLET_OUTER_SUPPORT:** 원 RGB에서 팔레트의 바깥 경계로 해석할 직접 지지가 있음.
- **OTHER_OR_CONSTRUCTED_BOUNDARY:** 다른 물체·그림자·내부 구조 등 다른 경계가 직접 확인되거나, 마스크/볼록 외곽 생성 과정에서 이어진 구간임이 확인됨.
- **UNRESOLVED:** 어두움·가림·영상 해상도·원자료 누락·여러 해석 때문에 해당 지지가 확인되지 않음.

두 번째 범주는 원인이 확정된 것이 아니다. `그림자`, `가림 물체`, `내부 모서리`, `볼록 외곽 연결 구간`, `화면 절단`, `기타`의 상세 근거를 별도로 적는다. 볼록 외곽으로 연결됐다는 계산상 사실과, 그것이 실제 모델 외곽을 잘못 나타낸다는 물리 판정은 별도다. 가려져 안 보이는 구간을 자동으로 틀린 경계라고 판정하지 않는다.

**다음 질문을 반드시 분리한다.**

A. 저장 마스크 경계가 이미지에서 보이는 팔레트 외곽을 지지하는가?
B. 그 외곽을 등록 직육면체의 투영 외곽과 동일시해도 되는가?
C. 참조 투영·물리 축·카메라 계약과 실제 영상이 함께 양립하는가?

A가 맞아도 B는 틀릴 수 있다. 예를 들어 등록 직육면체의 꼭짓점/가상 변이 물리 팔레트의 모든 실제 경계에 존재하는 것은 확인이 필요한 가정이다. 참조상 성공 후보가 마스크와 어긋난다는 사실만으로 mask 오류 또는 참조 오류를 결정하지 않는다. 후보 투영을 물리 경계의 정답으로 사용하지 않는다.

각 기록에는 원영상/마스크 SHA, 원영상 좌표의 구간, 원 sample index 목록, 관측 subtype, 모델의 어느 물리 외곽에 해당한다고 해석했는지 또는 미확정인지, 근거와 반론, 검토자 종류(human/model/code), 판정 일시를 넣는다. 출처 연결·계산 사실은 [확인], 영상 해석이나 일반화는 근거 범위에 따라 [추정]으로 구분한다. 모델이 읽은 결과를 사람 검수로 기록하지 않는다.

가능하면 먼저 오류 숫자·성공 표시 없는 RGB+관측 경계 화면을 검토하고, 그 기록 후 후보/비용 패널을 대조한다. 이미 알고 있던 사례이므로 독립 블라인드 검증이라 부르지 않는다. 지지 구간의 새 클릭이 필요하면 **감사용 파생 표시**에만 저장하고 기존 어노테이션이나 GT에 합치지 않는다.

CLI가 실제 이미지를 볼 도구가 없으면 본 것처럼 서술하지 않는다. 그 경우에도 자료 연결·좌표 검산·검토 화면 생성·기존 비용 연결은 끝까지 수행하고, 사람이 확인할 정확한 구간과 질문을 담은 REVIEW_REQUIRED.md를 만든다. 이미지 이름이나 비용 수치만 보고 의미 범주를 채우지 않는다.

## 6. 반례와 집계를 함께 보고

실패4장과 성공2장에 동일한 검토 형식·확대 방식·판정 기준을 적용한다. 성공 반례 `wood_night_01:030898`에서 outline이 잘못된 대조 후보를 약+0.774584 벌점화해 성공을 지킨 근거도 실제 경계와 연결한다.

사례별로 각 범주의 선분 수, 검토한/미검토한 observed 표본 수, 기존 signed Delta 합과 절댓값 합을 보고한다. 겹치는 표시 구간은 합산에서 중복 제거하고, UNRESOLVED와 미검토 구간을 분모에서 빼지 않는다. 이는 비용 기여의 설명이지 픽셀·영상 정확도나 독립 표본 기반 통계검정이 아니다. sample 가중치를 지지 판정에 맞춰 바꾸거나 이 범주별 표본만 남겨 새 성공률을 만들지 않는다.

전체32/114의 기존 장부는 그대로 두고6장 결과와 연결한다. 6장에서 보인 현상을 전량에 확인된 것으로 쓰지 않는다. 이 단계에서 전238 영상의 새 판정·새 mask 생성으로 범위를 늘리지 않는다.

## 7. 다음 수정 한 가지의 선택 기준

다음 표는 결론을 강제하는 규칙이 아니라 증거별 의사결정 경로다.

| 확인한 근거 | 보고할 다음 판단 |
|---|---|
| 실패의 결정적 경계가 다른 물체/그림자 등이고 성공의 결정적 경계와 지지가 다름 | 해당 관측의 출처·가시성·불확실성 중 한 가지를 다룰 최소 변경안. 손상 반례와 확인 조건을 함께 적음 |
| mask는 실제 외곽을 잘 지지하지만 직육면체 실루엣과의 대응이 일관되게 어긋남 | 분할기를 탓하지 말고 비교 기하/외곽 관측 가정 한 가지의 변경안을 제시 |
| image–mask–model–reference의 관계가 자료만으로 결정되지 않음 | 물리 축·원 카메라 계약·해당 외곽의 확인 중 무엇이 추가로 필요한지 정확한 장면/좌표/질문으로 제시 |
| 성공과 실패를 가르는 일관된 차이를 찾지 못함 | 현 가설의 한계를 보고하고 loss/weight 수정이나 추가 학습을 정당화하지 않음 |

변경안은 하나로 제한한다. 기존 표준 해법/가까운 선행과 현재 전제 차이를 확인한 뒤 설명한다. 이 작업의 검토 결과를 새로운 알고리즘의 최초성이나 개선 성능으로 쓰지 않는다. 변경안을 실행하는 새 학습·solver·후보·선택기 실험은 별도 승인이다.

후보부재46장과 `wood_night_01:033421`의 G10→G13 전달 공백은 기존 장부의 한계로 유지한다. 이번 외곽선 검토가46장을 복구했다고 보고하지 않으며, 해당 후보를 새로 추가하거나 초기화를 바꾸지 않는다.

## 8. 구현·검산·결과물

다음은 **신규 제안 경로**이며 기존 코드나 키라고 가정하지 않는다.

```text
scripts/research/pallet_outline_physical_support_audit_v1/
_docs/experiments/pallet_outline_physical_support_audit_v1/
```

이미 있으면 이전 시도를 보존하고 새 버전을 쓴다. 공통 로더·원 그림의 좌표 변환을 재사용하되 원 파일은 수정하지 않는다. 새 스키마의 필드는 기존 필드와 매핑한 뒤 기록한다.

최소 결과물:

- `REPORT_KO.md`: 여섯 장별 판정·반례·미확정·다음 수정 한 가지. 첫머리에 이번에 새 성능이 산출됐는지 명시.
- `INPUT_BINDINGS.json`: 원결과 commit, 읽은 파일/이미지/마스크/후보/표본의 경로와 SHA, 누락·파생 변환.
- `SUPPORT_REVIEW.jsonl` 및 `.csv`: 구간별 근거·출처·판정·미확정. 진단 전용이며 학습 타깃이 아님.
- `COST_SUPPORT_SUMMARY.csv`: 기존 비용 기여와 검토 범주의 연결, 표본/구간별 분모와 미확정.
- `gallery/index.html`: 여섯 장, 원본·mask·stored hull·표본·두 고정 후보·별도 참조 패널. 단순 기존 그림 복사로 새 검토 완료를 선언하지 않음.
- `NEXT_CHANGE_PROPOSAL_KO.md`: 근거가 충분한 최소 수정 한 가지, 또는 판단을 막는 최소 추가 확인.
- `VALIDATION.json`, `REPRODUCE.md`, `COST.json`: 좌표·합산·원자료 불변·실제 실행량과 재현법.
- 필요한 경우 `REVIEW_REQUIRED.md`: 사람이 실제로 확인할 구간만 정확하게 제시.

검산은 대표 ID/순서, 같은 observed 표본 인덱스, 원 crop 좌표, 원변환 재현, 방향별 비용 합, 후보별 Q/치수, 미검토/불명 구간의 보존, 기존 예측·참조·소스의 불변을 포함한다. JPEG 재압축과 원 RGB의 바이트 동일성은 혼동하지 않는다. 비교할 원파일이 없으면 검산 성공을 만들지 않는다. 무관한 방대한 검사를 늘리기보다 결론을 바꿀 수 있는 검사를 수행한다.

자원 상한은 이전 승인 범위 안에서 CPU 분석120분을 넘지 않는 임시 운영 상한으로 둔다. 실제 소요시간 예상치나 성능 합격선은 아니다. 새 학습/신경망/GPU 모델 실행은0회, 병렬 CPU 작업은최대2개로 시작한다. 대기·파일다운로드·그림·육안검토·CPU 계산은 실제 계측 가능한 범위대로 구분하고 사람이 검토하지 않은 시간을 인간 검토시간으로 적지 않는다. 원자료를 스트리밍하고 새 마스크/후보 생성으로 예산을 쓰지 않는다. 상한 또는 승인 범위 변경이 필요하면 필요한 이유와 최소 추가량을 보고한다.

## 9. main 반영과 완료 보고

사용자는 이번 분석 산출물도 main에서 볼 수 있도록 요청했다. 별도 작업 브랜치/worktree에서 안전하게 작업해도 되지만, **완료 시 검산된 새 분석 코드·작은 결과·공개 가능한 그림을 main에 병합·push한 뒤 원격에서 읽어 확인한다.** 기존 c56a4e92 결과와 원연구 브랜치는 보존한다.

- 먼저 원격 main을 확인하고 타인의 새 작업을 버리지 않는다. staged 파일을 검토해 이번 신규 경로 외 사용자 작업을 섞지 않는다.
- 기존 논문·추론 기본값·예측·정답·모델은 변경하지 않는다. 공개 가능한 자료와 로컬 비공개 원영상/대형 dense 기록을 구분한다. 비공개 절대경로·권한 미확인 RGB·토큰·모델 가중치는 게시하지 않는다.
- 큰 파일은 기존 승인된 manifest/Release 방식으로 보존하고 Git 한도를 넘기려고 이력을 삭제하거나 강제 push하지 않는다.
- main에서 충돌·브랜치 보호·필수 검사 실패가 나면 우회하거나 설정을 바꾸지 않는다. 깨끗한 작업 브랜치/PR을 보존하고 main 반영이 막힌 이유를 정확히 보고한다.
- PR 병합을 쓰면 검토한 head SHA를 고정한다. push 후 원격 main의 SHA와 이번 산출물 경로·내용을 재확인한다.

마지막 답변은 (1) 무엇을 실제 확인했는가, (2) 여섯 사례별 경계 지지와 미확정, (3) 성공을 지키는 근거와 실패를 만드는 근거의 차이, (4) 다음 수정 한 가지/필수 추가 확인, (5) 새 추론·학습·성능 측정 여부, (6) main의 실제 commit SHA와 보고서/갤러리 위치 순으로 적는다.

**목표는 또 하나의 비용표가 아니라, 어떤 경계를 어떤 모델의 관측으로 쓰는 가정이 잘못됐는지 또는 아직 결정할 수 없는지를 실제 영상 근거로 명확하게 만드는 것이다.**
