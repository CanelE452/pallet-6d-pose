# V188 완료 기록의 불변 추가 게시

이 도구는 게시 준비용입니다. 실제 V188 파일 열거·hash·복사·Git 실행은 아직 하지 않았습니다. 기존 V187 도구와 initial manifest, V187 delta/chain/index는 수정하지 않습니다.

1. Root가 V188의 `ROOT_PHASE_RESULT.json`, 완료 보고서와 독립 QA를 봉인합니다. `ROOT_DELTA_INVENTORY_ENTRY_TEMPLATE_APPROVED_FALSE.json`에 정확한 root publication scope, 완료 결과와 별도 QA PASS binding을 넣은 새 actual entry가 필요합니다. 원 V188만 열거하며, 금지 이름은 stat 전에 prune하고 symlink는 따라가지 않습니다.
2. `prepare_completed_phase_delta.py --entry <actual-inventory-entry>`를 한 번 실행합니다. 원문 code/JSON/HTML/MD/표/실패 기록과 clean review PNG는 보존합니다. raw CONTROL/INPUT NPZ, NPY, features, weights, full source bank는 제외 사유·경로·크기를 manifest에 남깁니다. 작은 수치 결과의 예외는 root의 명시 whitelist만 허용하고 input/control/cache/feature/weight/bank는 예외로 넣을 수 없습니다.
3. Root가 `ROOT_DELTA_BUILD_ENTRY_TEMPLATE_APPROVED_FALSE.json`의 새 actual entry를 작성합니다. exact candidate와 inventory, immutable initial `PUBLICATION_MANIFEST.json`, V187 `publication/deltas/V187_20261024_v1/DELTA_MANIFEST.json`, `MANIFEST_CHAIN_AFTER_V187.json`, `EXPERIMENT_INDEX_THROUGH_V187_KO.md`, 원 global `readme.md`를 모두 binding합니다. 준비 코드·protocol·검사·workflow는 `publisher_tool_bindings`에 파일별로 명시합니다. Root가 알려준 당시 main은 `2f4221fcd862b30ae5a2a52baf1b98fb67f131b8`이며, 실제 entry의 expected tip은 strict push runner가 다시 확인해야 합니다.
4. `build_completed_phase_delta.py --build-entry <actual-build-entry>`는 기존 exact copier를 호출해 새 `archive/task-2/pallet-keypoint-visibility/query_visibility_direct_end_local_counterfactual_20261024_v188/`와 `publication/deltas/V188_20261024_v1/`만 만듭니다. 1 MiB 이상 text는 원 SHA를 유지하는 lossless gzip 32 MiB chunks + physical `.parts.json` descriptor로 보존합니다. 원문 내용은 바꾸지 않습니다. `PORTABLE_REPORT_KO.md`는 root가 source phase 안에서 미리 준비해야 하며 원문과 다른 파생 보고서입니다. 큰 JSONL/CSV 링크는 physical descriptor를 가리켜야 합니다.
5. 새 `EXPERIMENT_INDEX_THROUGH_V188_KO.md`는 이전 V187 index bytes를 그대로 suffix로 보존합니다. 새 `MANIFEST_CHAIN_AFTER_V188.json`은 initial base와 기존 V187 delta를 유지하고 V188 delta를 추가합니다. 기존 manifest-covered 경로, 부모 manifest/chain/index의 충돌은 거절합니다. global repository `readme.md`만 최신 링크를 앞에 추가하며 원문은 새 delta backup 및 suffix로 그대로 보존합니다.
6. 독립 검산은 source bytes/gzip roundtrip, 모든 physical SHA/size, exclusions, credential patterns, relative report/gallery links, 이전 base/V187 SHA 불변을 확인합니다. 이는 게시 정합성 검산이며 실험의 물리적 gold 또는 모델 성공 증명이 아닙니다.
7. Root의 별도 `ROOT_DELTA_PUSH_PLAN_ENTRY_TEMPLATE_APPROVED_FALSE.json` actual entry와 completed/PASS 독립 검산 후 `build_completed_phase_delta.py --push-plan-entry <actual-plan-entry>`를 실행합니다. 이 단계도 Git을 실행하지 않습니다. 새 delta의 physical files와 QA/BUILD receipts 및 global README만 480 MiB 이하 batches로 봉인합니다. Root가 기존 strict `push_publication_batches.py`로 expected remote/local HEAD·index/blob·commit 경로를 검사해 non-force main push합니다. 새 closing receipt 이름을 사용하고 과거 receipt를 덮어쓰지 않습니다.

모든 단계는 exclusive 새 출력만 사용합니다. 실패·부분 출력은 보존하며 자동 retry는 없습니다. V188 source controls와 weak end 관찰 결과를 보존하는 작업이지, 모델 채택이나 전체 목표 해결을 뜻하지 않습니다.
