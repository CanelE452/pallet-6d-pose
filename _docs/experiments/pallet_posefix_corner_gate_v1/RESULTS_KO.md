# 코너별 선택 보정 — GPU 고정 모델 실험 결과

2026-09-20 KST. 새 학습 없이 기존 N2와 Replay 후보 중 선택하는 단일 설정 진단이다.

## 결론

**코너별 필터는 초록색의 큰 오보정 일부를 막았지만, 어떤 보정이 이득인지 충분히 구별하지 못했다. 최종 N2를 교체할 근거는 없다.**

- 초록 수동 정답에서 Replay의 신규 훼손 34점 중 18점 차단, 16점 잔존. 좋은 보정 7점 중 5점 유지, 2점 손실.
- 초록 PCK@10: N2 81.351% → Replay 77.386% → 전체 코너쌍 필터 79.736%. 필터가 Replay 대비 2.349%p 회복했지만 N2보다 1.615%p 낮다.
- 초록 매칭 평균은 5.028 → 6.244 → 4.994px로 큰 실패 억제 덕분에 낮아졌다. 그러나 N2 대비 P90은 9.749 → 10.279px, PCK@10도 악화해 일관된 성능 향상은 아니다.
- 비초록 기존 참조점에서도 전체 코너쌍 필터 PCK@10 58.919%로 N2 59.459%보다 낮다. 이 참조점은 검증된 수동 GT가 아니다.
- 모델·평가 라벨·학습 분할·수도 레이블을 바꾸지 않았다. 새 학습형 선택기는 아직 학습하지 않았다.

## 무엇을 실행했나

사용자의 GPU 요청에 따라 RTX 3080에서 222장의 정상 입력과 실제 좌우 반전 입력을 처리했다. 정상 입력은 저장된 R0 예측을 사용해 고정 Replay를 재실행하고, 반전 입력은 R0 검출부터 Replay까지 재실행했다. 실제 출력 후보는 기존 저장 Replay 좌표를 그대로 사용했다.

- CUDA, batch 1, CPU 4 threads. 전체 추론 루프 13.02초이며 준비·기하 검사·채점·시각화 시간을 포함한 전체 작업 시간은 아니다.
- 모델 CUDA peak allocated 355.96MiB. 실행 중 총 GPU 메모리 약 1.53GiB, 최대 관찰 온도 57°C.
- 저장 Replay와 재계산한 정상 영상의 최대 좌표 차이 0.0001763px; 사전 허용치 0.01px 이내. 반전 검출 누락 0/222.
- 기존 외부 학습 작업은 GPU 실험 전에 자체 종료돼 있었으며 종료시키지 않았다. RustDesk 유지, 드라이버·전원·재부팅 변경 없음. 종료 후 본 실험의 GPU 프로세스가 사라진 것을 확인했다.
- CPU 실행 계획을 기록한 원본 PROTOCOL은 보존했다. 사용자의 GPU 요청은 `RUNTIME_OVERRIDE_GPU.json`에 실행 장치만 정정했으며, 전체 추론 전에 코드 해시를 잠갔다.

## 고정 비교군과 판단 방식

| 비교군 | 동작 |
|---|---|
| A_N2 | 현재 최종 N2 그대로 |
| REPLAY | 기존 Replay의 모든 보정 그대로 |
| LEGACY_FRAME | 기존 사진 단위 confidence + 제거 안정성 중앙값 + 반전 차이 중앙값; 통과하면 Replay 전체, 아니면 N2 전체 |
| CORNER_GEOMETRY_PAIR | 점별 제거 안정성 검사 후 수직 모서리쌍 단위로 Replay/N2 선택 |
| CORNER_FULL_PAIR | 위 기하 검사 + 점별 반전 일관성 + heatmap 평균/최빈 위치 간 분리 검사; 이번 주 비교군 |

모서리쌍은 native 번호 `(0,3), (1,2), (4,7), (5,6)`이다. 쌍의 양 끝이 모두 통과해야 적용한다. 선택한 N2/Replay 좌표를 섞은 뒤 구조를 다시 검사하고, 실패한 쌍은 N2로 되돌린다. 처음 선택한 물체 치수 가설과 정규화 대각선 길이는 재검사에서 바꾸지 않는다.

confidence 0.85, 코너 confidence 0.5, 유효 코너 6개, 정규화 제거/반전/평균–최빈 차이 0.05, 정상/반전 박스 IoU 0.5로 한 번만 실행했다. 0.05는 기존 필터에서 옮긴 **탐색용 기준**이며 코너별 실패 확률로 보정된 값이 아니다. 점수 확인 후 기준 재탐색·구제 실험은 하지 않았다. 기존 사진 단위 필터에는 재투영 오차 조건을 새로 추가하지 않았다.

각 출력 코너는 N2 또는 저장 Replay 중 하나의 정확한 좌표다. 새 좌표를 GT에 맞추거나 heatmap argmax로 교체하지 않았다. 검출 박스·confidence·중심점·후보 순서는 그대로다. 거절된 사진도 평가에서 빼지 않았다.

## 전체 결과

PCK@10은 오차 10px 이내 비율이다. 평균/중앙값/P90은 매칭된 코너만 집계하고, PCK에는 원래 매칭 실패 벌점과 전체 분모를 유지한다. 두 종류의 통계를 혼동하지 않는다.

## GT 분리, 검증, 한계

- 222장 모두 GT 좌표 없이 필터 판단을 끝내고 `OUTPUTS_LOCK.json`을 작성한 다음에 채점용 GT를 읽었다. 평가 자료 안의 경로·물체 치수·원본 카메라 K는 메타데이터로 사용했다.
- N2와 Replay의 기존 결과에 대해 744개 프레임/모드 재현 검사가 통과했다. 11개 회귀 테스트가 통과했고, 시각화의 18개 예측은 대칭 대응과 오차를 별도로 재계산해 일치했다.
- 별도 검산에서 8,880개 출력 코너의 N2/Replay 바이트 일치, 메타데이터·중심점 보존, 모든 쌍 판정과 최종 수락 코너의 기하 재검사를 확인했다. 상세: [내부 산술 감사](INDEPENDENT_AUDIT_KO.md). 외부 독립 데이터 검증을 뜻하지 않는다.
- HTML은 desktop 1440×1000 / mobile 390×844에서 6개 내장 이미지, 6개 이동 링크, 10개 표를 검증했다. 외부 자원 요청·JS 오류·문서 가로 넘침이 없었다. 실제 Chrome 창도 제목과 `IsViewable` 상태를 확인했다. 상세: [뷰어 검사](../../../outputs/pallet_posefix_corner_gate_v1/VIEWER_QA.json).
- 기존 관찰 사례를 보고 설계한 재사용 평가다. 독립 사전등록 확인이나 학습형 선택기 일반화 결과가 아니다.
- 기하 필터는 저장된 source K와 등록 물체 치수에 의존한다. 기존 `DATASET_SNAPSHOT.json`에는 초록 128/150장의 camera metadata mismatch가 기록돼 있다. 이번에 이를 보정하거나 카메라 K의 실제 영상 적합성까지 새로 검증한 것은 아니므로, 이 결과를 6D pose 정확도나 물리적 안전 보장으로 해석하지 않는다. 영상 좌표에서 수동 GT와 비교한 PCK와 기하 필터 자체의 정확성은 구별해야 한다.
- 대각선 시점에서 관찰된 실패가 실제 yaw 45도에 집중된다는 주장은 검증하지 않았다.
- 결과가 좋은 비교군을 사후 선택해 최종 모델로 교체하지 않았다. 기존 N2와 과거 결과는 보존했다.

## 필터 말고 어떻게 구별할 수 있나

다음 후보는 **보정 이득 예측기**다. 코너 주변 영상, 전체 점 배치, N2 점, Replay 후보를 보고 `유지`와 `보정` 중 무엇이 오차를 줄일지 학습한다. 학습 목표는 TRAIN GT에 대한 `N2 오차 − Replay 오차`다. 추론에서는 GT를 받지 않는다.

작은 별도 품질 모델을 쓰는 근거는 [DEKR의 scoring net](https://github.com/HRNet/DEKR#scoring-net)처럼 예측 자세의 품질을 학습하는 방식에 있다. 원 논문의 전체 pose OKS 예측을 코너별 보정 이득 비교로 확장하는 것은 우리 문제에 대한 제안이지, 이미 검증된 팔레트 해결책은 아니다.

두 모델의 불일치만으로 어느 쪽이 맞는지 알 수 없으며, 같은 오류를 확신하는 경우도 있다. 따라서 추가 confidence 임계값보다 두 후보의 상대적 이득을 학습하는 목표가 더 직접적이다. 합성에서 학습 가능하지만 실사 일반화는 별도 확인이 필요하다. 초록 평가 150장·DEV72를 선택기 학습/기준 탐색에 넣지 않는다. 기존 실사 9장을 out-of-fold로 쓰려면 선택기뿐 아니라 후보 refiner도 해당 fold를 학습에서 제외해야 한다.

자세한 대안과 누수 방지 조건: [LEARNED_SELECTOR_OPTIONS_KO.md](LEARNED_SELECTOR_OPTIONS_KO.md). 이번에는 이 선택기를 새로 학습하지 않았다.
