## PalletGraph-6D (MSL + DGP) oracle line utility screen — MSL REJECT

### 목적

MSL(Mask-Supported Semantic Lines) + DGP(Dimension-Guided Graph Pose)가 ep57
point-only 보다 유효한지 **oracle gate 로 먼저** 판정. full architecture 학습 아님.
과거 실패한 vector/offset/voting/endpoint 표현은 재도입하지 않고, line 을 keypoint 로
되돌리지 않는 **raster line map = DGP 가 직접 읽는 2D residual** 로만 표현.

### 신규 파일

- `Deep_Object_Pose/common/pallet_graph_geometry.py` — 3D graph, semantic edge class,
  180° symmetry. **edge class 를 하드코딩하지 않고 실제 3D 좌표에서 유도**해
  convention 변경 시 조용히 뒤집히지 않게 함.
  검증: width(X)=1.1=W, depth(Z)=1.3=D, vertical(Y)=0.12=H,
  permutation (5,4,7,6,1,0,3,2,8) residual 5.6e-17 (= 기존 ADD-S permutation 과 동일).
- `Deep_Object_Pose/common/dimension_guided_graph_pose.py` — point+line full SE(3)
  damped Gauss-Newton (Lie algebra, depth/condition/step guard, 180° 두 가설 refine).
- `scripts/stage0/paper_s2_palletgraph_line_screen.py` — P0~P4 runner.
- `challenge/tests/test_paper_s2_palletgraph_line_screen.py` — 25 테스트.

### 결과 (strict mechanism-val N87, baseline gate PASS 재현)

```
arm        succ    yaw(mod180)  corner_sym   reproj    비고
──────────────────────────────────────────────────────────────────────
P0         0.805   6.025        0.4516       23.16     기존 OpenCV PnP
P1         0.805   6.734        0.3326       22.22     DGP, lambda_line=0
P2(oracle amodal)  6.5~7.3      0.399~0.411            FAIL (3개 lambda 전부)
P3(oracle assoc)   6.9~7.4      0.378~0.384            FAIL
P4(generic edge)   7.2~7.3      0.367~0.399            FAIL
```
pose success 는 **모든 arm 에서 0.805 로 완전 동일** — line 이 실패 프레임을 하나도
살리지 못했다.

### 디버깅 2건

1. **solver 가 전혀 안 움직임**(iters=1, 개선 0). 원인 = Huber 선형영역에서 유한차분
   Hessian 이 0 으로 붕괴 → step 이 clip 한계까지 튀어 전부 기각.
   Before: `hessian_diag = max(fd, 1e-8)` / After: **trust-region floor**
   `max(fd, |grad|/trust)` (trust: rot 0.05rad, trans 0.05m) + backtracking 6회.
   수정 후 8°/0.147m 섭동 → point+line 이 0.01°/0.006m 로 회복, line-only 도 1.04°.
2. **lambda_line 미보정**. E_point median 27.97(max 319) vs E_line 5.58 로 point 가
   5배 압도 → line 이 pose 를 0.002° 만 움직임. "line 이 안 통한다"가 아니라
   "가중치를 안 줬다"가 될 뻔함. Phase G4 원칙을 이식해 **E_line/E_point fraction
   0.25/0.50/1.00 으로 사전 보정**(lambda 2.76/5.52/11.04), 셋 다 보고.

### ★ 방법론 발견 — 집계 median 아티팩트

P3(fraction 1.0)가 close-range 에서 corner error **20.4% 감소**로 PASS 처럼 보였으나,
**같은 frame paired 로는 개선 6/13, Δcorner +0.0004m 로 오히려 악화**.
subset median 은 frame 순위가 바뀌기만 해도 움직인다.
→ gate 에 **paired 보강 조건**(같은 frame 이 65% 이상 개선)을 추가해 허위 PASS 제거.
같은 이유로 P0→P1 parity 도 집계로는 FAIL(yaw +0.71°)이나 paired 로는 중립
(Δyaw median +0.029°, pose success 동일).

### ★ 이 실험이 시험하지 못한 것

DGP 는 초기 pose 가 필요하고 그 초기값은 point-only PnP 다. **point 가 실패한
17/87 프레임은 초기 pose 가 없어 fallback** 되어 line 이 개입할 기회가 없었다.
그런데 최상위 가설이 바로 그 경우다 → **가설의 핵심 population 미검증**.
실제 비교는 point 가 이미 성공한 70 프레임이고, truncated common-success 는 6 프레임.

### ★ MSL 전제 붕괴 — mask support

ep57 seg mask 가 real N87 에서 매우 약하다: **31/87(36%) 프레임은 mask 최대 확률조차
0.5 미만**, mask 면적 median 0.40%. "Mask-Supported" 의 mask 가 real 에 사실상 없다
→ Phase F 의 L2(mask support) arm 은 oracle gate 와 무관하게 현재 mask 로 시험 불가.

### 판정

- **MSL: REJECT** (지시문 Phase E4: P2 FAIL → MSL 종료). Phase F 미실행.
- **DGP: INCONCLUSIVE** (parity 집계 미달, paired 중립).
- **SAP: DEFERRED**.
- 단 '시험하지 못한 것' 때문에 "line 은 원리적으로 무용" 으로 일반화 금지.

### 무결성

final-test open count 0, checkpoint SHA 불변, 데이터셋 파일 수정 0건(테스트로 확인),
신규 렌더링 없음, 학습 없음. pytest `challenge/tests/` **117 passed** (신규 25 포함).

### 판정 정정 (시각화로 발견) — MSL REJECT → INCONCLUSIVE

사용자 요청("시각적으로 안 되는 부분")으로 에너지 지형을 그려보다 **판정을 뒤집는
사실**을 발견. 스크립트 `scripts/stage0/paper_s2_line_failure_viz.py`,
산출 `.../paper_s2_palletgraph_line_screen/why_line_failed/`.

1. **line 정보는 있다** — oracle map 을 그린 GT pose 기준 ±10° slice 에서 E_line 은
   0.276(GT) → 3.9/4.5 로 정상 최소·단조. 즉 "line 에 pose 정보가 없다" 가 아니다.
2. **도달을 못 한 것** — DGP 가 실제 출발하는 point-PnP pose 근처에서는 E_line 최소가
   GT 방향이 아니다. basin 이 GT 주변에 좁고, 6 iteration × trust 2.9° 로 진입 실패.
3. **구현 불일치** — P2 는 amodal line map 인데 energy 는 `visibility_aware=True` 로
   계산해 pose 마다 edge 집합이 바뀐다. mean-over-edges 라 edge 수가 바뀌면 값이
   점프 → 지형이 계단형(그림 1 오른쪽에서 육안 확인).

→ 이번 FAIL 은 **line 무용의 증거가 아니라 최적화 도달 실패**.
**MSL: REJECT → INCONCLUSIVE 로 정정.** Phase F 는 여전히 미실행이나 사유가
"MSL 이 틀렸다" 가 아니라 "현재 설계로는 시험 불가" 로 바뀐다.

부수 확인: yaw>60° 프레임 3개는 corner error 1.03m / reproj 110px 로 **실제로 크게
틀린 것**이지 W/D 90° 혼동 metric 아티팩트가 아니다(내 초기 추정 반증됨).

다음 admissible experiment 수정:
1. DGP energy 연속화(visibility 고정 또는 soft weight) + sample 단위 정규화 +
   iteration/trust 확대 또는 multi-start. 이걸 고치기 전 line 결론 확정 불가.
2. point 실패 17 프레임을 시험 가능하게 — line + 알려진 W/D/H 만으로 초기 pose 를
   세우는 경로 필요.
3. mask support 선결(real 31/87 붕괴).
