### [14:41] 표시 프레임 변경 — Y 위 / Z 관측자 쪽 (사용자 요청)

repo 규약은 OpenCV식(X右 / Y**下** / Z**전방**)이라 축을 그리면 Y 가 팔레트 안으로,
Z 가 화면 뒤로 향한다. 슬라이드에서 읽기 어려워 **표시 프레임**을 도입:

- `DISPLAY_FLIP = diag(1, -1, -1)` — 자기 자신이 역, 우수좌표계 유지(X × (−Y) = −Z).
- triad: `triad @ DISPLAY_FLIP` → Y=위(상판 밖), Z=관측자 쪽. 라벨 `Y up` / `Z out`.
- 각도: `R_display = DISPLAY_FLIP @ R @ DISPLAY_FLIP` 에서 추출.
  **object 와 camera 에 같은 flip** 을 걸었으므로 pose 가 바뀐 게 아니라 표시 basis 변경.
  round-trip 검증은 `R_display` 기준으로 그대로 강제(<=1e-6).
- 값 변화: `yaw +25.6 → −25.6`, `roll +17.8 → −17.8`, `pitch +35.9` 불변.
  (Y·Z 축 뒤집으면 그 두 축 회전의 부호가 반대가 되고 X 축 회전은 그대로)

## [18:31] O_MAP forward-parity 재판정 — LOCKED_SOFTPLUS_TLS_FAIL

### 수정 (커밋 `116ae43`, 실행 전)

`batch_terms` 는 `sigmoid(logit)` 을 target 에 맞추고 `softplus(logit)` 을 TLS 에 준다.
그러므로 perfect prediction 이 decoder 에 주는 weight = `softplus(logit(target))`
= `-log1p(-target)`. 기존 `run_omap` 은 `weighted_tls(target)` 을 직접 호출 →
**forward 가 만들지 않는 map 을 decode** 했다. label `OMAP_ORACLE_SEMANTICS_MISMATCH`.
등가식 오차 9.5e-7 (기준 1e-6, 테스트로 강제). clamp 는 dtype `1-eps`(임의 cap 아님),
`target==0 → weight 0` 정확. 바꾼 것은 **oracle input 뿐** — weighted_tls·target·
sigma·grid·gate·sign alignment·population 전부 20eb590 그대로 (parity 가
