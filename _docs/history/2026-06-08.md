## diag 통과 PL 전수 9kp overlay 눈검증 (ft_s2)

사용자 요청: diag 필터가 통과시킨 프레임이 실제로 9kp 정확한지 도메인별 **전부** 눈으로 확인.

### 추가 파일
- `scripts/data_prep/eval/diag_pass_all_overlay.py` (신규)
  - inference-free. `filter_domain_analysis/_full_s2.json` 재사용.
  - diag pass = `filt_diag(kp)[0]` (filter_combo_9kp.py 와 동일 로직 → 카운트 정확히 일치).
  - 스타일: pred 9kp = green 점 + 0~8 번호, GT projected_cuboid = magenta, pred cuboid edge = cyan.
  - 배지: order-free 9kp Hungarian reproj(px) + GOOD/BAD(<10px).
  - 도메인별 개별 overlay + contact sheet 저장. `_exclude.txt` 반영.

combo_9kp_s2.json 의 diag good 수치(indoor 0 / outside 14 / night 6)와 일치 확인.

### 소견 (BAD-but-passed 코너 오차 패턴)
- indoor diag 통과 7개 전멸: front(~7px)만으로 통과, back/centroid 항상 어긋남.
- BAD 공통 원인 = **flat / edge-on** (저카메라·원거리 측면뷰). 팔레트가 얇은 띠로 보이면 front-to-back depth 붕괴 → back 코너가 front 쪽으로 squash. 그래도 공간 대각선 교점은 projective 하게 centroid 근처라 diag 통과(diag = projective invariant → depth 붕괴 구조적으로 못 잡음).
- night BAD: pred cuboid yaw 약간 + 마지막은 어둡고 truncation 심해 GT 밖으로 뻗음.
- 결론: diag 단독은 PL 필터로 부적합(특히 indoor). 신뢰 PL 은 back+centroid 까지 보는 조건 필요. ransac_loo 류 good%=100 과 정합(수↓ 품질↑).

### eval ↔ 실배포 변수·값 동일성 검증 (코드 대조)
사용자 질문: eval이 쓰는 변수/값이 실제 리프터를 움직이는 실배포(main_rec/fsm)와 같은지 + 로그로 남기는지.

```
항목            eval                              실배포                          동일?
────────────────────────────────────────────────────────────────────────────────────
명령 byte       control.issue_command_*           fsm/commands.py 가 같은          ✅ 같은 모듈
                → MOVEMENT_TEMPLATES              control.issue_command_*
rel_yaw         yaw_deg += deg(gyro.y*dt)         main_rec 동일 적분식             ✅ 값 동일
                (imu_yaw.RelYawEstimator)         (line131/143, accel는 yaw 미적용)
전진 거리→시간   motion_models.                    fsm/align.py _fwd_sec_for_       ✅ 같은 함수
                fwd_sec_from_offset_piecewise     distance → 같은 함수+config
회전 종료방식    |rel_yaw| ≥ target                |rel_yaw-ref| ≥ target           ✅ 같은 메커니즘
```
- rel_yaw 값까지 동일 `[확인]`: main_rec line133 "accel 기반 roll/pitch(보조), yaw에는 미적용". yaw=gyro.Y 적분만 → eval과 식 일치. eval은 yaw에 안 쓰는 보조계산만 생략.
- 로그: rel_yaw_deg, gyro/accel 6축, cmd_bytes, state 전부 raw에 남김(입력+반응 동일 행).
- **의도된 차이 2가지**: ① 회전 target — eval=GUI 입력(90°)/실배포=config REL_YAW_TARGET_DEG=85+snapshot(메커니즘 동일, 캘리브 목적상 목표값만 다름). ② depth dist_z — eval 미로깅(IMU 타이밍 보호)/실배포는 INSERT 거리 계산에 사용.
