pool 원본 8개 세션 전부 ~7fps 연속 촬영이다. 파일명 ns 타임스탬프로 솎으면
전체 8,031 → 0.5s 간격 1,241 → **1s 간격 648** → 2s 331 → 5s 138.
현재 pool 1,000장이 이미 1초 유효 프레임 648장을 넘는다 — 과표집 상태다.
U7 비율(candidate 의 3.5%)을 648에 적용하면 ~23장으로 **지금(32장)보다 작다**.
→ U6/U7 표본은 pool 확대로 회수 불가. 새 촬영이 필요한 구조적 한계.
memory `adaptation-pool-lacks-near-square-viewpoints` 및 multiteacher 노트의
"병목이 방법이 아니라 adaptation pool 구성일 수 있다" 와 정합.

## ★[정정] mask/hull 은 가림이 아니라 밝기를 잰다

`paper_4pallet_mask_v1` 10,000 장 전수에서 하위꼬리를 뽑았다
(cover = visible mask_area_px / projected_cuboid 볼록껍질).
```
cover 분위  p1 0.419  p5 0.496  p25 0.595  p50 0.657  p75 0.720  p95 0.798
TAIL_lt40    73 장 (0.73%)   TAIL_lt50  538 장 (5.38%)   TAIL_lt60  2,691 장 (26.9%)
```
**그런데 눈으로 보니 cover 가 낮은 이유가 가림이 아니다** (`occlusion_tail_look.png`).
하위꼬리 4 장은 팔레트가 **검은 실루엣으로 뭉개진** 프레임이다 — 어둡거나 그림자에
잠겨 마스크가 작게 잡혔다.  상위꼬리(cover 0.88~0.90)는 팔레트가 밝고 선명한데
**오히려 그쪽에 검은 적재물이 상판 위에 올라가 있다**(000866 · 002871 · 002832).

따라서 앞서 이 세션에서 두 번 말한 것을 정정한다.
```
X "학습셋에 적재물이 없다"        -> 적재물은 있다. 검은 상자 형태로 상판 위에 실재한다.
X "mask/hull 로 가림을 잰다"      -> 그 지표는 밝기·대비를 잰다. 가림 측정에 못 쓴다.
```
가림을 제대로 세려면 인스턴스 세그멘테이션이 필요하다 — 팔레트 마스크와 다른 물체
마스크의 겹침을 봐야 하는데 이 셋의 `mask_rle` 는 팔레트 하나만 담아 불가능하다 `[추정]`.
