## [10:21] ★ GPU 12시간 25분 유휴 — 대기 루프의 자기매칭 함정

### 무슨 일이 있었나

전날 21:56 에 NEG screen 드라이버를 하네스 추적으로 재기동하면서, 고아가 된 smoke
자식 프로세스가 끝나기를 기다리려고 이런 대기 루프를 앞에 붙였다.

```bash
until ! pgrep -f "_tr_ADAPT" >/dev/null; do sleep 10; done
python -u neg_screen_driver.py
```

`pgrep -f` 는 **자기 자신을 포함한 모든 프로세스의 전체 cmdline** 을 훑는다. 이 셸의
cmdline 안에 `_tr_ADAPT` 문자열이 그대로 들어 있으므로 pgrep 은 언제나 자기 자신을
찾아냈고, `until` 조건은 영원히 거짓이 됐다. 결과는 무한 sleep.

```
PID 2577847   STAT Ss   ELAPSED 12:25:12   wchan do_wait
GPU           775 MiB, 5%   (12시간 내내 유휴)
NEGSCREEN_LOG 마지막 줄 [21:55:54] PHASE U7 N0 smoke 1ep   에서 정지
```

드라이버는 **시작조차 하지 않았다.** 로그의 마지막 줄은 그 전에 죽인 nohup 드라이버가
남긴 것이라 "진행 중" 처럼 보였고, 살아있는 셸도 있었기 때문에 겉으로는 정상이었다.
"프로세스가 살아있다" 는 진행의 증거가 아니라는 사례가 하나 더 늘었다.

### 왜 안 걸렸나

- 백그라운드 task 출력 파일이 `| tail -200` 때문에 파이프라인 종료 전까지 **0 바이트**였다.
  진행이 안 보이는 상태 = 정상과 구분 불가.
- Monitor 는 `NEGSCREEN_LOG.txt` 를 보고 있었는데, 그 파일은 죽은 드라이버가 남긴
  줄에서 멈춰 있었다. 새 줄이 안 생기는 것과 "조용히 학습 중" 이 같아 보였다.
- Stop hook 은 셸이 살아있다고 계속 알려줬고, 나는 그것을 "학습 진행 중" 으로 읽었다.

### 조치

- `TaskStop` 으로 멈춘 셸 정리.
- 대기 루프를 **제거**하고 드라이버를 직접 기동. 드라이버 자체가 `results.csv` 행수로
  완료를 판정하므로, 이미 끝난 smoke 는 재학습하지 않고 그대로 재사용한다.
- 재기동 직후 `ps` + `nvidia-smi` 로 **산출물이 실제로 도는지** 확인했다.

### 교훈 (memory `pgrep-self-match-hangs-wait-loops` 로 분리 기록)

프로세스 대기 조건에 `pgrep -f <패턴>` 을 쓸 때 **패턴 문자열이 그 명령 자신의
cmdline 에 등장하면 절대 종료하지 않는다.** 이번 세션에서 같은 자기매칭이 세 번
나왔다 (`pgrep -af "combo_driver|..."`, `pgrep -af "neg_screen_driver"`, 그리고 이
대기 루프). 앞의 둘은 조회라서 오탐만 났지만, 이 하나는 **12시간을 날렸다.**
