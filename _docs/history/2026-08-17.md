## multihead 실패 원인 진단 — no-train diagnostics (세션이 08-16 자정을 넘김)

이 세션은 08-16 저녁에 시작해 자정을 넘겼다. **A0/A1/A2 3-arm screen 구축과 6k·25k
결과는 `_docs/history/2026-08-16.md` 에 있다**(복붙하지 않고 가리킴). 여기에는
자정 전후로 착수한 **원인 진단** 만 남긴다.

### 왜 진단을 하는가

08-16 결과: A1(corner+line 2-head)이 25,000 step·2 seed 에서 A0(line-only)를
개선하지 못했다(angle 평균 −4.02%, offset +0.67%, 두 seed 부호 일치). 그런데
A1 의 corner head 자체는 0.742 cell·seed 산포 0.8% 로 매우 안정적이고, line branch 도
학습된다. **둘 다 되는데 합치면 안 되는 이유**를 H1/H2/H3 로 분리한다.

```
H1  corner gradient 가 shared late-A1 에서 line gradient 와 충돌하는가
H2  early 는 공유 가능하나 late 는 분리해야 하는가
H3  상보성이 없는 게 아니라 line→CIGM→corner→PnP 변환이 정보를 버리는가
```

원칙: **싼 진단부터**, 게이트 통과 시에만 비싼 학습 단계로. A2 25k 가 GPU 를 쥐고
있어(pid 1170328, 죽이지 않음) GPU-heavy 단계는 그 뒤로 미뤘다.

### PHASE 1 — gradient interference: **기각. 이유가 예상과 다르다**

`GRADIENT_CONFLICT_SUPPORTED = False`. 512 train 프레임(두 manifest 와 disjoint),
64 고정 배치, 8 checkpoint, optimizer step 0.

```
seed/step         |g_line|   |g_corner|      ratio   cos med   neg frac
seed1 @ 6000     2.761e+00   1.808e-03   6.549e-04   +0.1818     0.08
seed1 @25000     3.672e+00   2.170e-03   5.911e-04   +0.1437     0.12
seed2 @ 6000     2.927e+00   2.262e-03   7.729e-04   +0.2481     0.09
seed2 @25000     3.571e+00   2.026e-03   5.673e-04   +0.1312     0.05
게이트  cos < -0.10 AND neg >= 0.60  → 8개 전부 정반대
```

per-tensor 로 쪼개도 line gradient 의 98.8% 를 지는 conv 4개가 전부 cosine 양수
(+0.129~+0.166). 숨은 충돌 블록 없음.

★**충돌이 아니라 부재였다.**

```
                 step 0        step 25,000     변화
||g_line||       7.53e-04      3.67e+00        × 4,900
||g_corner||     1.60e-02      2.17e-03        ÷ 7.4
ratio            21.3          5.9e-04         35,000배 붕괴
```

λ_corner=0.03518 을 곱하면 corner 가 공유 블록에 주는 기여 = line 의 **약 2e-05**.
step 0 엔 line head 가 무작위라 역전파가 거의 안 되고 corner head 는 warm-start 라
크게 틀려 gradient 가 크다 — **λ 를 하필 corner 에게 가장 유리한 한 순간에 쟀다.**
25k 에서 의도한 0.75 비율을 유지하려면 λ_corner 가 **약 1,300** 이어야 한다.
일반 교훈: **step-0 gradient norm 으로 multitask 가중치를 정하면 학습이 아니라
초기화를 재는 것이다.**

### ★PHASE 1 — 프로젝트의 "V" 는 visible 이 아니라 in-frame 이다

`mh_data.frame_row["v"]` = `sum(0<=x<W and 0<=y<H)` — **occlusion 검사 없음**.

**corner loss 는 평균 7.41 채널을 감독하는데 보이는 건 5.43** → hallucination 이
학습 목표에 이미 포함.

acceptance rule 은 이미 강제됨: `gates_all_pass` 40,000/40,000 (G1 Vvis>=4, G3 half unocc 등).
`degeneracy=none` 40k 전부. 코너 손실 주원인은 truncation 아니라 **occlusion 66%**.
