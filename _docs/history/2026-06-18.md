### 알고리즘 (실데이터 검증으로 결정)
- convention = camera-facing v6 (annotate_pnp.make_pallet_keypoints_3d): top{0,1,4,5}/bottom{2,3,6,7}, near{0,1,2,3}/far{4,5,6,7}.
- 3 평행변 그룹 중 **WIDTH(0-1,3-2,4-5,7-6)+DEPTH(0-4,1-5,2-6,3-7) 소실점만** 사용. HEIGHT(두께)는 thin slab 라 소실점 발산(실측 VP-spread 600~11000px) → corner 이동에 미사용.
- 각 corner = 자기 W-edge line ∩ D-edge line (line = edge 중점 통과 + 방향은 robust VP 로 snap). centroid(8) = 공간대각선 교점 평균(projective invariant).
- trust region(이동 cap=0.06×diag) + gate(코너<6 / 그룹 edge<2 / thin collapse / want_move>0.25×diag).

## 추론↔학습 입력 해상도 불일치 수정 (448 → 400)

### 발견
- 학습 로더 `Deep_Object_Pose/common/utils_dataset.py` 는 네트워크 입력을 **400×400 하드코딩** (`A.RandomCrop(400,400)` 일반 / `A.Resize(400,400)` truncation, line 425-426). `config/default.yaml`의 `input_size:448` 과 `train_dope.sh --imagesize 448` 은 로더에 transform 으로 전달 안 됨 → **dead value** (네트워크 실제 입력은 400). 따라서 이 history 상단 "img448" 표기는 실제로는 400.
