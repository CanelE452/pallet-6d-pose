## ★ 정정 — capacity audit 의 near 판정 뒤집힘 (pooling 이 원인)

직전 capacity audit 의 두 전제를 검증했다.

**(1) pooling 지적 — 맞다, 결정적.** mean/max 로 축약해 patch 내부 공간 배열을 없앴다.
corner 는 공간 패턴인데 그걸 못 보는 descriptor 로 쟀다.

**(2) GAP cancellation 지적 — 절반 맞다.** 내 코드는 차분이 아니라 GT/wrong 을 각각
독립 row 로 분류했으므로 "정확히 상쇄"는 아니다. 다만 같은 frame 이라 GAP block 이
두 클래스에 **동일**하게 들어가(`max|GAP(GT)-GAP(wrong)| = 0.0`) 선형 분류기에서 bias 로
흡수된다. 기전은 다르지만 결론은 같다.

→ 이전 "정보 존재의 upper bound" 표현은 과했다. **pooled descriptor 가 선형으로 읽히는
범위**만 잰 것이다.

### ★ Line oracle — O5 FAIL / O12 PASS (결정적)
topology 자동 생성: "축 하나만 다름" 규칙으로 12 edge, corner 당 incident 3개,

score(x,y) = -exp(mean dist to 3 incident edges / tau), tau=5, global argmax.
```

O5    eval56    56     2.7%     8.5%   69.4%   148.66px     0

```
**5-class 로는 corner 를 못 찾고, 12-edge instance 로는 거의 완벽하게 찾는다.**
원인은 구조적이다 — `top_width` 가 평행 edge 2개를 덮으므로 corner 를
"top_width+top_depth+vertical" 로 조건화하면 3개가 아니라 **6개 edge** 가 선택되고
distance field 의 최소점이 여러 corner 에 동시에 생긴다. O5 median 149px/293px 는
약한 신호가 아니라 **틀린 양**을 재는 것.

PPD head 가 예측하는 5-class 는 **GT 가 완벽해도** corner 식별에 불충분하다.
