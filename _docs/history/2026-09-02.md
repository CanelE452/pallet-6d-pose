## M1 의 DOPE 행을 채웠다 — evaluator 에 offline prediction 경로

M1 이 2행(YOLO26 R0 · Proposed)뿐이라 "main method comparison" 이라 부르기 어려웠다.
DOPE 는 checkpoint 가 있는데도 못 넣고 있었다 — evaluator 가 Ultralytics 전용이라서다.

```
challenge/evaluation_v2/paper_real_eval.py:1724   self.model = YOLO(str(weights), task="pose")
```

**해결 방식**: DOPE 전용 채점기를 따로 만들지 않았다. 그러면 M1 의 행들이 서로 다른
자로 잰 값이 되어 비교가 성립하지 않는다. 대신 evaluator 에 예측 주입 경로를 열었다.

```
Before                          After
──────────────────────────────────────────────────────────────────────────
predictor = _Ultralytics        --predictions 있으면 _CachedPredictor
Predictor(weights, device)      없으면 기존 _UltralyticsPredictor (기본 동작 불변)
(분기 없음)                     weights 는 provenance 로 계속 기록
                                selection_policy = OFFLINE_CACHED_PREDICTIONS
```

`_CachedPredictor` 는 `image path -> [{score, box_xyxy, keypoints_xy}]` 를 읽어
`_UltralyticsPredictor.predict()` 와 **같은 튜플 형태**를 돌려준다. 그래서 AP·keypoint·
subgroup 채점 코드는 한 줄도 바뀌지 않는다.

### 신규 `scripts/self_training_yolo/dump_dope_predictions.py`

추론 규약은 지어내지 않고 정본 함수를 그대로 썼다.


reflect-padding 은 선택이 아니다 — plain squash 는 truncation·근접에서 체계적

`mc_dump_dope.py` 는 쓰지 않았다. 그건 **다른 모델**(SplitLate multihead,
`weights/paper_s2/...`)용이고 161장 canonical 셋에 묶여 있다 `[확인]`.

## ★두 제안 필터의 단독 ablation — 누적 표로는 못 뽑던 것

사용자 지적: "flip 이랑 projection 각각 해보는 거" 를 했느냐.
**안 했었다.** 기존 arm 구성이 이랬다.

```
reproj 단독    F2 / R3_CONF_REPROJ    ✅
removal 단독   F3 / R4_CONF_REMOVE    ✅
flip 단독      (없음)                  ❌
removal+flip   F4 / R5_PROPOSED       ✅
```

M3 는 누적(R2→R4→R5)이라 `R4→R5` 는 **removal 이 이미 걸린 상태의 flip** 이지
flip 단독 효과가 아니다. 그래서 flip 단독 arm 을 만들고 2x2 를 완성했다.

### 신규 F5_CONF_FLIP + R6_CONF_FLIP

```
Before                                   After
──────────────────────────────────────────────────────────────────
ARMS = F0,F1,F2,F3,F4                    + F5_CONF_FLIP (flip 단독)
F4: removal_ok AND s_flip<=tau           flip_ok 를 먼저 계산해 F5 와 공유
manifest 5종                             manifest 6종
```

기존 F0~F4 manifest 는 **비트 동일**하게 재현됐다 (F4 sha 0df3a640 unchanged) `[확인]`.

### ★해석 — 주장을 다시 좁혀야 한다

```
keypoint-removal 단독   Δ +0.007   ← 효과 없음 (자기 std 0.045 안)
horizontal-flip 단독    Δ -0.060   ← std 0.076 안. 단독으로는 산포를 못 넘는다
둘 다 (Proposed)        Δ -0.123   ← std 0.014. 산포를 넘는다

단독 합 Δ -0.053  vs  실제 조합 Δ -0.123   →  상호작용 Δ -0.070
```

**어느 필터도 단독으로는 자기 replicate 산포를 못 넘는다. 조합만 넘는다.**
상호작용 항(-0.070)이 flip 단독 기여(-0.060)보다 크다 — 두 필터는 각자
독립적으로 기여하는 게 아니라 **함께일 때만** 효과가 나온다.

따라서 "flip 이 주 기여자" 라고 쓰면 안 된다. 앞서 누적 표에서 `R4→R5 Δ -0.132`
를 보고 그렇게 읽었는데, 그건 removal 이 먼저 걸린 조건에서의 값이었다.

Proposed 의 replicate std 가 0.014 로 네 칸 중 가장 작다는 점도 같이 남긴다 —
조합이 학습 신호를 안정화한다는 해석과 일관되지만 replicate 3 개라 분산 자체를
주장하지는 않는다.

## direct 3DoF track 착수 — 계약 확정 (학습 없음)

기존 `kp → PnP → x,z,yaw` 를 건드리지 않고 `challenge/direct_3dof/` 를 새로 열었다.
이번 단계 목표는 성능이 아니라 **계약 확정 + scaffold**다.

### 확인한 사실 (근거 있는 것만)

```
HEAD                b8bd485 (main), 작업트리 dirty M=224 ??=89 (다른 세션 동시 작업)
ultralytics         pallet-pose 8.0.120 / pallet-yolo26 8.4.60  ← YOLO26 는 후자 필요

```

배포 convention `[확인]` — 새로 만들지 않고 배포 코드에서 읽어 채택했다.
```python
center = tvec.reshape(3);  x = center[0];  z = center[2]     # 전면 중심, m
n = R @ [0,0,1];  yaw = atan2(n[0], n[2])                    # == atan2(R[0,2], R[2,2])
```

YOLO26n-pose 실측 (best.pt state_dict):
```
총 879 tensors / 3,063,920 params
  backbone model.0–10    240 / 1,373,880
  neck     model.11–22   228 /   903,334      합 468 / 2,277,214 = 74.3% 재사용 가능
  head     model.23      411 /   786,706
```
`Pose26.cv4` 는 읽기 헤드 없는 2-Conv trunk(45ch)이고 `cv4_kpts`(27ch)·`cv4_sigma`(18ch)가
1x1 로 병렬로 붙는다. **3DoF 를 같은 trunk 위 세 번째 형제로 붙일 수 있다** `[확인]`.
head 는 anchor-free dense — 8,400 anchor 각각이 답을 내고 object 대응은 학습 때 TAL
`fg_mask`/`target_gt_idx`, 추론 때 `get_topk_index` 가 맡는다. detection-pose association 유지.

synthetic exact GT `[확인]` — `objects[0].pose_transform` (4x4), `location`.
`u=fx·X/Z+cx` 로 투영하면 JSON `projected_cuboid_centroid` 와 소수점까지 일치.
단위 m, 축 OpenCV(+X right/+Y down/+Z forward) 로 **배포와 동일**.

### ★ 계약을 바꾼 발견 3개

**(1) yaw 주기가 2π 가 아니다.** 현장 팔레트는 4방향 포크 진입이라 90° 등가(사용자 확인).
`(sinψ, cosψ)` 를 쓰면 등가인 네 회전이 서로 다른 타깃을 받아 학습 신호가 상쇄된다.
`(sin4ψ, cos4ψ)` 로 인코딩하고 `ψ = atan2(s,c)/4` 로 디코드한다.
부수 효과로 사람 어노의 앞면 선택 모호성이 자동 해소된다.
기존 `SYMMETRY_CONTRACT.json` 은 `[0,180]` 이고 그 근거가 "X and Z extents differ" 라
X==Z 인 정사각에는 성립하지 않는다. **그 파일은 건드리지 않았다**(논문 SHA 핀).

**(2) object origin 불일치.** synthetic/annotate 는 cuboid 중심, 배포는 전면 중심.
보정 `t_front = t_center + R @ [0,0,-depth/2]` 를 빠뜨리면 z 가 깊이의 절반(~0.55 m)
계통 오차를 갖는다 `[확인]`.

**(3) 현재 R0 synthetic 은 치수가 프레임마다 랜덤 → direct z 학습 불가.**
G38 600 프레임 실측: width 0.675~1.660(2.46x), std/mean 16.4%, z 1.457~9.843.
이미지가 결정하는 건 `실제크기/z` 비율뿐이라 같은 픽셀 크기가 여러 z 에 대응한다.
z 오차 하한 ≈ 16.4% (평균 z 4.43 m 기준 ~0.73 m).
`02_synthetic v1/v3` 는 `[1.1, 1.3, 0.12]` 고정이라 대안이 된다 — **사용자 결정 대기**.

## C 의 파국 프레임 — "가림" 이 아니라 90 도 축 배정 실패였다 (정정 2 회)

### ★ 함정 1 — 정규화 구간을 배포 모델 규약이 아닌 임의 범위로 잡았다

모델은 멀쩡했고(5.1px) **내 정규화가 규약을 깬 것**이었다.
도구에 `--offset-deg`(기본 -90 = 배포 규약)를 추가하고 402개를 다시 맞춰
k=0 에서 5.1px 를 확인했다.

### ★ 함정 2 — ultralytics 라벨 캐시가 갱신되지 않는다

## paper_selftrain_v2 — V1 진단이 지목한 원인을 직접 고치는 별도 트랙

V1(`paper_selftrain_v1`)은 실패/진단 baseline 으로 **그대로 보존**한다.  V2 는
`scripts/self_training_yolo/v2/` · `challenge/.../paper_selftrain_v2/` ·
`data/pallet/results/paper_selftrain_v2/` 에 독립 생성했다.

핵심 아이디어: **box 신뢰도와 keypoint 신뢰도를 분리**한다.  좋은 detection 프레임
안에 나쁜 코너가 있다고 프레임을 버리지 않고, box confidence 가 높다고 모든 코너를
믿지도 않는다.  프레임은 keypoint 때문에 절대 제거되지 않는다.

문서 `_docs/paper/SELFTRAIN_V2_PROTOCOL.md`, 동결
`SELFTRAIN_V2_METHOD_LOCK.json`.  PAPER_EVAL 319 는 V2 에 대해
`V2_METHOD_DEVELOPMENT_POPULATION` 으로 역할을 바꿨다 — V2 방법 자체가 이 모집단의
진단을 보고 설계됐으므로 최종 성능을 여기서 주장하지 않는다.

`pseudo_fraction=0.25` 와 `ambiguity_threshold=0.75` 는 **DEV-INFORMED, NOT
PREREGISTERED** 로 lock 에 명시했다 (A12 근거: ALL corner 6.967 / 7.210 / 7.312 @
0.25 / 0.50 / 0.75, detection 은 셋 다 0.984).

### §12 — `visibility=0` 이 무엇을 하는지 gradient 로 쟀다

소스만 읽고 넘어가지 않았다.  영수증 `KEYPOINT_MASK_CONTRACT.json`.

A/C/D 통과 — box gradient 비가 **정확히 1.000**, masked 좌표는 무시되고, 보이는 점을
흔들면 손실이 바뀐다(31.82 -> 34.81).

**★ 함정**: `kpt_shape[-1] == 3` 이라 `bce_pose(pred_kpt[...,2], kpt_mask)` 가 masked
지점에 "보이지 않음" 을 **적극 학습**시킨다.  visibility=0 은 순수한 ignore 가
아니다.  배포가 `kp_conf >= 0.5` 를 쓰므로 DEV 에서 kp_conf 분포를 감시 지표로 둔다.
`kobj` 가중치는 바꾸지 않는다(§11).

중간 사고: 처음엔 무작위 이미지 + **픽셀 좌표** keypoint 로 쟀는데, 손실이
`batch["keypoints"]` 를 정규화 좌표로 받아 imgsz 를 곱하므로 전부 화면 밖으로 나가
`1-exp(-e)` 가 1 로 포화됐다.  그 상태에서 "masked 좌표 무시" 가 **공허하게 통과**
했다(무엇을 흔들어도 손실이 안 변하니까).  실제 프레임 + 정규화로 바꾸니
`visible_point_coordinates_matter` 가 False -> True 로 드러났다.

### §13 unit test 가 실제 결함 두 개를 잡았다

`challenge/tests/test_v2_keypoint_scores.py` (15 개).

1. **q 가 90 도 순열에 불변이 아니었다** (0.450 vs 0.358).  한쪽 변만 썼기 때문이다.
   마주보는 두 변의 평균으로 바꾸니 정확히 불변이 된다.

   바꿔(자기 자신 + 다른 한 점을 더 빼도 되는 적합 중 가장 관대한 값) 해결.

**V1 함수를 직접 import** 하도록 바꿔 갈라짐 자체를 없앴다 (V1 은 읽기만 한다).
