### Before/After — PnP solver (성능 critical)
- Before: grid decode 가 `annotate_pnp.solve_pose`(48-candidate 24-symmetry × IPPE
  6-face × LM refine) 호출 → 호출당 ~40ms, 100 config × 781 frame = 78k 호출 →
  58분+ 후 1h background limit 에 killed (json 미생성).
- After: fast core = `cv2.solvePnP(SOLVEPNP_ITERATIVE)` per-index 대응 × 110/130
  front 2-dim. 호출당 0.06ms(~600x), 전체 grid 5초.
- 근거: DOPE belief channel i = corner i 이므로 correspondence 이미 결정 →
  symmetry search 불필요(그건 수동 annotation 용). 부수적으로 더 정확
  (V=4 frame: solve_pose 301px 오대응 vs fast ITERATIVE 11px).

### 평가 메트릭 분리 (false-accept 노출)
- subset_reproj = 입력 subset 점 reproj (gate 용, GT 불필요, 배포 가능 신호).
- gt_reproj = 채택 pose 8 corner full projection vs 전체 8 GT median (정직, GT 필요).
- honest success = positive-depth & subset_reproj<reject & **gt_reproj<15px**.
  → planar 4점(V=4 한 면)은 subset_reproj 1px(완벽해보임)인데 gt_reproj 180~300px
  이므로 gate-only 성공률은 과대평가.

### 판정
- 판정지표(V=8 보존 + V<8 honest ≥20% / V6·7 ≥50%) **전부 미달**.
  - V=8 보존: D4/D0 OK (D3 는 V=8 FA 19% 오염).
  - V<8 회복: synthetic best 11%(D3)/7.6%(D4) < 20%. real V6-7 honest 25% < 50%.
- 결론: subset-PnP decode 단독으론 부족. 채택 시 **V<8 fallback 전용 +
  full-keypoint reproj-gate(치수 known)로 false-accept 제거** 필수. V=8 주경로는
  D0 유지.
- severe V=4(한 면)는 단안 RGB+postprocess 로는 planar 모호성 때문에 원리적 회복
  불가 → border supervision 학습 / 더 많은 truncation 증강 / depth 필요.
  (memory `dimsfree-2d-geometry-pl-filter-impossible` 와 정합.)
