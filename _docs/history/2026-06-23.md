## "NVIDIA처럼" 마지막 조각 — affinity 추론 사용 체크 (학습 X, decode만)

배경: base는 이미 정식 NVIDIA DOPE(belief9+affinity16, 둘 다 학습). 단 이 프로젝트 추론은 **belief peak만** 쓰고 affinity는 decode에 안 씀(`extract_keypoints_from_belief`=belief만, decode/PnP 경로에 affinity 사용 0). NVIDIA 정식 추론은 affinity로 greedy association. → "affinity를 추론에 쓰면 belief-peak보다 나은가?"가 유일한 미시험 NVIDIA 조각이라 싸게(학습X) 확인. base=`weights/challenge0123/final_net_epoch_0060.pth`. 스크립트 `scripts/stage0/eval_affinity_decode.py`, 결과 `data/pallet/eval_results/stage6_affinity/`.

**convention 정합 [확인]**: GT 생성(`utils_belief.py getAfinityCenter:79 angle=center-point`, `GenerateMapAffinity`) = 채널 2i,2i+1 = corner i→centroid 단위벡터, 순서 camera-facing 0123. detector(`detector.py find_objects:864~`)도 corner→centroid 동일 방향. belief채널 i↔affinity 2i 1:1 정합 — 재배선 불필요. sanity(synthetic 눈검증): affinity(빨강x)가 GT(초록)·belief(파랑) 코너에 겹침 = association이 올바른 코너 집음(garbage 아님).

- **왜 못 고치나**: real back 부정확 = belief map 자체가 back 코너를 부정확 예측(flat-view depth 붕괴, systematic). decode를 affinity로 바꿔도 **같은 부정확한 peak 후보 위에서 고르므로** 못 고침. memory "필터 천장=base 코너 정확도"·"flat depth 붕괴 systematic"과 정합.
- ⚠ 단일 config·중표본(real44/manual27) → "affinity 추론 절대 무용" 일반화 금지. 다중객체/오클루전 셋업에선 association 의미 있을 수 있음(미시험). 이 base·단일팔레트에선 corner 개선 無.

## ★ STEP7 sparse edge 벡터 (mask-free 판별) — (가) 벡터 불필요 확정

질문: dense voting이 진 게 마스크(데이터) 문제냐 벡터 자체 불필요냐. sparse(꼭짓점→꼭짓점 unit edge, global-pool→FC, **픽셀 마스크 완전 불필요**)로 우회 판별. 16 core edge(변12+면대각4), refine=mask-free least-squares(방향제약, scale=heatmap 고정). control vs sparse 둘 다 full 49k×10ep(§4 공정, 같은 스케줄). 밤샘 2-arm(control 12:42→15:53, sparse →19:14) rc=0. 학습 건강(L_bel 0.020→0.0096 개선·발산無, L_edge 1.07→0.24 수렴=edge head 학습됨, undertrain 아님).

```
                  ov_med  bk_med  good  gross   (refine win vs control)
filter-val(real)
  control-heatmap  10.5    17.0    14    1
  sparse-heatmap   10.6    17.0    12    6      ≈control
  sparse-refine    18.3    21.7     0   10      1/28  ← 더 나쁨, real back도
manual
  control          10.4    13.8    13    1
  sparse-refine    17.9    14.7     2   11      2/26
synthetic(1500)
  control           8.9     9.0   755   92
  sparse-refine    12.7    12.7   445  302      291/1237(~24%)
```
- **★ (가) 확정: sparse-refine(마스크 0)이 control-heatmap보다 전 셋 더 나쁨**(real back 21.7 vs 17.0, win 1/28). **마스크가 막은 게 아니다** — 마스크 자체가 없는데도 edge-벡터 위치추정이 heatmap에 짐. dense voting 패배는 마스크 탓이 아니라 벡터 접근 자체가 이 문제에 부적합.
- **sparse-heatmap ≈ control**(보조효과 無, STEP4 dense-aux와 정합).
- **왜**: back/flat 부정확은 heatmap·edge 방향 **둘 다 같은 depth-붕괴 feature**에서 나옴 → least-squares가 나쁜 edge 제약으로 좋은 front까지 끌어 오히려 악화. "방향을 몰라서가 아니라 depth 정보가 없어서"(정보 문제) 확증. affinity(STEP6) 결과와 정합.
