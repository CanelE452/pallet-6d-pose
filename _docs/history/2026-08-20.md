## [16:10] EDGE_HARD 학습 제외 해제 — DATA_ROLE_LOCK_V2

사용자 지시로 "corner 4개 이하라 못 쓴다" 제한을 해제했다. **기록은 덮어쓰지 않고
supersede** 했다 — V1 은 그 시점에 알던 것으로 옳았고 지우면 왜 바뀌었는지가 사라진다.

### ★ 해제 사유 — 사용자가 든 근거보다 강한 게 따로 있었다

사용자 근거는 "hough head 로 코너 없이도 잘 되는 걸 봤다" 였는데, 그 근거인 O12
감사(eval56 98.7% / 4.68px)는 **GT 선 oracle** 이다. 예측 선으로는 미검증이고
오늘 REAL_DEV 에서 F3 paired 개선은 R/t/ADD-S/IoU **네 지표 모두 CI 가 0 포함**이었다.
그래서 이 근거는 `[미검증]` 으로만 기록했다.

실제 해제 사유는 **배제 기준 자체가 범주 오류**였다는 것이다:

```
배제에 쓴 것    G1 게이트 V_vis >= 4        ← 평가에서 PnP 성립 여부를 보는 게이트
실제 감독 대상  n_supervised (화면 안 채널)  ← corner loss 는 가시성을 안 본다

EDGE_HARD_TRUNC 12,000 실측
  V_vis_actual      1:124  2:1,630  3:10,246          (전부 <=3)
  n_supervised      3:96  4:714  5:9,306  6:1,874 ...  → >=4 가 99.2%, 중앙값 5
  line_valid_roles  >=6 가 99.1%
```
즉 "4개 미만 코너로 pose 를 가르치게 된다 = 계약 위반" 이라는 V1 서술은 전제부터
성립하지 않았다. [[v-is-not-visible-count-three-counts-differ]] 의 귀결인데,
네 카운트를 구분해 놓고 정작 배제 규칙에서 다시 섞었다.

**한계 (결론 낼 때 반드시 붙일 것)**
- GT 0 → 오차·우열 정량 불가. 나온 수치는 자기일관성(두 경로 합치)뿐.
- 전처리는 plain squash. memory `dope-inference-needs-reflect-padding` 이
  "근접·truncation 에서 체계적 과소검출"이라 기록 → 낮은 검출이 **모델 실패가
  아니라 전처리 탓**일 수 있다. reflect-pad 로 다시 뽑기 전에는 단정 금지.

### §9 화면 밖 코너 — 두 경로의 출력 공간이 다르다 (사용자 질문)

질문: "점이 밖에 있어도 밖에 찍을 수는 있는 거야?"

```
경로                  화면 밖    근거                                    448 코너 실측 (56장 x 8)
────────────────────────────────────────────────────────────────────────────────────────────
belief (점 히트맵)     불가      _decode_peaks = argmax +- 3x3 무게중심   0개, 경계 초과 최대 +0.0px
                                -> 출력이 [0,49] 격자 안
CIGM (선 교점)         가능      solve_corners = 최소자승 linalg.solve    4개, 경계 초과 최대 +16.1px
                                -> 범위 제약 없음
```

★**능력은 있는데 방향이 반대다.**

```
GT 가 화면 밖인 코너 16개  ->  CIGM 이 밖으로 찍은 것   0개
GT 가 화면 안인 코너        ->  CIGM 이 밖으로 찍은 것   4개 (오차 27.7~49.9px)
```

★**§6 의 OFF_FRAME direct 118.0px 해석을 정정한다.** "화면 밖이라 구조적으로
도달 불가"로 읽으면 틀린다. GT 의 경계 초과폭 실측:

```
1.0(x6) 1.0 2.0 2.0 7.6 9.2 13.2 14.4 31.5 37.7 71.9   (px)
```
**대부분 1~2px 밖**이라 direct 가 원리적으로 못 가는 거리는 그만큼뿐이다. 118px
오차의 대부분은 구조적 한계가 아니라 그냥 틀린 것. 특히 `34532096 / 35089920 /
68820224` 의 코너 4·7 은 GT 가 겨우 1px 밖인데 direct 오차 145~283px — 화면
밖이라서가 아니라 far face 를 크게 틀린 것(§6(b) 의 far/depth 축과 같다).

O1(GT 점 + FINAL 선) = 3.39° 가 결정적 증거다. 점이 완벽해도 예측 선을 섞으면
3.4° 로 고정된다.

### 해석 = CASE C (강한 점에서는 악화)

F3 는 FINAL 자신의 약한 코너 위에서 검증됐다. 강한 코너 위에서는 **독립적 가치가

현재 형태의 fusion 이 강한 점과 맞지 않는다는 뜻이다.
