### 근본 원인 (라이브러리 소스까지 추적 [확인])

```python
# ultralytics 8.4.60  data/build.py:346
generator = torch.Generator()
generator.manual_seed(6148914691236517205 + RANK)   # ← args.seed 가 안 들어간다
```

이 FT 는 고정 가중치(G38 last.pt)에서 시작하므로 남은 무작위성은 **데이터 순서 +
worker 증강 RNG** 뿐이고 둘 다 이 고정 generator 에서 파생된다. 그래서 args.seed 를
바꿔도 학습이 완전히 동일하게 재현된다.

2차가 실패한 이유는 별개다 — `ultralytics.models.yolo.detect.train` 이 import 시점에
`from ultralytics.data import build_dataloader` 로 **자기 네임스페이스에 바인딩**한다.
원본 모듈만 갈아끼우면 trainer 는 옛 함수를 계속 부른다.

```
실측  _UB.build_dataloader is patched -> True
      _DT.build_dataloader is patched -> False   ← 실제 호출처
```

3차 패치는 `_UB/_UD/_DT` 를 전부 교체하고, 발동 기록을
`runs/*/DATALOADER_SEED_PATCH.json` 에 남겨 **먹었는지 확인 가능**하게 했다.
격리 시험(PATCH_FIRES, 6148914691236517204 → ...247)을 먼저 통과시킨 뒤 띄웠다.

★ 이 무효화는 **이 FT 실행 한정**이다. `CF_DATA_C_..._SEED42/43` 은 실제로 달랐다
  (different 749/879). 왜 그쪽만 달랐는지는 미확인 [추정: 60ep 에서 비결정 CUDA
  커널 누적, `use_deterministic_algorithms(warn_only=True)` 라 허용]. 만약 그렇다면
  그건 seed 효과가 아니라 **재실행 변동**이므로, 프로젝트의 seed 산포 주장은

### ★ 핵심 발견 — 좌표 잡음이 아니라 코너 번호가 돈다

N1 을 눈으로 보면(그림 확인 [확인]) AFTER 는 **박스도 맞고 코너도 파렛트 위에
찍혀 있다.** 틀린 것은 어느 점이 0/1/2/3 인지다 — 약 90도 돌아갔다.

```
                 TARGET   BEFORE    AFTER
yaw 오차           3.9deg   0.8deg   75.3deg   ← 75도 = 90도 회전 misassignment
corner_med        15.7px   16.3px   140.9px
```

N2(전형적 야간)는 세 모델 다 정상(yaw 3.9 / 0.6 / 2.9deg)이다. 즉 야간 p90 악화는
**전반적 정밀도 저하가 아니라 소수 프레임의 축 배정 실패**다. p90 은 나쁜 쪽 10%를
보는 지표라 이 소수가 그대로 잡힌다(median 은 16.4 → 16.8 로 거의 불변).

이는 기존에 알려진 실패모드와 같은 것으로 보인다 [추정 — 같은 원인인지 코드로
확인하지 않았다]: PLASTIC selector FAIL(83/140), W/D parity, 90도 교환.
→ 관련 memory: [[evaluator-receives-gt-per-frame-axis-assignment]],
  `_docs/paper/method.md` 의 object-specific pose gates.

### 판독 수정

"AFTER 는 정밀도를 잃었다" 는 **부정확한 요약**이다. 정확히는:

```
좌표 정밀도   거의 안 잃었다 (night median 16.4 -> 16.8px)
축 배정       소수 야간 프레임에서 90도 실패 -> p90 만 터진다
검출          크게 얻었다 (104 -> 130 / 140)
```

배포 영향: 코너 좌표를 PnP 에 그대로 넣으면 그 소수 프레임에서 **자세가 90도
틀린다**. 거리(t)는 비교적 견디지만 방향은 못 쓴다. 검출만 쓰거나 사람이 확인하는
용도면 문제 없다.

  DEV140 과 같은 모집단이지만 gap closure 의 matched 117장과는 다르다.
