### C4 permutation — 손으로 적지 않고 유도

3D vertex 를 `Ry(θ)` 로 돌린 뒤 원래 index 와 좌표 매칭(<1e-9)해서 복원했다.

```
  0도  [0, 1, 2, 3, 4, 5, 6, 7, 8]
 90도  [1, 5, 6, 2, 0, 4, 7, 3, 8]     ← canonicalize_fourfold_yaw 와 독립 유도로 일치
180도  [5, 4, 7, 6, 1, 0, 3, 2, 8]
270도  [4, 0, 3, 7, 5, 1, 2, 6, 8]
```

bijection · centroid 고정 · top/bottom 보존 · 12-edge 보존 · 90x2=180 · 180+90=270 ·
90x4=identity · inverse 일치 — 8 개 전수 PASS.

### 구현 — target 동치류 하나만 바꾼다

`calculate_keypoints_loss` 에서 C4 가 꺼져 있으면 곧장 `super()` 로 간다(그래서 F0 는
stock 과 bit-exact).  켜져 있으면 object 별 argmin branch 를 골라 `keypoints` 텐서의
keypoint 축을 **한 번의 gather 로** 재배열한 뒤 `super()` 를 부른다.  `[x,y,v]` 를
통째로 옮기므로 좌표와 visibility 가 갈라질 수 없다.  box/cls/dfl/TAL 은 손대지 않았다.

### MULTI_TEACHER 게이트 D — 융합 target 이 학생 학습을 차단했다

합의 임계를 합성 도메인에서만 동결: τ = 0.030 (box 대각선 대비),
"d ≤ τ 인 keypoint 의 합의 오차 p90 ≤ 대각선의 2%" 를 만족하는 가장 큰 d.
합성 val 통과율 19.7%.

★임계의 전이가 모집단마다 다르다.
```
SOURCE_DEV(합성 val)          0.1975
DEV_EVAL(real, visible)       0.1713   ← 합성과 거의 같다
TARGET_UNLABELED              0.0152   ← 11배 낮다
```
즉 도메인(합성↔실제)이 아니라 **풀의 성격**이 다르다. 미라벨 풀은 원본 주행 영상이라
불일치 중앙값이 0.359 로 DEV_EVAL 의 0.0528 보다 7배 크다. 미라벨 1,000장에서
usable keypoint 는 7,632 중 116 개(1.5%)뿐이다.

`DISTILL_TARGET_QUALITY = FAIL`. usable 부분집합(394, coverage 15.8%)에서
최고 융합 arm(F2 medoid)이 median 6.14 vs R0 5.80, p90 20.59 vs 20.14,
gross20 0.104 vs 0.102 로 세 항목 모두 나쁘다. session-cluster bootstrap 은
전부 0 을 포함하므로 "나쁘다" 가 해소된 것은 아니고 **"낫다는 증거가 없다"** 이며
점추정은 전부 나쁜 쪽이다.

기전이 분명하다 — 합의 필터는 R0 가 이미 맞힌 자리를 고른다
(usable 에서 R0 median 6.97→5.80, p90 60.31→20.14). 정답이 다른 교사에게 있는 자리는
정의상 교사들이 불일치하는 자리이고 그런 자리는 abstain 된다.

METHOD_LOCK 규칙에 따라 **학생 arm S0/S1/S2/S3 을 하나도 학습하지 않았다.**
τ 를 늘리거나 검사를 완화하지 않았다.
