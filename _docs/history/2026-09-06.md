### 결과

### 함정 두 개 (둘 다 이번에 한 번씩 걸렸다)

1. **`arccos((tr-1)/2)` 는 0 근방에서 1.2e-6도 미만을 못 잰다.** float64 에서
   sqrt(2·eps)=2.1e-8 rad 이 최소 눈금이라, 기계정밀도로 맞은 회전이 "1.207e-6도 오차"로
   찍힌다. 이걸 solver 수렴 실패로 오독해 damping·step 을 의심하는 데 한 사이클 썼다.
   실제로는 Frobenius 1e-16. 0 근방 회전오차는 `atan2(||skew||/2, (tr-1)/2)` 로 잴 것.
2. **사전등록 게이트에 '의미 있는 차이의 하한'이 없으면 1e-9 차이가 개선으로 센다.**
   D3 가 그래서 ACCEPT 로 찍혔다. 규칙을 사후에 고치지 않고 산출물에
   `indistinguishable_from_baseline` / `effective_reading` 필드를 추가해 구분되게 했다.

### 배선에서 실제로 걸린 것 (상세는 notes)

- YOLO 라벨 = `projected_cuboid` 원본 순서 + pad(100,100), centroid 가 index 8.
  이 학습셋은 perm_v4 미적용 — `broad40k_fixed` 와 다르다.
- 증강 대응: 영상면 affine A 에 대해 `K' = A K` 로 보정. A 는 소스 2D 와 배치 GT 2D
  대응에서 최소제곱 복원.
- `fliplr=0.5` 이 keypoint 인덱스를 `flip_idx` 로 바꾼다 → 두 대응 다 풀고 잔차 낮은 쪽
  채택. 감독률 55% → 98.9%.
- mosaic 은 `im_file` 을 대표 1장만 남겨 3/4 인스턴스가 어긋난다 → affine 잔차 게이트로
  마스킹. R0 레시피(mosaic 켬) 감독률 19.4%.
- ★`E2ELoss` 는 `__call__` 이 아니라 `loss()` 를 부른다. `__call__` 만 덮었더니 항이 한 번도
  계산되지 않았다(스모크 통계 0). 둘 다 덮어 one2many·one2one 양쪽 적용 확인.
- 정규방정식 절대 릿지(1e-8)가 affine 해에 편향을 남김 → 상대 릿지 + Hartley 정규화로
  잔차 3.6e-6 → 1e-6 미만.

### Q0 (lambda 선택)

값 비율이 아니라 `pred_kpts` 기울기 노름 비율로 선택. λ=1 에서 4.5%(목표 5%), 5% 대응
λ 중앙값 1.13, IQR 0.079~3.78(산포 48배). λ\*=1.0 채택.

  서로 다르지만 그 아래 topology 는 4개 — 스케일 랜덤화는 mesh 다양성이 아니다.

  `elev<8 AND 두께<=0.0923` 셀의 유효자산수 1.01, `elev<8 AND 대형 AND thin` 은 1.00.
  4자산 균등 노출(유효 4.00)은 앙각 >=30° 구간에만 있다.
- real 실패는 앙각이 지배: NME 실패 <3° 51.9% / 3~8° 50.9% / >=30° 14.1%.
  야간 효과는 앙각 통제 후에도 남는다(DAY elev<15 38.4% vs NIGHT elev<15 50.0%).
- 야간 격차는 휘도가 아니라 대비/하이라이트다. 어두운 프레임은 source 가 더 많고
  (37.5% vs 23.8%), "어두우면서 대비>=68" 은 real 야간 62.3% vs source 8~10%.
  `scene_preset` 은 휘도를 전혀 가르지 않는다(day/indoor/night 모두 p50 53).
- 가림·truncation 은 source 가 real 보다 많다 → 격차 아님.
- generic 40,000 의 `camera_distance_actual_m` 최소 1.5001 m, <1.5 m 0건(렌더러 하드 바닥).

  6D 는 세 arm 전부 미측정 → 현재 병목(localisation)을 겨냥하지 않는다.

  자산 다양성은 교란이 아니다. 그러나 A42 는 패딩 안 된 이미지에 패딩 기준 라벨을 붙인
  run 이라(코너 중앙값 40.1px 어긋남) 낮은 기준선이 망가져 있다 — 장수 효과로도 못 읽는다.
