# 팔레트 점·선 연구 누적 결과 및 v5 제공 코드 검토

검토일: 2026-09-12(KST). 목적: 합성 학습 기반 팔레트 인식의 실사 정확도를 개선했다는 근거가 어디까지 있는지, 현재 코드를 그대로 다음 실험에 사용할 수 있는지 판단한다.

## 0. 판정과 검토 경계

**v4의 저장 결과와 중단 판단은 다시 재현됐다. v5의 실제 팔레트 학습 결과는 이번에 확보하지 못했다. 대신 제공된 v5 원본 코드를 직접 검사해 기존 72개 테스트 통과와 별개로 5가지 설계·검증 공백을 재현했다.**

현재 확인한 원격 브랜치:
- main: `6a68452ea9a17a69860981fea1c5a3dc234e3dfa`
- research/pallet-point-line-v4: `bc22bdfa79a97b50e5f236bd31dc26b69fd2303d`
- exp/y26_pose_arch_20260825: `96ddf1967ecee2759e5d36578a84f2e4eb021efe`

두 앞 브랜치에서 지정 v5 결과 경로를 조회했지만 404였다. 대화·Library 검색에서도 v5 지시문은 확인했으나 새 실행 보고서는 확보하지 못했다. **이것은 로컬 v5 미실행이나 실패의 증명이 아니다.** 원래 지시문이 commit/push를 금지했으므로 로컬 결과가 따로 있을 수 있다. 현재 v5 실행본이 제공 코드와 같은지, 수정됐는지도 미확인이다.

이번에 한 일:
1. 이전 v4 검토 ZIP의 GT·예측 좌표·점수·학습 trace 재계산.
2. v5 원본 ZIP 무결성 확인 및 기존 테스트 재실행.
3. 새로 만든 생성 기하/입출력 계약 반례 검사. 이 추가 진단의 optimizer update=0, 실사 forward=0.
4. 원본 코드·학습 결과 변경=0. 추출 사본에 테스트 cache는 생성될 수 있다.

v5의 기존 pytest에는 생성 데이터의 CLI 통합 테스트 학습 3군×2step이 포함된다. 그것을 실제 팔레트 학습으로 보고하지 않는다. 새 v5 9개 본학습을 수행하지 않았다.

## 2. v4 재계산: 핵심 숫자는 맞고 성공 판정은 여전히 아니다

- 431개 제한된 assertion 모두 통과.
- GT tensor2,560개 SHA 확인.
- 기록된24,000 optimizer step의 배치 계획·손실 성분·감독 수 재검산.
- 12개 군/seed의 저장 출력에서 8코너·9점 지표 재계산: 원본 픽셀 요약/프레임 평균 최대 차이0.

### 실제 손익

`f7377`: 원래 same-ID 평균133.606121px → 공통 bank의 순수 번호 재배열 후보5.024358px → H 선택5.339696px. H의 추가 코너 이동은9.103686px이고 순수 재배열보다0.315338px 악화했다.

따라서 이번 성공 장면은 선 교점 정밀보정의 증거가 아니고, 한 장의 잘못된 번호 변경이 다른 장의 큰 개선보다 손해를 크게 만들었다.

원래10px 이하3,743코너 중 H1손상8개=0.2137%여서 기존1%안전조건은 통과했다. **손상비율만으로 손상 크기를 제한하지 못한 것은 원래 계획의 한계**다. 다만 평균기준이 실패를 잡았으므로 기존판정은 보존한다.

순수 번호 변경으로 오차를 줄일 수 있는8장 중7장은 H의 세 seed에서 문턱 적용 전부터 잘못된 원래 번호 후보를 선호했다. 해당 subset에서는 랭킹 실패가 확인된다. 1/8이라는 횟수만으로 무작위보다 나쁘다고 확정하거나, 모든 장면의 번호 식별이 불가능하다고 결론내리지 않는다.

## 3. v5 원본: 잘 구현된 부분과 검증 공백

이번 원본 ZIP 무결성검사41파일PASS, 기존테스트72 passed. 확인한 코어는 물체좌표계/치수/대칭, 실제 DHT누적, 영상 기반 여러 초기자세, 고정단계 점·선 자세계산, GT-free추론의 실행 경로를 갖는다. 빈 함수나 단순 문서만 있는 패키지는 아니다.

그러나 테스트 통과가 설계의 충분성은 아니다. 추가검사5개는 모두 제공한 원본에서 재현됐다. CLI가 실제 실행 전에 수정했는지는 미확인이다. **아래 문제를 미제출 v5실험의 실패 원인으로 확정하지 않는다.**

### V5-01. 무정보 선이 정확한 자세를 훼손한다

생성 cuboid fixture에서 정확한 점과 정확한 초기자세를 두고 모든 유효 line bin에 동일 score0을 넣었다. optimizer0회, 실사/RGB 성능시험 아님.

| 같은 생성조건 |점8개 평균오차|이동오차|수치pose_valid|
|---|---:|---:|---|
|point-only, line_weight0|0px|0m|true|
|flat line scores + line_weight0.25|4.607150px|0.162184m|true|

2,056개 유효bin/역할에서3개 mode를 선택했고, 12역할×3=36mode를 모두 valid로 처리했다. 첫 역할의 남겨진 mode가중치는0.307692/0.346154/0.346154였다. 원래의 ‘어느 선도 더 지지하지 않는’ 분포를 구체적인 소수선 가설로 바꾸고 그 가설들에 전체질량1을 다시 배분한다.

수치목적함수는19.374573→18.960662로 감소했지만 실제기하오차는 증가했다. 따라서 optimizer가 내려갔다거나 pose_valid=true라는 사실이 정확도 향상을 뜻하지 않는다.

### V5-02. 학습과 추론이 후보 유효성을 다르게 사용한다

`solver.py`는 `candidates_valid`를 정하고 무효후보를 최종선택에서 제외한다. 반면 `objective.py::compute_loss`는 모든후보의 energy에 softmax를 적용하며 해당mask를 읽지 않는다.

통제된 출력계약fixture에서 후보0은 valid/이동오차0.2m/energy5, 후보1은 정확한기하지만 ineligible/energy0으로 두었다. 학습은 후보1에99.3307%질량을 주고 pose-only loss0.000783이었으며, 후보1 valid flag를 바꿔도 loss는 같았다. 추론정책은 후보0을 선택하므로 이동오차0.2m다.

이는 실제solver가그후보쌍을생성했다는실험이 아니라 **반환된유효성계약을loss가무시함을보인직접검사**다.

### V5-03. seed 사이에 서로 다른 데이터 계약을 평균낼 수 있다

`assessment.py::compare`는 같은 seed의 reference/method 사이 manifest SHA는 대조하지만, 서로 다른 seed 사이의 manifest 동일성은 강제하지 않는다. 같은 ID 문자열을 쓴 서로 다른 manifest를 두 seed에 제공해도 비교 JSON을 출력하는 fixture가 재현됐다. 실제 v4/v5에서 모집단이 섞였다는 뜻은 아니다.

### V5-04. NaN GT 이동이 사전 산술 검사를 통과한다

`io.py::audit_manifests`는 GT 회전과 유효한 2D 점은 검사하지만 GT 이동 t가 유한한지 명시적으로 검사하지 않는다. t를 NaN으로 하면 투영 오차도 NaN이고 `NaN > 0.1`은 false라 차단되지 않아 최대 오차0과 산술 PASS를 반환한다.

단, **compute_loss는 GT t 유한성을 확인하므로 후속 학습에서는 중단된다.** 이는 preflight PASS 범위의 공백이지 조용한 학습 오염 증거가 아니다.

### V5-05. 저장된 2D 좌표와 자세의 일치·적법성 확인이 부족하다

`assessment.py::evaluate`는 저장 `pose_valid`와 2D 좌표의 유한성을 신뢰한다. 올바른 GT 2D 점과 `R=2R_gt`를 함께 넣은 출력 fixture도 수락됐다. 행렬식8인 비회전행렬인데 주지표0, 회전오차0도, 이동오차0m, 유효프레임1개로 보고됐다. 별도 cuboid ADD는0.854766m였다.

정상 model.forward는 회전을 검사하므로 실제 출력에서 이 오류가 발생했다고 단정하지 않는다. 파일 결합/변환 경로를 검증하려면 평가 단계에서도 회전 적법성·양의 깊이·재투영 일치를 확인해야 한다.

## 4. 현재 결론

**결과로 지지됨:** 기존 DHT 계열은 특정 실사 DEV에서 Direct보다 선을 더 잘 예측했다. 국소 선 분기로 점·이동의 부분적인 개선도 있었다. v4는 일부 번호 배치를 교정했지만 정상 프레임을 훼손해 seed 안정성 조건을 넘지 못했다.

**미확립:** 일관된 DHT 추가 기여, 치수·대칭을 넣은 v5의 실제 팔레트 성능 향상, 독립 실사 일반화, 실제 online 전체 학습의 승격.

**이번 새 진단이 지지하는 것:** 번호 정의만 해결해도 남는 공통 선 활용·학습 선택·평가 계약 문제가 v5 원본에 있다. 균등한 선 점수 예제는 수치 최적화 성공과 물리 오차 개선이 갈라질 수 있음을 보였다. 나머지 입출력 검증 공백은 실제 발생 여부와 별개로 자동 감사의 보증 범위를 제한한다.

**권고 순서:** 실제 v5 실행 ZIP과 원본 대비 diff 확보 → 해당 실행본에 위 문제가 남는지 확인 → 기존 저장 결과의 분모·좌표·자세·seed 검증 → 확대 여부 결정. 원본의 결함을 이유로 미제출 실험을 통째로 실패라고 처리하거나, 원본 테스트72개를 이유로 실제 실험을 승인하지 않는다.

## 5. 재현

`audit_v5_repro.py`는 제공된 v5 소스로 실행한다. PyTorch와 NumPy가 필요하다. 실제 팔레트 이미지·가중치를 읽지 않고 생성 fixture만 쓴다.

이 문서의 새 수치는 코드 반례 또는 이전 v4 재계산이다. 새 v5 학습·실사 결과처럼 인용하지 않는다.
