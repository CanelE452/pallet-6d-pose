# SYNTHETIC_DECISION — 새 합성 데이터를 만들 것인가

지시문 §23 · §24 · §25.  **새 렌더 0회 · 새 학습 0회.**
전수 근거는 `SOURCE_DIVERSITY_AUDIT.md` 와
`data/pallet/results/next_accuracy_v2/SOURCE_DIVERSITY_AUDIT.json`.

## 1. §23 의 세 조건 대조

지시문은 셋을 **모두** 만족할 때만 새 렌더를 연다고 했다.

```text
1. corrected real-GT 실험이 저앙각 supervision 효과를 지지      -> ★부분 충족
     §11: real supervision 은 저앙각을 움직인다 (contract − R0 <8 Δ+2.70 px [+1.73, +3.04]).
     §13: 그러나 **regime-matched 는 아니다** — 8-15 로 학습해도 8-15 평가에서
          더 낫지 않다(3.43 대 2.74).  "저앙각을 겨냥하면 저앙각이 특별히 좋아진다" 는
          지지되지 않는다.  관측된 것은 "저앙각 프레임이 두 층 모두에서 더 나은
          학습 데이터" 라는 약한 형태다.
2. 그 레짐의 synthetic structural diversity 부족이 확인         -> 충족
     <8 의 effective asset 1.693 대 >=15 의 3.998 (같은 4-mesh pool)
3. existing pool 의 resampling 만으로 그 다양성을 못 만든다     -> ★부분 충족
     R0 안에서는 못 만든다.  그러나 R0 **밖에** 안 쓰인 pool 이 있다.
```

## 2. 장수는 부족하지 않다 — 다양성이 부족하다

```text
R0 60,000장 앙각 분포
  <3      3,658   6.1%
  3-8    14,256  23.8%      -> <8 합계 17,914 = 29.9%
  8-15    7,732  12.9%
  15-30  10,029  16.7%
  >=30   24,325  40.5%
```

[확인] 저앙각 프레임은 R0 의 **29.9%** 로 결코 희소하지 않다.
문제는 그 중 82.8% 가 단일 mesh 계보(P0/TEX)에서 온다는 것이다.

```text
층       프레임   고유 asset  effective(exp entropy)  최대 점유
<8      17,914       4           1.693              0.871  scene.usd
8-15     7,732       4           2.836              0.644
>=15    34,354       4           3.998              0.263
```

[확인] **다양성이 무너지는 곳은 저앙각뿐이다.**  같은 4-mesh pool 인데 유효
다양성이 2.4배 낮다.  §25 대로 프레임별 W/D/H 스케일 랜덤화는 새 asset 으로 세지
않았다 — `<8` 안에서 `scene.usd` 는 두께 0.058~0.166, footprint aspect 1.00~1.61 로
늘어나 있지만 그것은 같은 mesh 다.

## 3. ★ 지시문이 지목한 cell 정의가 실데이터와 어긋난다

지시문 전제 7 은 "저앙각 × thin × **large**" 를 실패 cell 로 지목했다.

```text
corr(앙각, 투영 크기)     실데이터 +0.923      합성 −0.131
저앙각 × thin × large     합성 4,909장(8.18%)  실데이터 2장(0.24%)
```

[확인] 지게차 카메라 높이가 고정이라 **실데이터에서 저앙각은 곧 원거리이고
투영이 작다.**  실제 실패 레짐은 저앙각 × **small** 이다.
합성은 저앙각 × large 를 이미 과잉 공급하고 있다(8.18% 대 0.24%).

→ **그 cell 을 그대로 렌더하면 실데이터가 점유하지 않는 영역을 채우게 된다.**
새 렌더를 열기 전에 cell 정의를 고쳐야 한다.

부수 발견: `broad_family_v2` 는 두께 0.0923(registry 110x130x11)을 목표로 하는데
`live_capture_gt` 851장의 실측은 0.1364 다 — **다른 물체다** [확인].

## 4. 렌더 없이 지금 쓸 수 있는 것

[확인] `paper_release/oblique/extracted/corner_la_oblique_v1_{y15_30,y30_plus}`
5,000장이 **100% `<8도`**, 유효 asset **3.996** 이다.
폴더명의 `y15_30` 은 앙각이 아니라 방위각이라 그동안 오독됐다.
삼중 cell 안에도 621장이 유효 3.678 로 들어 있다.
저장소 전체 grep 에서 `challenge/yolo_pose_one_model/` 아래 사용처가 **0건**이다.

이 pool 을 접어 넣으면 저앙각 유효 asset 이 1.693 에서 크게 오른다 — **렌더 비용 0.**

미확인: `edge_complement_v1` zip 4개(약 11,000장)의 앙각 분포는 열지 않았다.

## 판정

```text
TARGETED_SYNTHETIC_NEEDED = NOT_YET — 렌더 전에 공짜 pool 로 먼저 시험한다
```

네 줄 근거:
1. 저앙각 실패 레짐의 구조적 다양성 부족은 **실재한다** (effective 1.693 대 3.998).
2. 그러나 §13 이 regime-matched 효과를 지지하지 않아, 렌더의 근거가 지시문이
   예상한 것보다 약하다.
3. 그리고 첫 수는 렌더가 아니다 — 안 쓰인 5,000장(100% `<8도`, 유효 3.996)이
   이미 디스크에 있다.  이걸로 "저앙각 asset 다양성이 실제 held-out 을 움직이는가" 를
   **렌더 비용 0 으로** 시험할 수 있다.
4. 렌더를 하게 되더라도 지시문의 cell 정의(`large`)를 **먼저 고쳐야** 한다 —
   실데이터의 저앙각은 원거리·작은 투영이다(corr +0.923).

§24 대로, 렌더를 하게 되면 40K -> 80K 같은 **장수 증가로 만들지 않는다.**
총 N 을 고정하고 실패 cell 의 composition 만 바꾼다.
