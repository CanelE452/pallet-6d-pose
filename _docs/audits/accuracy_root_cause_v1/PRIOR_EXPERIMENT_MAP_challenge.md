**실제로 무엇을 반증했는지** 와 **반증하지 못한 것** 을 분리한다. 실패 개수 세기가 아니다.

## 표기 규약

- 모든 사실 문장 끝에 `[확인]`(artifact 원문에서 직접 읽음) / `[추정]`(주석·명명·정황에서 추론, 미검증) 을 붙인다.
- `actual_verdict` 앞의 분류 태그:
  `(a)` 실제 실행해 실패 · `(b)` 다른 population 에서만 실행 · `(c)` oracle 에서만 성립 ·
  `(d)` evaluation contract 문제로 판정 불가 · `(e)` 단일 seed/config 에서만 실패
- 풀어 쓴 내부 용어: `cbox` = correct-box (예측 box 와 GT cuboid bbox 의 IoU ≥ 0.5),
  `R+ / RW` = 같은 실제 프레임 안의 정답 후보 / 오답 후보, `RN` = 실제 negative 후보,
  `S+ / SW` = 합성에서의 같은 쌍, `P3/P4/P5` = FPN 의 세 출력 level,
  `TAL` = Task-Aligned Assigner(YOLO 의 라벨 배정기), `q_pose` = 예측 pose 품질 스칼라,
  `gross20` = 코너 오차 20px 초과 비율, `5cm5` = 5cm·5도 동시 성공률.

- **adaptation pool 의 구성이 병목이다.** 여러 교사 트랙에서 미라벨 풀의 교사 불일치 중앙값이 `DEV_EVAL` 의 7배였고, 합의 게이트 통과율이 SOURCE_DEV 0.1975 → 미라벨 풀 0.0152 로 무너졌다 [확인]. 풀 자체를 바꾸는 개입(어떤 프레임을 모을 것인가)은 **한 번도 실행되지 않았다** [확인].
- **source 합성이 실제의 distractor 종류를 담고 있지 않다.** source 의 hard pair 는 87~95% 가 같은 물체의 duplicate 인데 실제는 75~87% 가 진짜 원거리/근거리 distractor 다 [확인]. 이 종류 불일치를 합성 배경 쪽에서 메우는 개입은 미실행이고, pairwise audit 이 다음 단계로 지목한 FAR_DISTRACTOR 특성화도 미실행이다 [확인].
- **야간(NIGHT) appearance 축.** 모든 계열에서 NIGHT 이 최악이고(top1-cbox 0.286~0.679, n=28) 표현 감사에서도 합성-실제 gap 이 NIGHT(0.934) > DAY(0.894) 였다 [확인]. 그런데 야간 데이터 자체를 늘리거나 야간 appearance 를 합성에 넣는 실험은 이 지도의 어느 행에도 없다 [확인].
- **point localization 이 붕괴한 subset.** same-real 128 중 88장(69%)의 corner median 이 ~89px 다 [확인]. orientation 보정(Hough/line)·solver 교체·조건부 gate 어느 축도 이 구간을 목표로 설계되지 않았다 [확인].
- **broad40k 의 분포 결함을 고친 재렌더.** 정사각 프레임 6.9%, target 두께비 이하 0.29%, 실제 plastic 치수 20% 이내 TRAIN 프레임 36장(10% 이내 0장) [확인]. 조건부 C4 Stage A 재학습·`DIM_PROBE_SYNTH`·`BROAD_FAMILY_V2` spec 전부 미실행이다 [확인].
- **negative 를 positive 와 혼합한 구성, 그리고 1,900 미만의 negative 비율.** 선별이 유효하다는 것은 확인됐고 대가(positive confidence 붕괴)만 남았는데, 그 대가를 줄이는 두 가지 방향(비율 축소 / positive conf 재보정 병행)은 모두 미실행이다 [확인].
- **다중 seed 재현.** arch baseline · posecls · inference path · C4 · DiffPnP 가 전부 seed 1 이다 [확인]. line branch 의 seed 산포가 15~19% 로 알려져 있어 [확인], 20% 미만 효과를 단일 seed 로 주장할 수 없는 계열에서는 "실패" 도 확정이 아니다 [추정].
- **60 epoch 확대.** posecls(30ep 에서 STOP), hard negative(10ep), DiffPnP(10ep) 모두 짧은 예산에서 중단됐고, DiffPnP 문서는 "60ep 에서 뒤집힐 가능성을 배제하지 못한다" 를 명시적으로 남겼다 [확인].
- **축 가설 선택기(`select_pnp_hypotheses`) 교체.** solver swap 은 read-out 만 바꿨고 선택기는 SQPnP 그대로였다 [확인]. 치수 probe 의 oracle 은 이 선택기가 59.29% → 100% 로 갈 여지를 보였다 [확인].
- **배포 config 의 치수 오류 수정.** `newauto` 가 1.000 × 1.200m 인데 실측은 1.10 × 1.10m 다 [확인]. 정사각 물체를 직사각 모델로 PnP 하는 상태라, 현재의 FSM 흔들림 원인이 keypoint 품질인지 config 인지 분리되지 않는다 [확인]. 수정 비용은 config 두 줄이다 [확인].
- **GT 축배정 없이 성립하는 합성 pose 평가 계약.** `model corner i ↔ projected_cuboid[7 − perm_v4[i]]` 이고 `perm_v4` 는 GT 전용이라, 합성 pool 에서 pose 기반으로 lambda·gate·architecture 를 고르는 것이 전부 불가능하다 [확인]. 이 계약을 고치면 adaptive Hough 를 포함해 "판정 불가" 로 닫힌 트랙들이 재개 조건을 얻는다 [추정].
- **keypoint 품질을 랭킹에 넣되 절대 target 을 깨지 않는 설계.** 절대 target 을 q_pose 로 곱하는 방식(Y1)은 반증됐고 [확인], 상대 순서만 강제하는 pairwise 는 source 신호 부족으로 학습조차 못 했다 [확인]. 두 극단 사이의 설계 공간은 비어 있다 [추정].
