# 논문 트랙 선행 실험 지도 (PRIOR_EXPERIMENT_MAP — paper)

작성 2026-09-06. 목적은 "실제 정확도를 막는 binding constraint" 를 확정하기 위한 상류 감사다.
실패 개수를 세는 문서가 아니라, **각 실험이 실제로 반증한 것** 과 **반증하지 못한 것** 을 분리하는 문서다.

읽는 법 세 가지.

1. 모든 사실 문장에 `[확인]`(artifact/코드에서 직접 봄) 또는 `[추정]`(해석) 태그를 셀 끝에 붙였다.
   문서에 값이 없으면 `UNKNOWN` 이고, 추측으로 채우지 않았다.
2. `actual_verdict` 앞의 괄호 태그는 실패의 **종류** 다.
   `(a)` 실제 실행해 실패 · `(b)` 구현됐지만 다른 population 에서만 실행 ·
   `(c)` oracle(GT 사용) 에서만 성립 · `(d)` evaluation contract 문제로 정식 판정 불가 ·
   `(e)` 단일 seed / 단일 config 에서만 실패.
3. 이 표의 핵심 열은 `what_it_does_NOT_rule_out` 이다.
   "한 pose-aware loss 실패 ≠ 모든 loss 실패", "median/medoid 다교사 융합 실패 ≠ 다른 교사에
   유용한 정답 정보 없음" 같은 구분이 여기에 들어간다.

내부 약칭은 처음 등장할 때 풀어 쓴다.
PPD = Pallet Polarity Detector(학습형 5-class semantic line polarity head) ·
PCR = Pallet Corner Role(코너 역할 보조 loss + FiLM) ·
VCR = View-Conditioned Residual(시점 조건부 heatmap bias 보정) ·
PGBC = Pallet Graph Belief Corrector(frozen feature 기반 belief 보정기) ·
SAI = Semantic Axis Initialization(semantic line 으로 회전축 후보 생성) ·
CGR = Continuous Geometry Refinement · DGP = Differentiable Geometry Pose(semantic line energy 최적화) ·
CIGM = Corner-from-Intersecting-Geometry Module(line 교점 → corner 변환) ·
MSL = Mask-Supported Line · LOO = Leave-One-Out(코너 하나 제거 후 재투영 일관성).

## 반증되지 않은 채 남은 가설

위 표에서 `(b)` 다른 population 에서만 실행 · `(c)` oracle 에서만 성립 · `(d)` evaluation contract 문제로
판정 불가 · `(e)` 단일 seed/config 로 분류된 항목들이 남긴 **열린 가설** 이다.
"실패했다" 로 닫혀 있지 **않은** 것들이므로, 다음 실험의 후보는 여기서 나온다.

1. **학습 신호 자체를 고치는 갈래가 통째로 미실행이다.** 세 개가 같은 곳을 가리킨다 —
   (i) real F2(confidently-wrong far corner) 분포를 담은 학습 소스: synthetic pool 의 far error 는
   median 2.12px / max 16.02px 이고 >20px 프레임이 0개라, real 의 43.3px 짜리 실패에 대해
   residual·backbone·loss 어느 후보도 **판정된 적이 없다**(B1 은 FAIL 이 아니라 NOT TESTABLE).
   (ii) truncation augmentation 재설계: 현 증강은 belief 데드존을 회피하려고 모든 코너를 중앙
   [0.20,0.80] 밴드로 밀어넣어 real truncation(outside 27.5%)과 분포가 겹치지 않는다.
   (iii) `clip_at_border=True` 수정: 존재하고 정확하며 하위호환인데 게이트상 **구현 보류** 다.
   `(b)`

2. **저앙각 학습 분포 + target 클래스 불균형을 교정하면 학습형 semantic line polarity(PPD)가
   real 로 전이되는가.** PPD 는 real 0.023(반-상관)으로 실패했지만 같은 셋에서 oracle 은 3/86 이다 —
   표현의 정보량은 이미 입증됐고 학습 조건만 시험되지 않았다. 학습 root 는 V=8 full-view 100% ·
   truncation 0% 인데 real 은 94%가 <8° edge-on 이고, base positive-frame rate 0.975~0.985 vs
   top 0.620~0.685 의 불균형은 class weight/oversampling 으로 한 번도 교정되지 않았다. `(a)+(c)`

3. **backbone 을 푸는 fine-tune 이 corner 판별 정보를 만들어내는가.** PGBC G1 의
   "표현에 답이 없다" 는 **frozen vgg trunk 50x50 한정** 결론이고, 더 얕은 고해상도 층도 미조사다.
   문서 스스로 frozen 전제를 깨는 것이 이 결론과 모순되지 않는 유일한 방향이라고 적었다. `(a) 범위 한정`

4. **view 다양성이 있는 촬영에서 viewpoint-conditioned bias 가설이 성립하는가.**
   VCR Gate 0 은 8 session 중 6개가 azimuth span <6°, 전 session 이 elevation −7.7~9.0° 라 LOSO 가
   외삽이 됐다. "가설이 틀렸다" 가 아니라 **검정 불가** 이며, robust(Huber/median) 회귀도 미시험. `(d)`

5. **corner-role 표현이 real 로 전이되는가.** PCR 은 Gate A(32 frame, 600 step, 단일 seed)에서 멈춰
   N87 접근 0회다. capacity 미달이 표현력 부족인지 최적화 예산 부족인지도 분리되지 않았다. `(e)`

6. **제대로 가중된 corner supervision 이 shared trunk 에서 line 을 돕는가.**
   A1 의 λ_corner 는 step-0 gradient 비율로 잡혔고 학습 중 약 35,000배 붕괴해, corner loss 가 실제
   기여한 양은 line gradient 의 약 2e-05 였다. 의도한 0.75 비율(λ≈1,300)은 시험되지 않았다. `(e)`

7. **E3_SPLIT_LATE 가 seed 2 에서도 재현되는가.** 이 연구의 유일한 양성 후보다 — corner +18.9% ·
   rotation +7.6% · translation +18.7% · 5cm5deg 0.078→0.147, 게다가 systematic geometry 9개 지표가
   전부 옳은 방향으로 움직였다(등방 수축의 절반을 oracle 없이 회수). 25k 확인은 seed 1 뿐이고,
   이 연구에서 단일 seed 판정이 이미 2번 뒤집혔다. `(e)`

8. **systematic 2D bias 를 직접 겨냥한 설계.** 두 갈래가 oracle 로만 열려 있다 —
   (i) per-frame scale: 등방 축소 4~5% 는 translation 의 단일 최대 레버이고 oracle 로 고치면 joint
   solver 가 처음으로 point-only 를 두 축 모두에서 이긴다. 상수 보정(1.029)은 실패했지만
   **per-frame 예측** 은 별개 문제다. (ii) rho(line offset) bias: theta 는 이미 충분하고
   (oracle 치환이 오히려 악화) rho 만 GT 로 바꾸면 rotation·translation 이 둘 다 좋아진다.
   rho 를 겨냥한 loss/parameterisation 은 미시험. `(c)`

9. **G2 deployable 과 축 부호 disambiguation.** line 의 marginal contribution 과 solver 자체 효과가
   아직 한 번도 분리 측정되지 않았다(코드·gate·prior 는 준비돼 있고 막은 것은 계산 시간이다).
   그리고 vertical 축 부호는 line 기하만으로 원리적으로 불가능한 것이 확립됐지만,
   상하 비대칭 evidence(포크 슬롯/그림자/접지선) · ground plane prior · 후보별 mask/appearance
   재순위는 전부 미시험이다. `(b)+(a) 범위 한정`

10. **교사 불일치를 좌표 생성이 아니라 거부(rejection) 축으로 쓰는 설계 / adaptation pool 의 구성.**
    다교사 융합은 좌표를 못 주지만 "어디가 틀렸는지" 는 AUC 0.79 로 안다(R0 자기 confidence 0.658).
    **좌표 median/medoid 융합 실패는 다른 교사에 유용한 정답 정보가 없다는 뜻이 아니다** —
    oracle-best 는 R0 gross 코너의 30.3% 를 10px 로 맞힌다. 동시에 미라벨 풀의 교사 불일치
    중앙값이 DEV_EVAL 의 7배라, 병목이 방법이 아니라 **pool 구성** 일 가능성이 잠긴 범위 밖으로
    남아 있다(full-site 확대는 `NOT_RUN_AND_NOT_PLANNED`). `(c)+(b)`

11. **positive control 두 개가 미실행이고, 둘 다 이유가 다르다.**
    (i) `paper_real_ft_v1` — 같은 예산에서 라벨 출처만 real manual GT 402장으로 바꾸는 실험이
    착수 전 중단됐다. 이유가 결정적이다: 402 중 **106장(26.4%)이 좌우 코너 순서 규약을 위반**하고
    **187장의 `keypoint_annotations` 가 90° 순열만큼 stale** 이다 — 즉 **고치려는 실패 모드가
    라벨 자체에 들어 있다.** 설계상 어느 쪽으로 나와도 결론인 실험인데, "라벨 품질은 병목이 아니다"
    라는 사전 선언된 실패 해석은 **얻어진 적이 없다.**
    (ii) `paper_strong_teacher_v1` — 설계된 medium 용량 source teacher(T1)와 3-teacher 합의가
    **만들어지지 않았고**, 측정된 2-view flip 합의는 모집단을 맞추면 오히려 꼬리가 나빠진다
    (p90 0.0993 vs 0.0784). gate 정의 문서로 인용된 프로토콜 파일은 저장소에 존재하지 않는다. `(b)`

12. **evaluation contract 변경 때문에 적용범위가 다시 열린 판정들.** 2026-09-04 에
    `POSE_METRICS_STATUS` 가 BLOCKED → REPORTABLE 로 바뀌어, 그 이전에 "pose 는 못 잰다" 를 이유로
    2D 지표로만 판정된 실험들의 적용범위가 열렸다 [추정]. 그리고 `_docs/EVAL_SET_CANONICAL.md` 가
    07-29~08-04 PAPER_S2 스크린 전부의 적용범위 표기가 틀렸고, 경계에 가까웠던 판정
    (predseed DiffPnP GT reproj +4.5%, VCR Gate 0 일부)은 재평가 대상이라고 사후 기록했다. `(d)`

## 이 감사에서 새로 드러난 두 가지 (taxonomy 와 무관하게 중요)

### 1. 논문 트랙에 봉인된 held-out 셋이 남아 있지 않다 [확인]

`data/pallet/results/paper_eval_v1/EVALUATOR_CONTRACT.json` 의 session_counts 에
`eval_pallet07` 27 · `eval_pallet09` 33 · `eval_night08` 12 · `eval_night09` 16 = **88 frame** 이
들어 있고, `challenge/data_paths.py` 는 정확히 그 네 세션을 `FINAL_TEST` 로 정의한다.
같은 파일이 역할 변경도 기록한다 — "2026-08-20: 이 4 세션 105장은 더 이상 final test 가 아니다.
4-모델 비교에서 열었고 **재봉인 불가**."

따라서 **V1~V5 arm 전부, teacher probe, fast6d 두 스크린이 그 88장을 포함한 population 에서
돌았고**, contract 자체가 `held_out_final: false` 라고 적는다.
`EVAL_CANONICAL_TOTAL = 140`(161 raw − 21 GT-QA 격리)이므로 319 는 정본 140/161 과
같은 셋이 아니라 더 큰 합집합이다. 위 표의 `held_out_status` 열은 이 사실 위에서 읽어야 한다.

### 2. day/night 라벨이 artifact 마다 다르다 [확인]

`EVALUATOR_CONTRACT.json` 은 ALL 168/106 · PLASTIC 144/50 · WOOD 24/56 을 준다.
그런데 `FAST_6D_SCREEN_V1B_REPORT.md` 는 319 중 **120장만** `paper_domain` 라벨을 갖고
(daytime 70 / nighttime 50) 나머지 199 는 `none` 이라고 적는다.
claim lock 의 헤드라인 "nighttime detection 0.840 → 0.960" 은 **N=50, plastic only** 위의 값이다.
