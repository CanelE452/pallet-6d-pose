## 추가 — 저앙각은 "얇게 투영된다" 와 같은 말이다. 그러나 해상도 한계는 아니다

리뷰 패킷 생성 후 야간 모호 프레임(`eval_night08__1779449470423201536`)을 눈으로 보다가
확인한 것이다 [확인]. 저앙각 프레임의 팔레트는 **얇은 띠**로 투영된다.

```
bbox 단축 4분위    N   단축px p50  대각px p50  앙각p50  NME실패  (최대오차/단축) p50
Q1 얇음           80      34.9      203.7    4.6도   51.2%      0.546
Q2                80      72.7      242.8   12.6도   30.0%      0.123
Q3                79     153.1      359.3   24.2도   16.5%      0.081
Q4 두꺼움          80     386.9      696.8   34.5도   17.5%      0.053
```

[확인] 앙각과 bbox 단축은 **거의 같은 변수**다 — Spearman 0.850, 실패 예측 AUROC 0.699 대
0.692 로 구분되지 않는다. 기하학적으로 당연하다(저앙각 = foreshortening = 단축 압축).
따라서 "저앙각" 과 "얇은 투영" 을 서로 다른 두 조건으로 다루면 안 된다.

가장 얇은 4분위에서 **최대 코너 오차가 물체 단축의 0.546 배**다. 단축 중앙값이 34.9 px 이니
오차가 ~19 px, 즉 물체의 짧은 쪽 절반만큼 틀린다. 이것만 보면
"640 px 입력에서 35 px 짜리 물체는 원래 못 푼다" 는 **해상도/관측성 한계**로 읽고 싶어진다.

**그 해석은 기각된다** [확인]. 같은 해상도·같은 추론 레시피에서 real fine-tune 이
`<8도` 구간의 코너 오차를 9.22 → 5.86 px 로 낮췄고(짝지은 세션 CI [+2.50, +4.69], 0 배제),
검출은 별개로 개선됐다. **해상도가 한계라면 데이터만 바꿔서 36% 가 줄 수 없다.**
저앙각 실패는 관측 불가가 아니라 **학습되지 않은 것**이다.

(이 방향은 memory `stage22-coord-loss-small-rear-signal-not-fix` 의
"레버는 데이터/appearance 지 해상도·loss 표현 아님" 과 독립적으로 같은 결론에 도달한다.)

## 이 분해가 배제하는 것 / 배제하지 못하는 것

배제하는 것 [확인]:
- **A (GT/annotation semantics 수정)** 이 2D 정확도의 주된 레버라는 것 — 외삽 점을 고쳐도
  중앙값이 1 px 움직이고, 가림 안에서는 방향이 반대다. (단 6D yaw 분기는 별개다.)
- **B (evaluation contract)** 가 논문 트랙 정확도의 주된 레버라는 것 — 계약 대칭 {0,180}이
  구제하는 프레임이 0장이고, 순열을 완전히 자유롭게 풀어도 p50 이 4% 만 내려간다.
  (단 배포/과제 트랙에서는 B 가 실재한다 — `DEPLOYMENT_GEOMETRY_AUDIT.md`.)
- **검출·ranking 이 병목이라는 것** — IoU50 매칭 97.5%, 후보 0인 프레임 0장.

배제하지 못하는 것:
- Layer D 의 **원인**. 이 문서는 "위치추정이 무너진다" 까지만 말하고 왜인지는 말하지 않는다.
  capacity / 표현 / source 분포 / real supervision 중 무엇인지는
  `CAPACITY_AND_REAL_SUPERVISION_AUDIT.md` 와 `SOURCE_REAL_GAP_AUDIT.md` 가 다룬다.
- Layer E (PnP 증폭)의 잔여 헤드룸. 기존 판정은 양쪽 REJECT 지만 이 분해로 재확인하지 않았다.
- 야간의 NME 열세가 **조명** 때문인지 야간 촬영의 **거리/앙각** 때문인지. 교란되어 있다.
