# 수동 GT와 41.49px 오차의 검증

상태: 2026-09-09 수치·원본 시각 검토·독립 감사·HTML 검증·전달 완료.
기존 점·선 결합 실험과 정본 GT는 보존한다.

## 질문과 실행 전 기준

사용자가 직접 찍은 정답에 오차가 있을 수 있으므로, 기존 baseline의 41.49px가
정확한 GT에서도 남는 모델 오차인지 확인한다. 이 값은 평균이 아니라 동일 점 번호의
관측된 개별 픽셀 오차를 모은 P90이다. 현재 319장 DEV와 저장된 예측을 그대로 읽으며,
다시 학습하거나 예측에 맞춰 GT를 고치지 않는다.

1. 공식 값과 분모를 원 좌표에서 독립 재계산하고 실제로 채점한 GT 필드를 확인한다.
2. 보임/가림, 직접 클릭/추정/출처 불명, 중심/꼭짓점, 세션과 과거 사람 리뷰별로 나눈다.
3. GT만 먼저 그린 원본을 검토한다. 전체 contact sheet는 선별용이며 상세 검토한
   프레임과 점만 실제 시각 확인 범위로 기록한다. 번호의 정의와 위치 오차를 구별한다.
4. 모든 GT 위치 오차가 2/5/10px 이하라고 가정했을 때, 같은 점 집합에서 P90이
   가능한 범위를 계산한다. 가정에 대한 민감도이며 실제 손 클릭 산포의 측정은 아니다.
5. 정답 불확실성을 나눠도 점·선 결합의 비교 결과가 달라지는지 같은 subset에서 본다.

기존 리뷰의 `일부 어긋남`, `모르겠음`을 정답 확정으로 승격하지 않는다. 과거 pose
가설 두 개가 모두 틀렸다는 판정 역시 그대로 2D 클릭 좌표가 틀렸다는 뜻은 아니다.
GT 수정 후보는 원본을 보존한 별도 기록으로만 남긴다. 완전히 검증한 수정 좌표가
없는 경우 `수정 정답 기준 41.49px`라는 결론을 내리지 않는다.

## GT에서 확인한 문제와 남는 모델 오차

319장 모두 상위 `gt_source=manual`이지만 점별 출처는 unknown 1,557,
manual_click 648, pnp_projected 509, centroid_auto 146, extrapolated 11개로
섞였다. `manual_kps`라는 필드의 존재만으로 직접 클릭했다고 판단할 수 없다.
173장에는 점별 출처가 unknown으로 남아 있다.

- `plastic_night_01:037376`의 GT7 `[173,319]`은 전체 팔레트의 아래 끝보다
  검은 측벽 위쪽에 보인다. 두 에이전트가 모델 출력 없이 원본과 확대 crop을
  확인한 재검토 후보다. 그림자/재질 때문에 대체 좌표나 정확한 오차 크기는
  확정하지 않았다. 같은 이미지 GT1 `[556,215]`은 실제 상단 끝 부근인데
  현재 번호의 baseline 오차는 277.643px다. GT의 일부 불확실성과 큰 예측
  오류가 같은 프레임에 공존한다.
- `wood_night_01:032043`의 GT5 `[650,225]`는 폭640 화면 밖인데
  visible=2/manual_click/in_frame=false로 기록됐다. 현재 평가가 `v>0`를
  쓰므로 이 점도 채점된다. 좌표의 옳고 그름과 별도로 “보임” 메타데이터를
  재검토해야 하는 구체적 사례다.
- `plastic_day_01:012143`의 8점과 `wood_night_01:032043`의 9점에서
  legacy `manual_kps`와 현재 채점 좌표가 다르다(최대32.773px). 이 차이는
  어느 쪽이 정답인지 알려주지 않으며, 평가기는 현재 annotations만 일관되게
  사용했다. 다른 필드를 섞어 읽으면 평가가 달라질 위험이 있다.
- 원래 사용자 사례에서는 보이는 0/1/2/4/7번 GT가 실제 외곽 부근이었다.
  가려진 5/6번·중심의 정확성은 확인할 수 없다. 숫자 순서를 바꿔서 예측과
  맞게 만드는 작업은 하지 않았다.

Root가 오차 경계/큰 실패 19장의 원본·GT 상세 그림과 GT7 확대 crop을 직접

## 해석과 한계

**41.49px는 현재 GT 기준의 계산으로는 맞지만, 모든 GT가 정확한 상태에서
측정한 순수 모델 오차라고 인증할 수 없다.** 그렇다고 손 클릭의 작은 위치
오차가 큰 실패를 전부 설명하지도 않는다. 가림/화면 밖을 분리해도 오차가
남고, 실제 경계 부근의 직접 클릭점에서 수백 픽셀 실패를 확인했다.

GT 위치가 모두 진짜 정답에서 최대5px 이내라는 가정 아래, 같은 번호·점·
검출 매칭을 고정하면 P90은36.487–46.487px 범위를 벗어날 수 없다.
10px 가정이면31.487–51.487px다. 역삼각부등식에 따른 보수적 경계이며,
실제 클릭 오차를 측정한 결과는 아니다. ID/visibility/매칭 수정이나 크게
틀린 가림점에는 이 가정을 적용할 수 없다.

선 결합은 가려진 점의 P90을 약간 낮추지만 visible/명시적 직접 클릭점의
P90을 악화시킨다. 작은 median 차이, 과거 ok subset의 개선과 함께 보더라도
일관된 추가 향상이 GT 오차 때문에 가려졌다는 근거는 없다. 자유롭게 GT로
점 대응을 고르는 진단의 baseline P90 23.192px도 공식 결과를 바꾸지 않는다.
이는 번호를 무시한 oracle이며 정답 오류나 실제 모델 개선의 증거가 아니다.

정확한 수정 GT 점수를 얻으려면, 보이는 점을 모델 출력 없이 독립 재클릭해
좌표의 반복 측정 산포를 확인하고 별도 검증 GT 버전을 만들어 같은 저장
예측을 재채점해야 한다. 이번 감사에서는 숨은 정답을 추측으로 채우지 않았다.
