# V42 목표점별 물리 제약 유효성

유효한 선을 구분하면 기존 점 보정을 추가로 개선할 수 있는지 검증한다. 새 신경망 아키텍처 학습이 아닌, 고정 특징의 분류·선택 진단이다.

- V41 실제 물리 법선 3후보, 직접 회귀(fallback), 잔차 회귀와 V39 점 어려움 선택기를 고정한다.
- 가시성 / 물리 경계 정렬 / 목표점 제약 정확도 3목표 × 기하 / 영상+기하 2입력 × 3시드 = 18 HGB 분류기, 각 60라운드. 감사 재학습 3개는 별도다.
- 기존 2 CAD, 12 fit / 4 calibration / 8 재사용 check 그룹. 총 600관측 중 436검출, check 200관측 중 130검출·1040점. 미검출 70관측은 점 오차에서 제외한다.
- 상류 모델과 offset은 과거 16그룹 학습 이력이 있다. 새 실사 평가, GT 수정, 렌더, 신경망 업데이트는 없다.
- 유효한 점·역할 슬롯만 학습한다. 그룹별 프레임 가중치를 슬롯으로 확장한 뒤 무효 슬롯을 제외하고 정규화하므로 남은 그룹 총가중치는 같지 않을 수 있다.
- calibration 4그룹에서 고정 .10~.95 격자 중 precision≥90%, 최소 10슬롯·2그룹 조건을 만족하는 최대 recall 기준을 고른다. 없으면 1.1로 기권한다. 독립적인 90% 보장은 아니다.
- 주판정은 constraint_visual_pre_all이다. 실제 입력에 GT는 없다. 비교 기준은 기존 직접 회귀 10.410px이며, 원래 점 대비 fallback 이득을 새 분류기의 이득으로 세지 않는다.

## 재현

저장소 루트에서 실행한다. Python 환경: `/home/minjae/anaconda3/envs/pallet-yolo26/bin/python`.

```bash
/home/minjae/anaconda3/envs/pallet-yolo26/bin/python scripts/research/pallet_constraint_validity_v42/run42.py --phase all
```

`all`은 완료 마커가 있는 단계를 건너뛴다. 개별 단계는 `train`, `eval`, `audit`, `probe`, `audit_probe`, `report`, `deliver`다. 개별 재실행은 결과를 덮어쓰므로 완료 후 수정 실험은 새 버전에 저장한다. 전달은 Chrome/X11 접근 권한이 필요하다. Discord는 별도 절차이며 기존 사용자 승인에 따라 완료 사실만 보낸다.

일차 설계/결과는 `PROTOCOL.json`/`SUMMARY.json`, 일차 결과 후 고정한 무학습 후보 진단은 `PROBE_PROTOCOL.json`/`PROBE.json`이다. `AUDIT.json`은 18분류기 재현, 93점 배열 재계산, 3개 비학습 영역 교란 재학습 및 GT 분리를 확인한다. `PROBE_AUDIT.json`은 후보별 GT 최소 오차와 기회 수를 독립 계산한다. 전달은 표 원본 수치·지역 링크·실제 Chrome 가시 창을 확인하고 파일 해시를 `COMPLETION.json`에 기록한다.

## 결과

주판정 10.410014→10.408929px, 차이 95% 구간 [-.008859,+.007855]px로 안정적 추가 개선 실패. 선택한 점의 제약 precision 96.3/91.6/98.4%와 조건 보존은 통과했다. 1px 초과 개선 가능한 GT 유효 후보가 있는 점은 78/72/67개인데 실제 통과 후보에서는 15/11/6개로 줄었다. 순위 손실도 남아 있지만 후보 누락이 더 큰 병목이다. 운영 모델은 교체하지 않는다.
